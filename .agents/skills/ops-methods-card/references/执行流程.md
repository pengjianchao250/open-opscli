# 方法卡分析执行流程

本文件用于 `ops-methods-card` 的完整分析任务。只有当用户要求按方法卡完成数据分析并输出 HTML 时读取。

## 1. 认证门禁

先执行：

```bash
opscli auth token status
```

认证无效时切换到 `ops-auth` 完成登录或刷新，认证通过后再继续。

## 2. 获取方法卡列表

优先用用户输入中的关键词检索：

```bash
opscli methods-card list --keyword "<用户输入关键词>" --page 1 --per-page 100 --pretty
```

如果用户输入较长或不适合作为关键词，先用更短的业务词检索，例如“广告优化”“异常诊断”“Listing”。

## 3. 选择方法卡

根据用户输入，与列表项中的以下字段做语义匹配：

- `card_name`
- `card_code`
- `scenarios`
- `platforms`
- `sites`
- `categories`

如列表项不足以判断，取候选卡详情后再比较 `detail.content.name` 和 `detail.content.description`。

选择规则：

1. 用户明确指定卡片名称或编码时，优先精确匹配。
2. 用户只描述问题时，优先匹配 `card_name` 和 `description`。
3. 多张卡片相近时，选择与用户输入业务目标最贴近的一张，并在最终回复中说明选择原因。
4. 无法判断时停止并向用户说明需要补充卡片名称或业务目标。

## 4. 获取方法卡详情

选定卡片后执行：

```bash
opscli methods-card detail <card_id> --pretty
```

详情中的 `detail.content` 是分析规范的核心来源。重点读取：

- `description`
- `scope`
- `inputIntent`
- `requiredEntities`
- `supportedScenarios`
- `analysisView`
- `knowledgeScopes`
- `analysisSteps`
- `outputContract`
- `qualityRules`

## 5. 读取 Excel 数据

默认数据文件：

```text
opscli/skills/templates/ops-methods-card/交叉表-1778233062511.xlsx
```

先用脚本输出结构化预览：

```bash
python opscli/skills/templates/ops-methods-card/scripts/xlsx_preview.py --input "opscli/skills/templates/ops-methods-card/交叉表-1778233062511.xlsx" --max-rows 50
```

如用户提供了其他 Excel 文件路径，使用用户文件替代默认文件。

## 6. 完成数据分析

分析必须同时参考：

- 用户输入的问题或目标
- 选定方法卡的 `detail.content`
- Excel 预览数据和数值统计
- `references/卡片.md`
- `references/卡片输出示例.html`

输出内容至少包含：

- 选用的方法卡名称和选择原因
- 数据来源和样本量
- 核心指标或字段摘要
- 关键发现
- 按方法卡 `analysisSteps` 展开的分析过程
- 按方法卡 `outputContract.content` 生成的报告正文
- 按方法卡 `qualityRules` 做的质量校验说明

不要编造 Excel 中不存在的字段或指标。字段不足以支撑某个结论时，要在报告中明确说明限制。

## 7. 输出 HTML 文件

参考 `references/卡片输出示例.html` 的结构生成完整 HTML 文件，保存到：

```text
output/methods-card/<方法卡ID或名称>-YYYYMMDD-HHMMSS.html
```

要求：

- HTML 必须是可直接打开的完整文件。
- 不依赖构建工具。
- 样式内联在 HTML 中。
- 如果使用 ECharts CDN，需要保留无网络时的降级文本。
- 页面内容必须来自本次用户输入、方法卡详情和 Excel 数据分析，不得保留示例里的虚构分析结论。

## 8. 回复用户

最终只需要说明：

- 选用了哪张方法卡
- HTML 文件保存路径
- 如果有无法完成的接口、认证或数据限制，给出具体原因
