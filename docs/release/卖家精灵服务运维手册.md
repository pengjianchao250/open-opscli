# 卖家精灵服务运维手册

> 内部文档，仅供 SellerSprite 服务部署和运维人员使用。本文不加入公开用户文档、CLI 帮助或 Skill 命令清单。

## 1. 文档边界

本文只说明服务巡检、任务队列处置、专属账号管理、状态文件和故障排查。

业务场景选择及参数不在本文维护，以以下 Skill 为准：

- [ops-seller-sprite Skill](../../opscli/skills/templates/ops-seller-sprite/SKILL.md)
- [卖家精灵场景参数手册](../../opscli/skills/templates/ops-seller-sprite/SCENARIO_PARAMS_ZH.md)

本文中的本地运维命令不会通过 MCP Tool 提供，但命令本身不构成权限控制。只有服务主机管理员可以执行。

## 2. 执行前提

所有 `queue` 和 `account-binding` 命令必须同时满足：

1. 在实际运行 Collector MCP 的服务主机执行。
2. 使用 Collector MCP 的服务账号执行。
3. 使用与服务进程相同的 `HOME` 和 `CONFIG_DIR`。
4. 使用与线上服务相同的 opscli 版本和 Python 环境。
5. 多实例部署时，先确认只有一个实例写入 SellerSprite 状态目录。

默认状态目录为：

```text
CONFIG_DIR/seller_sprite/
```

如果使用了自定义环境变量或持久卷，以下所有路径均以服务进程的实际配置为准。

### 2.1 防止操作错误目录

先执行：

```bash
opscli seller-sprite queue status
```

检查输出中的 `db_path` 是否指向线上 `task_queue.sqlite3`。如果队列意外为空，优先检查当前系统用户、`HOME`、虚拟环境和挂载卷，不要立刻判断线上没有任务。

队列仓储初始化时会自动创建缺失的 SQLite 文件。在错误账号或错误目录执行命令，可能得到一个新的空数据库。

## 3. 命令速查

### 3.1 本地运维命令

| 目的 | 命令 | 是否改写状态 |
|---|---|---|
| 查看队列摘要 | `opscli seller-sprite queue status` | 否 |
| 查看 Worker 健康摘要 | `opscli seller-sprite queue worker-health` | 否 |
| 列出任务 | `opscli seller-sprite queue list` | 否 |
| 人工终止任务 | `opscli seller-sprite queue fail` | 是，不可自动撤销 |
| 重排超时运行任务 | `opscli seller-sprite queue requeue-running` | 是 |
| 绑定或更新专属账号 | `opscli seller-sprite account-binding bind` | 是 |
| 查看专属账号绑定 | `opscli seller-sprite account-binding list` | 否 |
| 解除专属账号绑定 | `opscli seller-sprite account-binding unbind` | 是 |

### 3.2 远端状态检查命令

以下命令走正式远端 MCP 代理链路，需要当前 CLI 已完成 OPS 登录。它们用于辅助核对用户任务，不代替本地队列巡检：

| 目的 | 命令 |
|---|---|
| 查看用户额度 | `opscli seller-sprite quota-status` |
| 查看单个普通任务 | `opscli seller-sprite job-status <job-id>` |
| 批量查看普通任务 | `opscli seller-sprite jobs-status <job-id>...` |
| 查看普通任务导出信息 | `opscli seller-sprite export <job-id>` |
| 查看 Listing Analysis 状态 | `opscli seller-sprite listing-analysis-status <job-id>` |
| 获取 Listing Analysis 结果 | `opscli seller-sprite listing-analysis-result <job-id>` |

远端状态命令受当前用户任务归属约束。管理员排查全局积压时，应以本地 `queue` 命令为准。

## 4. 日常巡检

### 4.1 查看队列摘要

```bash
opscli seller-sprite queue status
```

重点字段：

| 字段 | 含义 | 关注点 |
|---|---|---|
| `db_path` | 当前命令读取的队列库 | 必须与服务状态目录一致 |
| `by_state` | 各状态任务数量 | `queued` 是否持续增长，`failed` 是否突增 |
| `oldest_queued_at` | 最早排队时间 | 长时间不变化通常表示消费异常 |
| `oldest_running_started_at` | 最早运行开始时间 | 结合任务超时和租约判断 |
| `stale_running_count` | 超过阈值的运行任务数 | 大于 0 时进入异常排查 |
| `stale_running_cutoff` | 本次 stale 判定时间线 | 确认阈值是否符合排查目标 |

自定义 stale 阈值：

```bash
opscli seller-sprite queue status --stale-running-seconds 1800
```

### 4.2 查看 Worker 健康摘要

```bash
opscli seller-sprite queue worker-health --stale-running-seconds 1800
```

当前命令没有持久化 Worker heartbeat：

- `worker_state` 固定为 `no_heartbeat`。
- `healthy=true` 只表示没有被当前阈值判定为 stale 的运行任务。
- `healthy=true` 不能证明 Worker 进程存在，也不能证明队列正在消费。

还必须检查：

1. Collector MCP 服务进程状态。
2. 调度器和账号工作槽日志。
3. `oldest_queued_at` 是否持续推进。
4. 受控测试任务是否从 `queued` 进入终态。

### 4.3 查看任务明细

```bash
opscli seller-sprite queue list --state queued --limit 100
opscli seller-sprite queue list --state running --limit 100
opscli seller-sprite queue list --state failed --limit 100
```

`--limit` 最大为 500。未指定 `--state` 时返回最近任务。

重点检查：

- `job_id`、`task_kind`、`status`；
- `created_at`、`started_at`、`finished_at`；
- `assigned_account`、`worker_key`；
- `heartbeat_at`、`lease_expires_at`；
- `failover_count`、`last_error_code`、`retry_reason`；
- `error` 和导出状态。

输出可能包含用户查询条件、账号摘要和内部路径。不要直接粘贴到用户聊天、公开工单或外部群聊。

## 5. 队列处置

所有写操作都应遵循：

1. 先用 `status` 和 `list` 保存受影响任务清单。
2. 确认服务进程、浏览器和第三方任务的真实状态。
3. 明确影响范围和恢复方式。
4. 执行最小范围命令。
5. 再次执行 `status`、`list` 和任务状态查询完成验证。
6. 记录操作人、时间、任务 ID、原因和结果。

### 5.1 终止指定 queued 任务

```bash
opscli seller-sprite queue fail \
  --state queued \
  --job-id <job-id> \
  --reason "维护窗口人工终止"
```

多个任务可重复传入 `--job-id`：

```bash
opscli seller-sprite queue fail \
  --state queued \
  --job-id <job-a> \
  --job-id <job-b> \
  --reason "异常任务批量终止"
```

也可以按创建时间筛选：

```bash
opscli seller-sprite queue fail \
  --state queued \
  --before "2026-07-24T10:00:00+08:00" \
  --reason "终止维护窗口前积压任务"
```

执行效果：

- 匹配任务改为 `failed`。
- 错误码写为 `SELLER_SPRITE_QUEUE_ABORTED`。
- 对应 MCP 调用记录同步改为 `failed`。
- 命令只返回变更数量，不提供自动撤销。

安全要求：

- 日常处置只对 `queued` 使用 `fail`。
- 禁止在未保存任务清单时使用 `--all`。
- 不建议用 `fail --state running` 处置运行任务：数据库状态变化不会可靠取消已经发生的浏览器或第三方副作用。

### 5.2 重排 stale running 任务

```bash
opscli seller-sprite queue requeue-running --older-than-minutes 30
```

该命令会把 `started_at` 早于阈值的所有 `running` 任务重新置为 `queued`，没有按 `job_id` 过滤能力。执行前必须：

1. 确认原 Collector 进程和浏览器执行已停止或已失去租约。
2. 确认没有第二个消费者仍在执行同一任务。
3. 检查第三方是否已产生不可重复副作用。
4. 保存所有匹配任务 ID。
5. 优先让调度器通过租约恢复机制自动处理过期任务。

Listing Analysis 可能已经提交远端任务。应优先续查现有任务，不要盲目重排或重新提交。

重排后检查：

```bash
opscli seller-sprite queue status
opscli seller-sprite queue list --state queued --limit 100
```

如果原执行进程仍存活，先停止异常实例，再恢复队列消费，避免重复执行。

## 6. 专属账号运维

### 6.1 查看绑定

```bash
opscli seller-sprite account-binding list
```

输出只包含用户邮箱、账号 ID、账号名称、脱敏用户名、稳定账号键和绑定时间，不读取或输出密码。

### 6.2 绑定或更新账号

```bash
opscli seller-sprite account-binding bind \
  --user-email user@aukeys.com \
  --account-name account-a \
  --username seller@example.com
```

命令随后通过隐藏提示读取密码。禁止把密码写入命令参数、脚本、终端录屏、日志或工单。

注意：

- 每个 OPS 用户只能绑定一个专属账号。
- 同一个 `account-name` 可以被多个 OPS 用户复用。
- 使用已有 `account-name` 重新绑定会更新该命名账号的用户名和密码，所有复用该账号的用户都会受到影响。
- 更新共享账号前，必须先用 `account-binding list` 确认复用范围。

### 6.3 解除绑定

```bash
opscli seller-sprite account-binding unbind \
  --user-email user@aukeys.com
```

解绑效果：

- 删除该用户绑定。
- 该用户尚未领取的专属 `queued` 任务会失败。
- 已经 `running` 的任务继续使用领取时加载到内存的账号完成。
- 命名账号本身不会删除，其他复用用户不受影响。

解绑后核对输出中的 `deleted` 和 `failed_queued_tasks`，再检查相关任务状态。

账号绑定的完整语义参见[卖家精灵专属账号绑定指南](../guide/卖家精灵专属账号绑定指南.md)。

## 7. 状态目录与备份

默认状态文件：

| 路径 | 用途 | 备份要求 |
|---|---|---|
| `seller_sprite/task_queue.sqlite3` | 队列、任务租约和 MCP 调用记录 | 必须备份 |
| `seller_sprite/account_bindings.sqlite3` | 专属账号和用户绑定密文 | 必须备份 |
| `seller_sprite/.account_bindings.key` | 专属账号 AES-256-GCM 密钥 | 必须与绑定库配套备份 |
| `seller_sprite/browser_profiles/` | 浏览器登录 Profile | 建议备份，按敏感凭证管理 |
| `seller_sprite/api_runs/` | 状态文件和任务结果 | 按保留策略备份 |

备份和恢复要求：

1. 优先在停止 Collector 写入后做一致性快照。
2. `account_bindings.sqlite3` 与 `.account_bindings.key` 必须成对备份和恢复。
3. 保留原服务账号的文件所有者和访问权限。
4. 不要把数据库、密钥、浏览器 Profile 或任务结果上传到公开制品库。
5. 恢复后先检查 SQLite 完整性，再启动单一 Collector 实例。
6. 禁止绕过 CLI 直接修改 SQLite 任务状态或账号密文。

## 8. 常见故障排查

### 8.1 队列显示为空，但用户有待处理任务

按顺序检查：

1. `queue status` 返回的 `db_path`。
2. 当前执行用户和 Collector 服务用户是否一致。
3. `HOME`、`CONFIG_DIR` 和持久卷是否一致。
4. 是否误连了另一个部署实例。

不要向新建的空库执行写操作。

### 8.2 queued 持续积压

检查：

1. Collector MCP 进程是否运行。
2. 是否存在可用公共账号或专属账号。
3. `running` 是否长期占用账号工作槽。
4. 日志中是否出现浏览器启动、认证、验证码、网络或配置错误。
5. `oldest_queued_at` 是否推进。

恢复服务后观察任务自行消费，不要重复提交用户任务。

### 8.3 running 长时间不结束

1. 查看 `heartbeat_at` 和 `lease_expires_at`。
2. 检查原进程及浏览器是否仍在执行。
3. 对照 `OPSCLI_SELLER_SPRITE_TASK_TIMEOUT_SECONDS`。
4. 确认任务是否已在第三方产生结果。
5. 优先等待租约自动恢复；人工重排必须遵循第 5.2 节。

### 8.4 专属账号认证失败

1. 用 `account-binding list` 确认用户当前绑定和账号复用范围。
2. 使用原 `account-name` 重新执行 `bind` 更新凭证。
3. 确认修复后再重新提交失败任务。

专属账号异常不会回退公共账号池。不要通过反复提交任务尝试切换账号。

### 8.5 `SELLER_SPRITE_ACCOUNT_UNAVAILABLE`

公共账号池没有可用账号，或账号加载失败。检查账号配置、服务日志和账号冷却状态，不要在输出中打印完整账号配置。

### 8.6 `SELLER_SPRITE_DEDICATED_ACCOUNT_UNAVAILABLE`

专属账号绑定被删除、变更、无法解密或无法登录。核对绑定库与密钥是否配套，再检查当前用户绑定。

### 8.7 `SELLER_SPRITE_TASK_TIMEOUT`

任务超过配置的执行超时。检查第三方响应、浏览器状态、网络和任务复杂度。调整超时前先确认不是账号、验证码或页面阻塞问题。

### 8.8 `SELLER_SPRITE_QUEUE_ABORTED`

任务由管理员通过 `queue fail` 人工终止。根据错误消息和运维记录确认操作原因，不要把它误判为第三方采集失败。

### 8.9 Collector 不可用

正式 CLI 或通用 MCP 返回 Collector 不可用时：

1. 检查 Collector MCP 进程和监听状态。
2. 检查通用 MCP 到 Collector 的内网连通性。
3. 检查部署配置，但不要输出内部 URL、API Key、JWT 或 Session。
4. 恢复 Collector 后查询原 `job_id`，不要重新提交 pending 任务。

Collector 的启动边界参见 [Collector MCP运维说明](Collector%20MCP运维说明.md)。

## 9. 安全红线

1. 禁止记录或输出卖家精灵密码、Cookie、API Key、JWT、Session 和 Authorization Header。
2. 禁止把真实凭证放入命令参数、Shell 历史、脚本、代码仓库或聊天记录。
3. 禁止向用户发送完整队列 JSON、用户邮箱、账号键、数据库路径或浏览器 Profile。
4. 禁止在未确认影响范围时使用 `queue fail --all`。
5. 禁止在原执行仍存活时重排 `running` 任务。
6. 禁止重复提交仍为 `queued` 或 `running` 的任务。
7. 禁止直接修改 SQLite 状态、密文或 schema。
8. 禁止多实例同时写同一 SellerSprite 状态目录。
9. 任何生产写操作都必须保留操作记录和验证结果。

## 10. 标准处置闭环

```text
确认服务主机和状态目录
→ queue status
→ queue list 保存任务清单
→ 检查服务、日志、浏览器和账号状态
→ 选择最小影响操作
→ 再次 queue status / queue list
→ 查询受影响 job_id 的终态
→ 记录操作原因、范围和结果
```

业务场景、参数映射和用户查询流程统一回到 `ops-seller-sprite` Skill，不在本运维手册重复维护。
