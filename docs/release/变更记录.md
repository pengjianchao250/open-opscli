# 变更记录

## 2026-10-09 OPS App 迁移运行兼容门禁轻量化

**变更原因**：首次按三项迁移合同执行真实项目时，完整双运行与业务一致性验证诱发重复依赖安装、环境重建和长时间端到端检查，迁移总耗时明显高于复制与适配本身。

**改动点**：保留 `dual_runtime` 清单字段以兼容既有门禁，但将其改为轻量运行兼容模式；默认只执行原本地入口与 AppHub 薄适配入口两个冒烟检查，完整业务一致性仅在业务/API、公共路径、SPA/WebSocket、存储、后台任务、进程模型或执行链路变化时通过 `--require-parity` 启用；相同命令在单次验证中只运行一次；默认超时调整为 180 秒；文档明确复用 `.venv`、`node_modules`、pnpm store 和构建缓存，锁文件未变化时不得默认重装依赖。

**验证结果**：新增默认跳过一致性、风险强制一致性、缺少一致性命令阻断和相同命令结果复用测试；迁移验证器、迁移 push 门禁、迁移服务与建站 Skill 定向回归通过。

**影响范围**：仅影响 `origin_type=migration_copy` 的迁移验证执行策略；三项合同、验证清单、源码指纹和 push 门禁仍保留。普通模板克隆、`app create`、`app init` 与普通项目 `app push` 不变。

**回滚方式**：恢复 `validate_migration_contract.py` 的必填 `--parity-check-json` 和三命令固定执行逻辑，并撤销迁移验证合同、迁移规范与 Skill 中的风险触发和依赖复用说明。

## 2026-10-09 OPS App 迁移双运行与发布门禁闭环

**变更原因**：源码迁移改造无法对所有旧项目使用同一实现，但迁移后的本地运行、AppHub 薄适配和线上发布条件可以统一验收；同时必须保证迁移门禁不侵入普通新建流程。

**改动点**：新增三项迁移验证合同与验证脚本，统一输出迁移完整性、双运行、发布门禁和交付源码指纹；迁移项目 push 新增发布资产、验证清单和指纹新鲜度检查；更新建站 Skill 的失败持续修复与 `push_on_success` 编排；新增需求文档及回归测试。所有新增门禁仅在 `.opscli/project.json.origin_type=migration_copy` 时启用。

**验证结果**：`tests/skills/test_ops_app_migration_contract_validator.py` 与 `tests/app/test_manager.py` 共 66 项通过；`tests/app/test_migration.py` 与前端合同校验器共 29 项通过；建站 Skill 安装、迁移和部署相关 4 项定向回归通过；新增 Python 文件编译检查通过。完整 Skill 测试文件仍有 1 项既有中文模板编码断言失败，与本次迁移改动无关。

**影响范围**：仅影响 `origin_type=migration_copy` 的迁移验证与推送前门禁、`ops-app-build-spec` 迁移编排和相关文档；普通模板克隆、`app create`、`app init` 和普通项目 `app push` 逻辑保持不变。

**回滚方式**：移除迁移验证脚本与参考文档，撤销 `migration_contract.py` 的发布资产/指纹函数和 `AppManager._validate_migration_push` 的验证清单检查，并恢复 Skill 迁移步骤；普通新建流程无需回滚。

## 2026-08-13 Sorftime 深度报告批处理

**变更原因**：500+ 商品需要断点续跑，单次会话内逐项调用会被远端慢请求阻塞。

**改动点**：新增 `scripts/sorftime/run_sorftime_deep_queue.py`，串行执行现有深度任务清单，保存 MCP 原始响应；超时任务延期，其他异常单独记录，每个商品结束后合并优化报告。执行器会展开 MCP SDK 的嵌套异常，并在认证失效时停止队列，避免产生批量无效请求。

**验证结果**：执行 Python 编译检查；示例 JSON 的凭据已失效，执行器改为优先读取 Codex 当前生效配置，再使用单商品队列进行真实 MCP 取数验证。

**影响范围**：仅影响 `test-data/sorftime` 测试数据批处理，不修改 opscli 业务模块。

**回滚方式**：停止批处理进程并删除新增脚本；已保存的原始数据和报告可继续保留。

## 2026-08-14 Sorftime 超时无数据终态

**变更原因**：5 个竞品关键词任务多轮等待约 5 分钟仍无响应，不应无限重试，也不应伪装成接口正常返回空数据。

**改动点**：新增 `no_data_after_timeout` 终态；任务清单将其视为已处理，完整性审计单独统计“完整但含超时无数据”，报告明确展示接口状态和超时证据。

**验证结果**：将 5 个重复超时任务转为终态，重新生成对应报告并执行全量完整性审计。

**影响范围**：仅影响 Sorftime 测试数据任务状态和报告标注；正常成功数据不变。

**回滚方式**：从 `no_data_tasks.json` 删除对应任务并重新生成任务清单，即可恢复为 pending。

## 2026-08-14 Sorftime 脚本目录整理

**变更原因**：Sorftime 本地调试脚本数量增加，散落在 `scripts/` 根目录不便于维护和提交审查。

**改动点**：将 Listing 处理、队列执行、MCP 存储、报告生成和审计脚本统一移动到 `scripts/sorftime/`，同步更新脚本间调用路径；临时 MCP 响应加入 Git 忽略。

**验证结果**：执行全目录 Python 编译检查、完整性审计和单商品报告合并验证。

**影响范围**：Sorftime 脚本入口路径由 `scripts/*.py` 调整为 `scripts/sorftime/*.py`；本地 `test-data/` 数据不变。

**回滚方式**：将脚本移回 `scripts/` 根目录并恢复三处内部调用路径。
