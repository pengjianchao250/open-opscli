## 前置准备

### 1. 安装构建和发布工具

```bash
pip install build twine
```

| 工具 | 用途 |
|------|------|
| `build` | 构建 `.whl` 和 `.tar.gz` 包 |
| `twine` | 安全上传包到 PyPI 服务器 |

### 2. 添加 .gitignore

确保构建产物不被提交到 Git，在项目根目录创建 `.gitignore`：

```
dist/
*.egg-info/
build/
__pycache__/
*.pyc
.pytest_cache/
.venv/
```

### 3. 注册 PyPI 账号

| 平台 | 地址 | 说明 |
|------|------|------|
| PyPI | https://pypi.org/account/register/ | 正式发布 |
| TestPyPI | https://test.pypi.org/account/register/ | 测试验证 |

注册后在 `~/.pypirc` 配置凭证：

```ini
[pypi]
username = __token__
password = pypi-xxxxxxxxxxxx  # API Token，从 PyPI 账号设置中生成

[testpypi]
username = __token__
password = pypi-xxxxxxxxxxxx
```

## 打包构建

### 完整构建命令

```bash
cd /path/to/opscli

# 清理旧产物
rm -rf dist/ build/ *.egg-info/

# 构建
python -m build
```

### 构建产物

构建完成后 `dist/` 目录下会生成两个文件：

```
dist/
├── opscli-0.1.0-py3-none-any.whl   # 二进制包（安装快）
└── opscli-0.1.0.tar.gz              # 源码包（备选）
```

### 验证构建产物

```bash
# 检查包元数据
twine check dist/*

# 本地测试安装
pip install dist/opscli-0.1.0-py3-none-any.whl

# 验证命令可用
opscli --version
opscli --help

# 卸载测试包
pip uninstall opscli
```

## 发布渠道

### 零、TestPyPI 测试环境（正式发布前必做）

> 每次发布正式版前，先在 TestPyPI 验证包能否正常构建、上传和安装，确认无误后再发布到正式 PyPI。

#### 第 1 步：注册 TestPyPI 账号 + 生成 API Token

1. 访问 https://test.pypi.org/account/register/ 注册账号
2. 登录后进入 **Account settings → API tokens → Add API token**
3. Token name 随意填（如 `opscli`），Scope 选 `Entire account`
4. 复制生成的 Token（`pypi-` 开头，只显示一次）

#### 第 2 步：配置凭证（只需一次）

创建 `~/.pypirc` 文件，避免每次手动输入 Token：

```bash
cat > ~/.pypirc << 'EOF'
[testpypi]
username = __token__
password = pypi-你的TestPyPI-Token值

[pypi]
username = __token__
password = pypi-你的正式PyPI-Token值
EOF

chmod 600 ~/.pypirc
```

> **注意**：`__token__` 是固定的用户名，不是占位符。密码填你生成的 API Token。

#### 第 3 步：构建包

```bash
cd /path/to/opscli

# 清理旧产物
rm -rf dist/ build/ *.egg-info/

# 构建
python -m build
```

构建产物：

```
dist/
├── opscli-0.1.0-py3-none-any.whl
└── opscli-0.1.0.tar.gz
```

验证包是否合规：

```bash
twine check dist/*
# 输出 PASSED 即可
```

#### 第 4 步：上传到 TestPyPI

```bash
twine upload --repository testpypi dist/*
```

成功后输出：

```
Uploading opscli-0.1.0-py3-none-any.whl 100%
Uploading opscli-0.1.0.tar.gz 100%

View at:
https://test.pypi.org/project/opscli/0.1.0/
```

#### 第 5 步：从 TestPyPI 测试安装

> **重要**：TestPyPI 上可能缺少依赖包，所以需要 `--extra-index-url` 指向正式 PyPI 拉依赖。

```bash
# 安装测试（从 TestPyPI 拉目标包，从正式 PyPI 拉依赖）
pip install \
    --index-url https://test.pypi.org/simple/ \
    --extra-index-url https://pypi.org/simple/ \
    opscli

# 验证 CLI 命令可用
opscli --version
# 输出: opscli v0.1.0

opscli --help
# 应显示所有命令: login, logout, status, token, system, doctor, version

# 验证 SDK 可导入
python -c "from opscli import AuthClient; print('SDK OK')"

# 验证系统列表
opscli system list
# 应显示 ops 和 polaris 两个内置系统
```

#### 第 6 步：清理测试包，切回开发模式

```bash
# 卸载 TestPyPI 安装的包
pip uninstall opscli -y

# 重新安装为开发模式（代码改动即时生效）
cd /path/to/opscli
pip install -e .
```

#### 已验证的实际操作记录（2026-04-18）

```bash
# 构建
$ python -m build
Successfully built opscli-0.1.0.tar.gz and opscli-0.1.0-py3-none-any.whl

# 校验
$ twine check dist/*
PASSED with warnings  # warnings 关于 long_description，不影响功能

# 上传
$ twine upload --repository testpypi dist/*

Uploading opscli-0.1.0.tar.gz 100%
View at: https://test.pypi.org/project/opscli/0.1.0/

# 安装验证
$ pip install --index-url https://test.pypi.org/simple/ \
    --extra-index-url https://pypi.org/simple/ opscli

```

```

                                      testpypi        test.pypi.org
```

### 方式一：发布到 PyPI（公网）

发布后全球用户可 `pip install opscli` 直接安装。

```bash
# 确认 TestPyPI 验证通过后，发布到正式 PyPI
twine upload dist/*
```

发布后用户安装：

```bash
pip install opscli

# 指定版本
pip install opscli==0.1.0
```

### 方式二：发布到私有 PyPI

适用于公司内部有私有 PyPI 服务器的场景（如 devpi、Nexus、GitLab Package Registry）。

```bash
# 上传到私有服务器
twine upload --repository-url http://your-pypi-server:8080/simple/ dist/*

# 如果需要认证
twine upload \
    --repository-url http://your-pypi-server:8080/simple/ \
    -u <username> -p <password> \
    dist/*
```

用户安装时指定私有源：

```bash
# 命令行指定
pip install opscli --index-url http://your-pypi-server:8080/simple/

# 或配置 pip 全局源
# ~/.pip/pip.conf
[global]
index-url = http://your-pypi-server:8080/simple/
trusted-host = your-pypi-server
```

#### GitHub Packages 示例

```bash
# 构建
python -m build

# 上传到 GitHub Packages
twine upload \
    --repository-url https://upload.pypi.org/legacy/ \
    --username __token__ \
    --password ghp_xxxxxxxxxxxx \
    dist/*
```

### 方式三：Git 仓库直接安装（推荐内部项目）

不需要构建和发布，推代码到 Git 即可。适合内部工具，最省事。

```bash
# 推到 Git 仓库
git remote add origin git@github.com:your-org/opscli.git
git push -u origin main

# 打 tag 标记版本
git tag v0.1.0
git push origin v0.1.0
```

用户安装方式：

```bash
# 安装最新版（main 分支）
pip install git+ssh://git@github.com/your-org/opscli.git

# 安装指定版本（tag）
pip install git+ssh://git@github.com/your-org/opscli.git@v0.1.0

# 安装指定分支
pip install git+ssh://git@github.com/your-org/opscli.git@develop

# HTTPS 方式（无需 SSH 配置）
pip install git+https://github.com/your-org/opscli.git@v0.1.0
```

在其他项目的 `pyproject.toml` 中声明依赖：

```toml
[project]
dependencies = [
    "opscli @ git+ssh://git@github.com/your-org/opscli.git@v0.1.0",
]
```

## 版本更新流程

### PyPI / 私有 PyPI 发布

```bash
# 1. 修改版本号
# 编辑 pyproject.toml，将 version = "0.1.0" 改为 version = "0.2.0"

# 2. 提交代码
git add .
git commit -m "release: v0.2.0"
git push

# 3. 打 tag
git tag v0.2.0
git push origin v0.2.0

# 4. 清理 + 构建
rm -rf dist/
python -m build

# 5. 发布
twine upload dist/*
```

### Git 仓库发布（更简单）

```bash
# 1. 修改版本号
# 编辑 pyproject.toml: version = "0.2.0"

# 2. 提交 + 打 tag
git add .
git commit -m "release: v0.2.0"
git tag v0.2.0
git push && git push origin v0.2.0

# 用户更新安装
pip install --force-reinstall git+ssh://git@github.com/your-org/opscli.git@v0.2.0
```

### 重要提醒

> **PyPI 不允许覆盖同版本号**，每次发布必须修改 `version`，否则上传会被拒绝。

## 版本号规范

遵循 [语义化版本](https://semver.org/lang/zh-CN/)：`MAJOR.MINOR.PATCH`

| 版本变更 | 示例 | 说明 |
|----------|------|------|
| PATCH | 0.1.0 → 0.1.1 | Bug 修复，向后兼容 |
| MINOR | 0.1.0 → 0.2.0 | 新功能，向后兼容 |
| MAJOR | 0.2.0 → 1.0.0 | 破坏性变更，不兼容 |

在 `pyproject.toml` 中只改 `version` 字段：

```toml
[project]
name = "opscli"
version = "0.2.0"   # ← 改这里
```

## pyproject.toml 配置说明

当前配置：

```toml
[project]
name = "opscli"          # pip install 用的包名
version = "0.1.0"                 # 版本号，每次发布必须改
description = "Aukeys 多系统 CLI 认证工具（一期：ops + bi）"
requires-python = ">=3.10"        # 最低 Python 版本
dependencies = [                  # 运行时依赖
    "typer>=0.12",
    "httpx>=0.27",
    "cryptography>=42",
    "rich>=13",
    "keyring>=25",
]

[project.optional-dependencies]
dev = [                           # 开发依赖：pip install -e ".[dev]"
    "pytest>=8",
    "respx>=0.21",
]

[project.scripts]
opscli = "opscli.cli:app"  # CLI 入口命令

[build-system]
requires = ["hatchling"]          # 构建后端
build-backend = "hatchling.build"
```

### 可选：补充元数据

发布到 PyPI 时建议补充以下字段：

```toml
[project]
name = "opscli"
version = "0.1.0"
description = "Aukeys 多系统 CLI 认证工具"
readme = "README.md"              # 在 PyPI 页面显示 README
license = "MIT"                   # 或 "Apache-2.0" 等
requires-python = ">=3.10"
authors = [
    { name = "Your Name", email = "you@example.com" },
]
classifiers = [                   # PyPI 分类标签，方便搜索
    "Development Status :: 4 - Beta",
    "Intended Audience :: Developers",
    "Programming Language :: Python :: 3",
    "Programming Language :: Python :: 3.10",
    "Programming Language :: Python :: 3.11",
    "Programming Language :: Python :: 3.12",
]

[project.urls]
Homepage = "https://github.com/your-org/opscli"
Repository = "https://github.com/your-org/opscli"
```

## 常见问题

### Q: 上传时报错 `File already exists`

PyPI 不允许覆盖已发布的版本。解决：

```bash
# 修改 pyproject.toml 中的 version
# 重新构建并上传
rm -rf dist/ && python -m build && twine upload dist/*
```

### Q: 上传时报错 `Invalid API Token`

1. 检查 `~/.pypirc` 中 token 是否正确
2. 确认 token 未过期
3. 重新生成 token：PyPI → Account settings → API tokens

### Q: 安装后命令找不到 `opscli`

检查 `pyproject.toml` 中的 `[project.scripts]` 配置是否正确：

```toml
[project.scripts]
opscli = "opscli.cli:app"
```

### Q: Git 安装报错权限拒绝

```bash
# 确认 SSH key 已配置
ssh -T git@github.com

# 或改用 HTTPS 方式
pip install git+https://github.com/your-org/opscli.git
```

### Q: 如何撤销已发布的版本

PyPI 不支持删除指定版本（防止破坏依赖链），但可以「撤销发布」：

```bash
# 通过 PyPI 网站手动操作
# https://pypi.org/manage/project/opscli/releases/
```

### Q: 如何在 CI/CD 中自动发布

```yaml
# GitHub Actions 示例
name: Publish
on:
  push:
    tags: ["v*"]

jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install build twine
      - run: python -m build
      - run: twine upload dist/*
        env:
          TWINE_USERNAME: __token__
          TWINE_PASSWORD: ${{ secrets.PYPI_TOKEN }}
```
