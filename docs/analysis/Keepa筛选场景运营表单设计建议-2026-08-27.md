# Keepa 筛选场景运营表单设计建议（2026-08-27）

> 目标：将 Product Finder、Seller Finder、Deals 的 `selection` 从“让运营人员填写 JSON”改为按业务语义填写表单；生成请求时再组装为 Keepa selection JSON。复杂字段仍保留高级 JSON 兜底。

## 1. 调研结论

仓库当前的三个场景都把 `selection` 作为开放 JSON 透传：

- `opscli/keepa/api/scenarios.py`：`_product_finder_params`、`_seller_finder_params`、`_deals_params`。
- Product Finder 和 Seller Finder 的字段很多，而且大量字段使用统一的 `_gte` / `_lte` 后缀；这类字段不应在页面上直接暴露为几十个 JSON key。
- Deals 的 `priceTypes` 虽然是数组，官方要求**只能传一个值**；当前代码已做这个约束。
- Keepa 官方明确规定：数组过滤器默认是 OR，同一请求的不同过滤器之间是 AND；字符串可用前缀 `-` 或 `✜` 表示排除；范围字段使用 `gte`（大于等于）和 `lte`（小于等于）。

因此推荐：**常用字段使用可读控件，范围使用“最小值/最大值”，数组使用标签输入，低频字段放到“高级筛选”，原始 JSON 只作为兜底调试入口。**

## 2. 公共规则（三个场景共用）

| Keepa 规则 | 运营端控件 | 生成的 JSON |
| --- | --- | --- |
| `*_gte` / `*_lte` | 数值范围（最小、最大） | `field_gte`、`field_lte` |
| String[] | 多值标签输入，逗号分隔 | `field: ["a", "b"]` |
| 排除字符串 | 标签前加“排除”开关 | `field: ["-keyword"]` |
| Boolean | 开关，默认“不限制” | 仅在用户打开时发送 `true`；不要发送无意义的 `false` |
| Category/Seller ID 数组 | ID 多值输入，可从搜索结果选择 | Long[] / String[] |
| 时间字段（Keepa Time minutes） | 日期时间选择器；提交前转换 | 整数 Keepa Time，不让用户填写分钟值 |
| 分页 | “返回数量”下拉（50/100/500/1000） | `perPage`；默认 50 |
| 排序 | 排序字段 + 升降序 | 官方要求二维数组，如 `[["current_SALES", "asc"]]` |

公共交互：页面显示当前已启用的条件摘要，例如“类目：3 个；Amazon 价格：$10–$50；评分 ≥ 4.0”，并提供“一键清空”。提交前显示预计结果数量/额度提示（不能把 token 估算当作账单保证）。

## 3. Product Finder（`/query`）

### 3.1 推荐表单分组

| 分组 | 运营字段 | Keepa 字段 | 控件与说明 |
| --- | --- | --- | --- |
| 基础定位 | 根类目 | `rootCategory` | 类目搜索/选择器；支持最多 50 个 ID |
| 基础定位 | 包含子类目 / 排除子类目 | `categories_include` / `categories_exclude` | 两个 ID 多选；语义是直接挂在这些类目的商品 |
| 基础定位 | 标题关键词 | `title` | 文本输入；空格分词，最多 50 个词；可用“排除关键词” |
| 基础定位 | 品牌、制造商 | `brand` / `manufacturer` | 多值标签；同字段多值默认 OR |
| 价格与销量 | 当前价格 | `current_<PRICE_TYPE>_gte/lte` | 价格类型下拉（Amazon、New、Buy Box 等）+ 最小/最大；单位按站点货币显示，提交转最小货币单位整数 |
| 价格与销量 | 近 30/90 天价格变化 | `delta30_*`、`deltaPercent30_*` | “变化金额/变化百分比”范围；正负号要在帮助文案解释（降价为正，涨价为负，按官方定义） |
| 价格与销量 | 月销量 | `monthlySold_gte/lte` | 最小/最大销量；提示“Amazon Bought Past Month，非估算值，很多 ASIN 可能无值” |
| 竞争与口碑 | Sales Rank | `current_SALES_gte/lte` 或 `salesRankReference` | 排名范围；默认按当前 Sales Rank 升序 |
| 竞争与口碑 | 评分、评论数 | `current_RATING_gte/lte`、`variationRatingCount_gte/lte` | 评分控件显示 0–5 星，提交时评分乘 10；评论数为整数 |
| 供货与 Buy Box | Amazon 有货、FBA、Buy Box | `availabilityAmazon`、`buyBoxIsAmazon`、`buyBoxIsFBA` | 枚举下拉/开关；不要让用户填写数字枚举 |
| 商品属性 | 颜色、尺寸、材质、款式等 | `color`、`size`、`material`、`style`、`itemForm` 等 | 收进“商品属性”折叠面板；统一使用标签输入 |
| 商品状态 | 变体、A+、视频、成人品 | `singleVariation`、`hasParentASIN`、`hasAPlus`、`hasMainVideo`、`isAdultProduct` 等 | 开关，默认不限制 |
| 结果控制 | 返回数量、页码、排序 | `perPage`、`page`、`sort` | 默认 `perPage=50`；`page=0` 时可请求更大数量；页码组合总上限 10,000 |

### 3.2 不应直接暴露的字段

`packageHeight_*`、`itemWeight_*`、`buyBoxStats*`、`srAvg<C><MM>`、`lastPriceChange_*`、`backInStock_*` 等低频/技术字段应放在“高级筛选”。金额、Keepa Time、价格类型后缀和 `-1` 缺失值都需要统一转换，不能让运营人员自己拼接字段名。

Product Finder 官方要求至少一个筛选条件；当前本地 `_product_finder_params` 对空 selection 没有阻断，前端必须禁止“无条件查询”，服务端也应补同等校验。

### 3.3 示例：运营填写后生成

```json
{
  "rootCategory": ["165793011"],
  "brand": ["anker"],
  "current_AMAZON_gte": 1999,
  "current_AMAZON_lte": 5999,
  "current_SALES_lte": 50000,
  "hasReviews": true,
  "perPage": 100,
  "page": 0,
  "sort": [["current_SALES", "asc"]]
}
```

## 4. Seller Finder（`/sellerquery`）

### 4.1 推荐表单分组

| 分组 | 运营字段 | Keepa 字段 | 控件与说明 |
| --- | --- | --- | --- |
| 快速查找 | 卖家名称/公司/地址关键词 | `search`、`sellerName`、`businessName`、`address` | 单文本输入；`search` 是跨卖家字段的通用搜索 |
| 活跃状态 | 仅活跃卖家 | `activeOnly` | 默认打开；官方当前等价于最近 31 天见过报价 |
| 评分质量 | 当前好评率 | `currentRating_gte/lte` | 百分比 0–100；UI 显示 0–100% |
| 评分质量 | 评分数量 | `currentRatingCount_gte/lte` | 最小/最大数量 |
| 评分趋势 | 30/90/365 天新增评分、评分变化 | `ratingCountDelta30_*`、`ratingDelta90_*` 等 | 选择时间窗口 + 范围；说明“评分变化单位为百分点” |
| 履约能力 | 使用 FBA | `hasFBA` | 开关 |
| 店铺规模 | Verified Listings 数量 | `totalStorefrontAsins_gte/lte` | 最小/最大商品数；提示无完整 verified count 时可能是估算下限 |
| Buy Box | 新品/二手 Buy Box 占有率、平均竞争卖家数 | `buyBoxNewOwnershipRate_*`、`buyBoxUsedOwnershipRate_*`、`avgBuyBoxCompetitors_*` | 百分比/数量范围 |
| 主营类目与品牌 | 根类目、主品牌、竞品卖家 | `rootCategories_include/exclude`、`primaryBrand`、`competitorSellerIds` | 类目/卖家 ID 选择器；竞争对手场景可使用预置卖家 ID |
| 企业资料 | 国家、企业资料是否存在 | `addressCountry`、`customerServicesAddressCountry`、`hasBusinessDetails` | ISO 3166-1 alpha-2 国家选择器；“有企业资料”开关 |
| 结果控制 | 返回数量、排序 | `perPage`、`page`、`sort` | 默认 50；最多 10,000；排序最多 3 个字段 |

### 4.2 运营端需要特别提示

- 同一数组内的品牌/类目/卖家 ID 默认 OR；需要“至少命中 N 个”时才显示高级 `minMatch`。
- `isNotFound` 默认不显示。官方说明已不存在的卖家默认被排除，只有排查历史卖家时才打开。
- `domainId` 可是多站点数组并覆盖请求层 `domain`；如果产品页面只允许选择一个站点，就不要把这个字段暴露在普通表单。
- 官方 Seller Finder 的有效站点不包含 Brazil（domain 12）；站点下拉应按场景过滤，不能复用所有场景的站点列表。

### 4.3 示例

```json
{
  "search": "thriftbooks",
  "activeOnly": true,
  "hasFBA": true,
  "currentRating_gte": 95,
  "currentRatingCount_gte": 1000,
  "perPage": 50,
  "page": 0,
  "sort": [["currentRatingCount", "desc"]]
}
```

## 5. Deals（`/deal`）

### 5.1 必填与核心筛选

| 分组 | 运营字段 | Keepa 字段 | 控件与说明 |
| --- | --- | --- | --- |
| Deal 类型 | 价格类型 | `priceTypes` | 单选，不要使用多选；例如 Amazon 价、New、Sales Rank、Lightning Deal、Warehouse、Buy Box |
| 时间窗口 | 变化发生时间 | `dateRange` | 下拉：最近 24 小时、7 天、31 天、90 天（官方值 0–3） |
| 类目 | 包含/排除类目 | `includeCategories` / `excludeCategories` | 类目 ID 多选，最多 500 个 |
| 价格变化 | 当前价格、变化金额、变化百分比 | `currentRange`、`deltaRange`、`deltaPercentRange` | “启用价格范围”后显示最小/最大；金额按站点货币展示，提交最小货币单位整数 |
| 排名与评分 | Sales Rank、最低评分 | `salesRankRange`、`minRating` | Sales Rank 范围；评分 UI 0–5 星，提交 0–50；`-1` 表示不限制 |
| Deal 状态 | 历史最低、最低报价、缺货、Amazon offer | `isLowest`、`isLowest90`、`isLowestOffer`、`isOutOfStock`、`mustHaveAmazonOffer`、`mustNotHaveAmazonOffer` | 开关，默认不限制 |
| 商品属性 | 标题、品牌、材质、型号等 | `titleSearch`、`brand`、`manufacturer`、`material`、`model`、`color` 等 | “商品属性”折叠面板；数组字段用标签输入 |
| 排序与分页 | 排序、页码 | `sortType`、`page` | 排序下拉：最新 Deal、绝对变化、Sales Rank、变化百分比；每页最多 150 |

### 5.2 关键约束

- `priceTypes` 必填且只能有一个值；界面必须使用单选。
- Deals 请求每页最多 150 条，最多翻页到 10,000 个 ASIN；默认第一页即可满足运营查看。
- 范围条件只有在 `isRangeEnabled=true` 时生效；若运营填写价格范围，客户端应自动打开该开关。
- `isFilterEnabled` 是官方筛选开关；若页面有任一高级筛选，客户端应自动设置为 `true`，不让运营手动填写。
- `domainId` 应由顶部站点选择器生成，不再在 selection JSON 中重复让用户填写；服务端仍保留校验。

### 5.3 示例

```json
{
  "page": 0,
  "priceTypes": [0],
  "dateRange": 1,
  "isRangeEnabled": true,
  "currentRange": [1000, 5000],
  "deltaPercentRange": [20, 100],
  "includeCategories": [165793011],
  "minRating": 40,
  "sortType": 4
}
```

## 6. 前端落地建议

1. 普通模式只展示“基础定位/价格与销量/竞争与口碑/供货与 Buy Box/结果控制”五组；每组默认只显示 3–6 个最常用字段。
2. 高级模式用 schema 驱动：字段元数据包括 `label`、`help`、`type`、`unit`、`enum`、`keepaKey`、`gteKey`、`lteKey`、`maxItems`。这样可在不改请求组装器的情况下补充 Keepa 新字段。
3. 数组输入统一使用标签组件；保存值为数组，不把逗号字符串直接发送给 API。
4. 所有空值字段在序列化时删除；不要发送 `null`、空数组或默认 `false`，避免误触发筛选。
5. “查看请求”可以展示生成后的 selection JSON，但默认只读；编辑 JSON 需明确进入高级/调试模式，编辑后重新解析并回填表单。
6. Product Finder、Seller Finder、Deals 建议使用 POST 传输 selection，避免复杂条件造成 GET URL 过长；当前场景执行链主要走 GET，这是后续接口层优化项。
