# ops-dataset-query 第二轮字段与合同优化报告

> 日期：2026-07-16  
> 数据口径：仅使用现有 `datasets.csv`、`dataset_fields.csv`、`dataset_select_columns.csv`、`intent_rules.json` 与 `VERSION.json`  
> 约束：未新增、未生成任何索引文件；未修改 ready 快照中的 CSV/JSON 数据

## 一、优化目标

第一轮基线确认了四个相互关联的 P0 问题：字段名大小写折叠导致物理身份冲突、跨数据集标签污染、显式多字段被展示名去重吞并、合同容量无法兑现公开的 32 字段上限。本轮只处理字段解析与静态合同，不混入选表和执行状态改造。

```mermaid
flowchart LR
    A["用户查询与 --field"] --> B["大小写敏感精确解析"]
    B --> C["选中数据集字段作用域"]
    C --> D["显式 field_name 身份保留"]
    D --> E["model_view 中文投影"]
    D --> F["execution_ref 物理字段"]
    E --> G{"投影一致性"}
    F --> G
    G --> H["严格 Schema 与体积守卫"]
```

## 二、改动与原理

### 2.1 字段点名采用四级匹配

解析顺序调整为：

1. NFKC 后大小写敏感的 `field_name`；
2. NFKC 后大小写敏感的主展示名或备选展示名；
3. casefold 后唯一技术名；
4. casefold 后唯一展示名。

这使同表 `SPU` 与 `spu` 保持不同物理身份，同时避免 `VCPM` 被另一字段的技术名 `vcpm` 抢先匹配。

### 2.2 授权字段收紧到已选数据集

原实现把 43 个数据集的中文字段标签汇总成全局兜底池，导致当前表没有的字段也能进入 `model_view`，而 `execution_ref` 因缺少 `field_name` 无法执行。本轮只加载已选 `dataset_alias` 的字段，并把完整字段身份、字段类型、公式/快照策略一并带入兜底投影。

### 2.3 显式字段与展示去重解耦

展示层仍可对系统推荐字段做长标签吞并，但 `selection_source=explicit` 的字段改为按 `field_name` 去重，且不参与维度/指标之间的包含删除。原则是：中文展示可以压缩，用户明确点名的物理字段身份不能丢失。

### 2.4 合同容量按公开上限校准

点名字段存在时，不再为每个字段类型机械填充 8 个无关 fallback；无显式字段的另一类型最多给 3 个推荐。指导合同与模型合同的体积上限分别调整为 16,000 和 24,000 字节，用真实 32 字段矩阵验证，而不是只提高常量。

### 2.5 修复严格 Schema 漂移

为运行时已存在的 `model_view.default_filters_zh` 和 `execution_ref.default_filters` 补充 Draft 2020-12 定义，恢复 `additionalProperties=false` 下的合同有效性。

## 四、仍未在本轮解决的问题

- Walmart/Wayfair 字段文本仍可能被平台槽位误识别；该问题属于语义抽取 span 与选表阶段，将在第三轮处理。
- 12 个低自然语义可达数据集、VC 中文全名误触发、同名数据集候选不可区分，属于数据集选择层。
- 快照元数据实际为 0 个标记样本，不能通过代码推断替代源数据修正。
- `planned` 状态与权限枚举、默认时间确认、执行 payload 绑定仍需单独收紧。

## 五、本轮结论

字段层已从“单字段近似可用、批量字段不可兑现”提升到真实快照下 1～32 字段全覆盖；model_view 与 execution_ref 的跨表身份断裂已经消除。下一轮可以在此稳定字段基础上处理选表语义、平台 span 和候选澄清质量。
