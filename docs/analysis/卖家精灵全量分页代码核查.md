# 卖家精灵全量分页代码核查

核查日期：2026-09-28。范围：当前已提交的 SellerSprite 选产品请求、队列、账号、额度、导出、上传、沉淀与缓存链路。本文只读核查代码并提出实施建议，没有修改业务代码，不依赖未提交的 SQLite 迁移方案。

## 结论与网页边界

首期应只支持 `product-research` 的网页可访问范围采集，默认单页 100 条保持不变。新增全量选项并不等于能取得页面宣称的所有匹配结果。

主任务本轮网页实测：LOFT 加两项床类目匹配总数 4830，100 条模式前两页各 100 条且无交集；跳转第 21 页或第 49 页时，页面提示“只支持查看前2000条，建议输入过滤条件获取精准结果”。当前页面分页组件亦设置 `maxTotal:2e3`。该边界应作为首期实现约束，不发送绕过网页可访问上限的请求。网页末页、缩小条件后的自然末页验证结果以主任务最终设计记录为准。

例如采满可访问的 2000 条后，应返回 `collection_complete=true`、`coverage=source_limited`、`total_reported=4830`、`access_limit=2000`。前者表示约定范围完成，后者明确未覆盖全部匹配结果。不能把 `collected_count < total_reported` 一律当程序失败，也不能把导出成功当成数据全量完整。

## 内存与列语义

当前把原始 response 放入 raw，再将所有 rows 放入 result；`result.to_dict()` 使用 dataclasses.asdict，写文件使用 `json.dumps` 构造完整字符串。[api_manager.py](../../opscli/seller_sprite/services/api_manager.py#L389)、[models.py](../../opscli/seller_sprite/domain/models.py#L65)、[api_manager.py](../../opscli/seller_sprite/services/api_manager.py#L1365)

格式化先构造完整二维 `worksheet.rows`，XLSX 再使用普通 `Workbook()` 创建全部单元格对象。[xlsx.py](../../opscli/seller_sprite/export/xlsx.py#L20)、[xlsx.py](../../opscli/seller_sprite/export/xlsx.py#L117) 因此不能简单在 manager 中不断 `rows.extend` 后认为内存安全。不过当前网页上限 2000 条显著缩小了首期规模，无需预先开发百万行分文件框架。

选产品列不能从查竞品或其他场景复制：`columns_for_scenario` 的选产品分支映射月销量为 `totalUnits`、子体销量为 `amzUnit`，有站点币种、百分比、LQS 等转换。[columns.py](../../opscli/seller_sprite/export/columns.py#L552)、[columns.py](../../opscli/seller_sprite/export/columns.py#L599) 流式导出应复用选产品列定义和 `_column_value` 转换，仅替换批量存储方式。同比增长字段是否应随 salesGrowthType 改变导出列，需要单独核对页面响应，不能趁分页改造直接猜测。

推荐全量首期只开放 XLSX 文件交付和小摘要，单页 JSON 保持兼容。使用逐行格式化和 `Workbook(write_only=True)`，保留表头、列宽、冻结行与必要数字格式。openpyxl 要求先配置冻结窗格等元数据，再 append；write-only 工作簿只能保存一次，不能作为采集中途断点文件。样式可以通过 WriteOnlyCell 设置。[openpyxl 官方说明](https://openpyxl.readthedocs.io/en/stable/optimized.html)

不要重写已经有界的链路：

- XLSX 沉淀使用 `load_workbook(read_only=True)` 和记录迭代器，MySQL 分批 executemany，已具备逐行入库基础。[parser_utils.py](../../opscli/shared/collection_storage/parser_utils.py#L186)、[mysql_repository.py](../../opscli/shared/collection_storage/mysql_repository.py#L669)
- 上传使用文件句柄作为 multipart 内容，重试时重新打开文件，不是 `read_bytes` 全文件加载。[file_uploads.py](../../opscli/shared/file_uploads.py#L253)
- 但沉淀入口仍先加载 result.json，所以全量 result 必须只有摘要与文件引用。[parser_utils.py](../../opscli/shared/collection_storage/parser_utils.py#L39)
- JSON 格式的缓存命中会读取所有 Dataset records 并 fetchall；MCP 也会完整读取 JSON 工作簿。首期限制全量 XLSX 可以避开这条全量内存路径。XLSX 缓存命中目前已使用 `include_datasets=false`，可继续复用文件元数据。[mysql_repository.py](../../opscli/shared/collection_storage/mysql_repository.py#L470)、[seller_sprite.py](../../opscli/mcp/tools/seller_sprite.py#L1113)
- `safe_result_metadata` 当前只保留 row_count、export、warnings；应扩展必要分页与覆盖状态，否则命中缓存时会丢失“仅前 2000 条”的声明。[result_cache.py](../../opscli/shared/collection_storage/result_cache.py#L76)

## 首期最小实施建议

1. 增加 `collection_scope=page|all`，默认 page；首期拒绝其他场景的 all，拒绝全量 JSON 以免静默改变其合同。all 从第一页开始，只读网页允许的前 2000 条。是否需要前 N 条可作为后续小扩展，无需首期同时引入多种范围协议。
2. 独立选产品分页编排函数：第一次构建并冻结业务 payload，后续只改页码；每页 referer 由同一 builder 重建。每页验证 response 页码、size、items、total、pages、hasNextPage 的实际合同。结合网页边界计算可访问页数，不能仅因短页就结束；元数据矛盾、页码不前进、整页指纹重复应停止并报告不完整。
3. 每页成功后将响应写入代际目录的临时文件并原子替换，再提交检查点。检查点保存查询指纹、页号、实际 size、文件相对路径、hash、账号键和当前 generation。检查点提交沿用队列当前执行的条件更新；只有已提交页可用于恢复。崩溃留下未提交文件可忽略重取，不能推进页码造成缺页。
4. 同一任务锁定账号和已解析类目、monthName、排序、变体模式。跨重启只在查询指纹、账号与页大小一致时续取；账号变化默认新采集序列，避免把不同权限/时点页面默默拼接。页内短暂网络错误有限重试，不重试已经落盘的页；登录失败、额度/访问限制保留部分结果。账号替换不是绕过来源限制的手段。
5. 2000 条上限允许使用严格有界的 ASIN 去重集合，无需首期磁盘去重数据库。记录重复数量；展示变体时不按 parent ASIN 去重。缺失稳定业务键应保留诊断信息，不把全部缺失键合成一条。由于来源没有快照，去重不能证明没有遗漏，应保留首次/末次 total 与采集时间。
6. 全量 result.json 与 raw.json 改为版本化摘要/分页清单，完整响应保存在页文件；流式读取页文件导出。summary 至少包括 requested_scope、collection_complete、coverage、stop_reason、total_reported、access_limit、effective_page_size、pages_completed、rows_received、rows_exported、duplicates、first/last_collected_at。`data` 只保留明确标注的有限 preview，不能让调用方把预览条数当总行数。
7. 分开记录采集完成度、导出和上传结果。仍可使用既有 succeeded/failed 任务状态，但部分失败的结果文件与分页信息必须能从任务状态中取得；只有约定范围完成的结果进入成功缓存。达到来源 2000 条上限属于范围成功、coverage=source_limited；超时、异常空页、取消属于部分结果。已采齐后的上传失败只重传文件，不重新查询所有页。
8. 使用既有任务租约和同账号串行，不首期建设跨账号分页并发或全新调度器。增加页级进度与取消检查；按实测耗时配置 all 的总预算和每页预算。默认 600 秒能否保留由 20 页实测/模拟重试验收决定，不无限放大所有场景超时。
9. 完整 XLSX 继续复用 collection submitter、Outbox、read-only parser、批量入库。不要将部分失败写成正常完整 cache。缓存键加入 collection_scope、可访问上限合同和版本；缓存元数据带上覆盖状态。当前跨账号共享策略在固定网页合同下可保留，账号权限差异须另设可访问范围指纹或禁用该缓存命中。

## 必要验收与待验证

- 页面：100 条模式前两页、第 20 页、缩小筛选后的自然末页、零结果；记录允许请求的 request/response 样本与限制提示。不同场景不默认使用相同分页参数。
- 请求：全量第 2 页与第 1 页除页码和相应 referer 外业务条件完全一致；分页输入正整数、size 冲突和 startPage 规则明确。
- 异常：第 k 页网络重试、身份失效、来源额度错误、意外空页、重复页、total 漂移；都不能误报全量完成。
- 恢复：页文件已写但检查点未提交、检查点已提交后进程退出、旧 generation 写回被拒绝、不同账号不能混接、导出失败只重新导出。
- 数据：相同页面样本新旧 XLSX 列顺序、币种、数字、空值、子体/父体口径一致；网页变体模式下保留不同子 ASIN。
- 内存：模拟 100、1000、2000 条真实宽度记录，测完整链路峰值 RSS；包括导出、上传 mock、result 序列化、XLSX 沉淀和缓存命中。只有实测才能给部署内存预算，不能凭最终文件体积推断。
- 边界：磁盘不足、页文件损坏、上传超时、取消后部分文件可读、缓存命中仍带 source_limited。2000 条上限下不需要先实现 Excel 超百万行分片。

本文没有运行真实采集或修改 quota 策略。网站每翻一页实际消耗的账号额度、不同会员的可访问上限、response 分页字段与视频/同比导出语义等，未由代码核查单独证明，应以主任务网页证据和后续契约测试为准。
