# SQLite 迁移复核：队列与监控证据

复核日期：2026-09-30。范围：SellerSprite 队列、调度器、Collector Bundle、Collector Monitor 服务端存储，以及 browser worker 会话事件落库。

## 1. 结论与证据边界

**代码层面不能认定迁移完成。** 两个基线的 SellerSprite 默认队列仍由 `sqlite3.connect` 实现；Monitor 仍直接读取队列及 quota SQLite，并持续写入自己的 SQLite 状态库；browser worker 在特定路径下仍创建独立 session events SQLite。迁移 DDL 是预建表脚本，不是运行时切换证明。

最关键的已证实差异：

1. **主仓库 v9 的 `seller_sprite_product_checkpoints` 整表缺失。** 通用任务领取 SQL 无条件包含该表的子查询，缺表会阻断这条领取路径，不只是失去分页恢复。迁移 worktree 仍为 v8，不能只用其旧表集合验收主仓库迁移。
2. **DDL 与当前队列 SQL 不兼容。** 当前入队、上下文读取和终态更新均引用 `session_id/jwt`；DDL 未建这两列，新增的 `auth_context_*` 没有被当前队列实现消费。应完成接口及历史任务策略适配，不能简单把 MySQL 连接接到旧 SQL 上。
3. **Monitor 的 quota 路径未随 quota 后端选择切换。** 未提交 quota 代码支持显式选择 MySQL，但 Monitor 仍用 SQLite 路径和 `day` 字段；目标 MySQL 使用 `quota_day DATE`。
4. **Monitor 自有 `state.sqlite3` 的三张表不在 DDL 中。** 它们承载告警生命周期、连续观测和扫描状态，是服务端持久依赖，不是页面展示缓存。
5. **`.seller_sprite_session_events.sqlite3` 是独立数据库路径，不是同名独立表。** 写入复用 `seller_sprite_account_events`；目标表虽已预建，写入入口及多来源历史数据仍未统一。

特别校正：在这两个指定基线中，**证明了 Monitor 直接读 quota SQLite，未发现 Monitor 直接写 quota SQLite**。该连接明确使用 `mode=ro` 与 `PRAGMA query_only=ON`。Monitor 自身的直接写入发生在状态库；可选 scenario-test 请求会调用 Collector MCP，不能因此称为直接写 quota。详见第 4 节。

上述结论是源码可达调用链与静态 SQL 契约结论。**生产是否部署这些版本、进程是否运行、DDL 是否执行、实际后端环境变量、数据库文件是否存在及其行数、历史数据是否迁完，全部未知。** 本次未访问生产、网络、数据库、凭据、业务输出或日志，未启动服务、导入业务模块或运行业务/测试。

### 3.3 确实阻挡切换的差异

**检查点表：主仓库已使用，旧 worktree 尚无。** [领取 SQL:370](D:/Gitlab/open-opscli/opscli/seller_sprite/services/task_queue_store.py:370) 检查已有分页、账号键和 deadline，防止在恢复窗口把任务交给其他账号。该子查询是每次通用领取 SQL 的组成部分，即使候选任务本身没有分页清单，数据库仍需解析该表。[Scheduler:1703](D:/Gitlab/open-opscli/opscli/seller_sprite/services/task_scheduler.py:1703) 把加载和保存回调注入 manager；保存方法校验 running、账号、执行代际、执行者及未过期租约。仅有 DDL 前七表时，保留主仓库行为的 MySQL 实现无从执行这些操作。须补表、数据策略及等价查询，不应为了适配旧 DDL 删除主仓库分页能力。

**鉴权字段：是尚未完成的契约替换，不是要求恢复明文存储。** [普通入队:108](D:/Gitlab/open-opscli/opscli/seller_sprite/services/task_queue_store.py:108) 和 [MCP 入队:156](D:/Gitlab/open-opscli/opscli/seller_sprite/services/task_queue_store.py:156) 仍显式插入 `session_id/jwt` 列（新任务写 NULL），[上下文读取:1917](D:/Gitlab/open-opscli/opscli/seller_sprite/services/task_queue_store.py:1917) 查询它们，[终态更新:855](D:/Gitlab/open-opscli/opscli/seller_sprite/services/task_queue_store.py:855) 清空它们。目标 [DDL:131](D:/Gitlab/open-opscli-worktrees/sqlite-to-mysql-migration/scripts/create_sqlite_runtime_mysql_tables_v1.sql:131) 改用 `auth_context_ref/auth_context_ciphertext/auth_crypto_version/auth_key_id`。当前调度器 [308 行](D:/Gitlab/open-opscli/opscli/seller_sprite/services/task_scheduler.py:308) 已把显式凭证限制为内存保存，[1984 行](D:/Gitlab/open-opscli/opscli/seller_sprite/services/task_scheduler.py:1984) 优先从内存或 CredentialStore 取凭据，只在旧任务兼容分支读旧列。因此需要明确旧任务排空/失败重提/受保护引用的策略，并同步改 SQL 和上下文接口。新建四个字段本身不会完成该适配。

**运行时仍绑定 SQLite。** `BEGIN IMMEDIATE`、`?` 占位符、`ON CONFLICT`、`PRAGMA`、SQLite JSON/时间函数及 `sqlite3.IntegrityError` 都在真实读写路径上，例如 [领取:360](D:/Gitlab/open-opscli/opscli/seller_sprite/services/task_queue_store.py:360)、[检查点保存:1243](D:/Gitlab/open-opscli/opscli/seller_sprite/services/task_queue_store.py:1243)、[初始化:2337](D:/Gitlab/open-opscli/opscli/seller_sprite/services/task_queue_store.py:2337)。SQLite 已有代际 CAS 和租约逻辑；缺的是 MySQL 等价实现与选择入口，不能笼统说“整个项目没有 CAS”。DDL 新增 `lease_token` 和账号运行态唯一保护也不等于代码已使用它们。

**其余字段无已证实漏列，不代表迁移安全已验证。** 静态列名比对结果：主队列只缺旧 `session_id/jwt` 两列，额外新增四个 `auth_context_*` 字段、`lease_token`、`updated_at`、`running_account_guard`；前述六张附属表的现有列名均已覆盖。需要验证的语义包括文本时区到 `DATETIME(6)` 的统一转换、JSON 返回类型、行锁/并发领取、唯一约束和新增外键的存量数据兼容。当前 [时间生成:2814](D:/Gitlab/open-opscli/opscli/seller_sprite/services/task_queue_store.py:2814) 会生成带本地偏移或 UTC 的 ISO 字符串，不能直接假设与 MySQL 无时区 DATETIME 等价。

**DDL 的 ready 不证明字段齐全或迁移完成。** [文件说明:14](D:/Gitlab/open-opscli-worktrees/sqlite-to-mysql-migration/scripts/create_sqlite_runtime_mysql_tables_v1.sql:14) 明说只创建空表，不搬数据、不改配置、不切流；[队列说明:97](D:/Gitlab/open-opscli-worktrees/sqlite-to-mysql-migration/scripts/create_sqlite_runtime_mysql_tables_v1.sql:97) 标明 PRE-CREATE ONLY；[ready 判断:277](D:/Gitlab/open-opscli-worktrees/sqlite-to-mysql-migration/scripts/create_sqlite_runtime_mysql_tables_v1.sql:277) 仅统计七个表名，不检查列、索引或外键。因此即使 `queue_schema_precreated=1`，也无法发现 v9 检查点表缺失或既有同名表结构不兼容。

### 4.2 quota：证明直接读，未证明直接写

[Monitor 配置:104](D:/Gitlab/open-opscli/opscli/collector_monitor/config.py:104) 只取 `ENV_SQLITE_PATH` 或 `CONFIG_DIR/mcp_quota/quota.sqlite3`；[server.py:36](D:/Gitlab/open-opscli/opscli/collector_monitor/server.py:36) 将该路径传入 `AccountMonitorRepository`。[usage_today:154](D:/Gitlab/open-opscli/opscli/collector_monitor/storage/account_repository.py:154) 以北京时间生成 `YYYYMMDD`，验证 `day` 列，再执行 `WHERE day = ?`。连接由 [account_repository.py:516](D:/Gitlab/open-opscli/opscli/collector_monitor/storage/account_repository.py:516) 转到 [storage/sqlite.py:23](D:/Gitlab/open-opscli/opscli/collector_monitor/storage/sqlite.py:23)，明确 `mode=ro`、`query_only=ON`。
