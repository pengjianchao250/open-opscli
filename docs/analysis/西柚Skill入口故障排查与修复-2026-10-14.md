# 西柚 Skill 入口故障排查与修复

## 结论与证据

截图 1、2 展示的是 Agent 在执行查询前判断“工具未挂载”并停止，没有供应商错误码、真实请求或 Trace ID，不能归因为西柚接口故障。截图 3 显示同名 Skill 出现两次，可作为检查安装来源的线索，但不能仅据此认定重复安装导致工具不可用。

2026-10-13 的最新源码将西柚 MCP 收敛到操作目录和通用查询两项工具。ops-xiyou v2.0.0 只指导宿主 MCP 直连，工具不可见时直接提示检查连接；同时顶级 CLI 没有 xiyou 注册，无法像 Keepa 一样从终端继续查询。新增回归通过顶级 CLI 复现 `No such command 'xiyou'`，两项用例修复前均失败。

本轮在本会话中发现了西柚 MCP 工具，并实际调用一次 `ext_xydc_openapi_operations({})`，返回 `success=true` 和 21 个公共操作。当前会话的工具元数据还包含四个旧包装，与尚未发布的两工具源码目标不同；这说明发布与刷新必须分别检查，不能把源码清单当作用户已连接服务的清单。目录查询不进入供应商收费 Provider，成功不证明凭据池和具体 ASIN 历史查询可用，也不代表截图用户的连接状态。

## 对照 Keepa 后的改动

| 入口 | Keepa | 西柚修复后 |
| --- | --- | --- |
| 宿主直连 | keepa_* tools | ext_xydc_openapi_operations / ext_xydc_openapi_call |
| 终端代理 | opscli keepa | opscli xiyou operations / call |
| 远端连接 | RemoteMcpAdapter 读取当前 OPS 用户的 MCP 配置 | 复用同一适配层 |
| 供应商凭据 | 服务端管理 | 服务端管理，本机不初始化 MySQL 凭据池 |
| 输出 | Keepa 任务与服务端 JSON/XLSX 导出 | 通用查询完整 JSON，可落盘后在本地生成 Excel |

新 CLI 的业务 payload 原样透传，不改页码、站点、父子体或日期；公开操作名复用 REST/MCP 的静态合同。支持参数文件以避免终端 JSON 转义问题，文件接受 UTF-8 BOM。远端 `success=false` 保留原始响应、返回退出码 1，不由 CLI 自动改参或重复请求；共享层既有 MCP 401 配置刷新机制保持原样。

Skill v2.0.1 增加工具发现与 CLI 备用入口，区分“Skill 可读取”“宿主工具已挂载”“客户端包含命令”“远端工具及权限可用”。只有这些可用入口确实未满足时，才报告未执行查询并给出具体缺口；业务查询失败不跨链路自动重放。

针对截图中的历史表格任务，增加按真实父子体关系、月订单、目标类目日 BSR 生成月度报告的说明。供应商没有声明父体汇总时不把 ASIN 订单量标成父体销量；类目月均排名按同一类目 ID 的有效日值计算并报告覆盖天数；开售日期、早期历史、当前未结束月份及缺失数据分别说明。

## 验证与边界

- 修复前入口与顶级 CLI 到远端传输的两项回归均失败，修复后通过。
- 西柚 Provider、CLI、REST、MCP、Skill 安装、懒加载与共享/Keepa/鹰眼远端适配层：142 项通过。测试使用模拟网络和临时目录。
- 新 CLI 覆盖 JSON 输入校验、输入二选一、内部操作拒绝、BOM 文件、完整响应保存、远端错误保留与不重复执行。
- Skill Creator 校验、Python 编译和 diff 检查通过。
- 真实远端仅调用目录一次成功；未执行收费商品、流量、订单或排名查询，未更改用户安装目录、宿主连接配置、生产服务或数据库。

## 发布后验收

按 [西柚 MCP 统一入口迁移说明](../guide/西柚MCP统一入口迁移说明.md) 同步客户端、Skill 和服务工具/角色权限。只发布 Skill 无法让旧程序产生 xiyou 命令；只更新服务也不会自动改变已有会话缓存。

先在目标用户环境检查程序版本、`opscli xiyou --help` 和不收费的 `opscli xiyou operations`，或通过宿主发现并读取两项通用工具。确认入口可用后，按真实业务任务执行查询；若出现具体错误，保留工具/命令、实际参数、原始错误和 Trace ID，并按项目 ops-feedback 规则提交。没有真实失败记录时，不将历史截图推断成当前服务故障。
