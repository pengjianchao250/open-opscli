# 卖家精灵实时查竞价场景参数调研

## 结论

实时查竞价可以纳入 Collector MCP，但列表页、详情页和列表导出不是同一数据口径：

- 列表页 `/v3/real-time-bidding` 展示任务摘要，并通过 `taskList` 查询任务状态。
- 详情页通过 `getTaskDetail` 分页展示关键词；页面可按 `adType=sp/sb` 切换竞价列。
- 列表页官方导出通过 `exportTaskDetail` 和 `taskIdList` 生成完整工作簿，不是把任务摘要直接写入 Excel。

因此，本地导出不能只使用列表摘要，也不能只使用详情页当前广告类型的一次响应。实现会先判断普通查询历史：已有完成/失败记录时触发一次“再次查询”，没有历史时通过弹窗新建默认“亚马逊推荐关键词”任务，已有进行中任务只等待；官网示例记录只读。任务完成后分别读取 SP 和 SB 第一页，并按关键词严格合并为官方 46 列。

## 页面与接口证据

核验时间：2026-07-31。

| 阶段 | 接口 | 关键参数 / 返回 |
| --- | --- | --- |
| 新建任务 | `POST /v3/api/keywordbidding/newTask` | `taskType=AC`、单个 `asin`、`keywordList=[]`、`marketId` |
| 查询任务 | `POST /v3/api/keywordbidding/taskList` | 按 ASIN、站点分页查询；状态 `3` 表示完成，`4` 表示失败 |
| 查询历史 | `POST /v3/api/keywordbidding/queryTaskTimeList` | 通过 `parentTaskId` 获取历史任务 |
| 详情列表 | `POST /v3/api/keywordbidding/getTaskDetail` | `taskId`、`parentTaskId`、`page`、`size`、`adType` |
| 列表导出 | `POST /v3/api/keywordbidding/exportTaskDetail` | `taskIdList`；返回工作簿二进制 |

核验期间在真实登录页面创建并完成一次美国站 `B07Z82895W` 的“亚马逊推荐关键词”任务，确认任务列表、完成状态和详情页链路可用。Collector 复用同一页面交互：无普通历史时打开官网弹窗创建推荐关键词任务，有完成/失败历史时按官网 `queryAgain` 参数刷新任务。

## 查询参数

| 参数 | 规则 |
| --- | --- |
| `site` | 默认 `US`；映射为页面 `marketId` |
| `asin` | 必填且只能一个；10 位字母数字 |
| 历史判断 | `taskList` 按 `updatedTime` 倒序持续翻页；完成/失败记录再次查询，进行中只轮询，无记录则新建；未知状态不得提交 |
| 明细分页 | SP、SB 均固定第一页 `page=1/size=100` |

## 详情字段与官方 46 列

详情关键词行提供：

- 基础字段：`keyword`、`keywordCn`、`weekSearchNum`、`rank`、`displayNum`、`clickNum`。
- SP：`autoSponsor` 和 `manualSponsor`，各含 `EXACT/BROAD/PHRASE` 的 `value/min/max`。
- SB/SBV：`sponsorBrand` 和 `sponsorBrandVideo`，各含 `EXACT/BROAD/PHRASE` 的 `value/min/max`。
- 集中度与 ASIN：`abaConcentrationDegree`、`cvsShareRate`、`topClickAsin`。
- 查询时间：详情响应的 `data.task.queryTime`，写入每一行。

列数校验：7 个基础列 + 12 组竞价乘 3 个值 + 2 个占比 + 1 个 ASIN 列，共 46 列。

## 本地导出策略

1. 按站点和 ASIN 查询普通任务列表；只有完成/失败记录或确认无历史时才调用一次 `newTask`，未知状态不得提交。
2. 从更新时间倒序列表持续翻页：普通历史已有完成/失败记录则“再次查询”，无记录则弹窗新建，进行中只轮询；US 无普通记录时额外精确识别官网示例且不创建任务。
3. 对该任务分别请求 `adType=sp` 和 `adType=sb` 的第一页 100 条。
4. 校验两组关键词集合完全一致后按 `keyword` 合并，保留 SP、SB 和 SBV 的完整竞价字段。
5. 本地生成 46 列业务主表，不调用官方导出接口，不生成 `Notes`。

官方原件保存在 `tests/fixtures/seller_sprite/official_exports/real-time-bidding/`，仅作为不可变回归基线；所选历史任务的查询时间和竞价值可能与该原件不同。
