核对日期：2026-09-28。范围为 `product-research` 的非分页参数、页面初始化 URL 和缓存兼容。分页保持原状。

## 证据来源和边界

1. 用户提供的原会话 `codex://threads/01a0e6bb-e891-7370-9eb2-c31756091d29` 中，`POST /v3/api/product-research` 的实际 curl 请求。只保留业务 body 到 `tests/fixtures/seller_sprite/product-research/page-request-20260928.json`，不保存 Cookie、Token 或账号信息。
2. 已登录 Chrome 中的[选产品页面](https://www.sellersprite.com/v3/product-research)，实际操作匹配模式、展示所有变体和主图视频，读取控件状态及页面生成的 URL。
3. 当前页面加载的官方静态资源：
   - [表单字段和参数转换](https://www.sellersprite.com/v3/webapp/static/js/chunk-1d0709b8.f51240dbabf5.js)：包含词使用 `keywords`；匹配单选框使用 `selectType=2/3/4`；URL 的视频值按布尔字面量解析。
   - [列表请求和 URL 构建](https://www.sellersprite.com/v3/webapp/static/js/chunk-2bd9164c.c6711696d05e.js)：`initData` 复制查询参数构建 URL，随后执行 `n.symbolFlag=!n.symbolFlag` 再调用查询；视频 POST 使用 Y/N，URL 转为布尔值；销量增长率排序区分环比、同比。
   - [状态默认值和文案](https://www.sellersprite.com/v3/webapp/static/js/app.55778a35ea36.js)：增长率比较默认 `30d`，区分环比和同比。

本轮浏览器工具没有提供网络请求捕获能力，因此未声称重新抓到每次点击的 POST。修复依据是已有真实 POST、当前页面源代码和登录页面行为三者对照；本地测试另行检查 browser-route 真正传给 `route.continue_` 的请求体。没有用其他场景的字段语义推断本场景，也没有运行远端部署后的 CLI/MCP 端到端采集。

## 参数对照与修复

| 含义 | 本页合同 | opscli 修正 |
| --- | --- | --- |
| 包含词 | `keywords` 字符串，多个以英文逗号分隔 | `keyword` 仅作旧别名；原生字段优先；拒绝数组 |
| 匹配模式 | `selectType="2"` 模糊、`"3"` 词组、`"4"` 精准 | 不再向 POST 传 `matchType`；旧值 0/1/2 转换为 2/3/4 |
| 展示所有变体 | 控件及 URL 为 true；POST `symbolFlag=false` | 保留 POST 原义；构建 URL 时取反；兼容 `loadVariations` |
| 排序 | 嵌套 `order.field`、`order.desc` | 原生 `order` 优先，缺省时兼容扁平别名 |
| 数据周期 | `monthName` | 保留原映射 |
| 增长率比较 | `salesGrowthType=30d` 环比、`yoy` 同比 | 独立于数据周期，默认环比；增长率排序同步选择相应字段 |
| 主图视频 | POST 为 Y/N；URL 为 true/false；不限为空 | 接受 Y/N 或布尔值，分别序列化 POST 与 URL |
| URL 布尔值 | JavaScript 小写 true/false | 本场景的变体、子类目、排序方向和视频使用小写 |
| 历史缓存 | 同一旧入参可能曾被映射成错误条件 | 仅为选产品加入请求合同版本，隔离旧缓存；不删除旧数据 |

`salesGrowthType` 缺失不能单独解释原查询结果差异：原会话重试时还改变了关键词类型等条件。本次没有把多变量变化误判为单个字段的因果关系。
