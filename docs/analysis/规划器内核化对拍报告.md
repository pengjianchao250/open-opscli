## 四、逐条归因（可接受差异 vs 真实回归）

对拍过程发现两处差异，逐条归因如下：

### 4.1 可接受差异：`execution_ref.table_id` 类型归一（int vs "1"）

- 现象：旧 CSV 路径 `table_id` 为字符串 `"1"`，新适配器路径为 int `1`。
- 归因：CSV 值恒为字符串；后端 JSON 的 `table_id` 为 int。两者指向同一张表，
  且 `QueryManager.build_simple` 的 `table_id: int` 期望 int，**新路径更规范**。
- 处置：对拍按字符串归一比对语义身份，类型差异不计为回归。

### 4.2 真实回归（已修复）：权限枚举结果形状不匹配导致二段收敛失效

- 现象：platform_enum 用例，新规划器初版返回 `requires_permission_enum`
  （`resolved_platform_values: []`），而正确结果应为 `blocked`（账号仅授权 Temu、
  请求 Amazon 无重叠）——旧规划器正确返回 `blocked`。
- 根因：`entry._extract_enum_values` 只兜底多级嵌套形状（`data.result.data` 等），
  而 `QueryManager.build_simple_and_run().get("result")` 的真实形状是
  `{success, data:[行...], meta}`——**行直接位于 `result["data"]` 一级**。
  路径不匹配 → enum_fn 恒返回空 → 平台/组件权限枚举二段收敛静默失效。
- 影响：所有需权限枚举的平台/部门筛选查询（生产高频路径）会拿不到授权值，
  无法正确 blocked/resolved，退化为「待枚举」并要求模型走手动枚举命令。
- 修复：`_extract_enum_values` 路径新增一级 `("data",)`（优先），锁定真实形状；
  新增回归单测 `test_extract_enum_values_from_raw_simple_result`。
- 验证：修复后 enum_fn(7,'platform_name') 返回 `['Temu']`，platform_enum 用例
  收敛为 `blocked`，对拍 6/6 一致。

> **安全网价值**：本次对拍即在 Phase 4 内捕获并修复了一处会导致生产权限枚举
> 静默失效的真实回归——正是回归对拍安全网的目标所在。
