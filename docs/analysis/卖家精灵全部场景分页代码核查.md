# 卖家精灵全部场景分页代码核查

核查日期：2026-09-28。基线：选产品全量分页提交 `2477cafc`。本文仅做源码和现存一手抓包研究，没有调用账号接口、没有操作浏览器、没有修改业务代码。网页新一轮验证由主任务另行记录。

## 结论与证据边界

16 个场景不能共享同一种翻页请求。当前至少存在普通 JSON 页码、JSON offset、HTML 查询、官方 XLSX 下载、创建任务后查询详情、单 ASIN 报告六类合同。`collection_scope=all` 目前明确仅允许 `product-research`，见 [models.py:48](../../opscli/seller_sprite/domain/models.py#L48)。其他场景应逐个验证并注册适配器，不能把选产品的 2,000 条、ASIN 判重或 `data.items/data.total` 当成通用合同。

证据分三层：源码表示“当前实现”；本地捕获的原始响应表示“该时间、该账号、该查询的实际结果”；manifest、脱敏摘要、官方导出工作簿表示有限的历史证据。第一屏、一个 XLSX 文件或 `replay_safe=true` 都不能单独证明全量分页正确、当前访问上限或整个流程可安全重复执行。

### 多层截断与大小参数优先级

公共 `build_payload` 同时注入 `size` 和 `pageSize`，其中 branddb 的 pageSize 默认是 20，其余为请求 page_size；不同构造器取值优先级不同，见 [scenarios.py:55](../../opscli/seller_sprite/api/scenarios.py#L55)。因此统一 page_size 不能替代场景参数冲突检查。

manager 对 keyword-comparison、traffic-extend、keyword-conversion-rate、real-time-bidding 做 `rows[:100]`，见 [api_manager.py:419](../../opscli/seller_sprite/services/api_manager.py#L419)。通用 `build_export_worksheets` 和 `export_rows_to_xlsx` 又分别对后三者截断，见 [xlsx.py:93](../../opscli/seller_sprite/export/xlsx.py#L93)、[xlsx.py:163](../../opscli/seller_sprite/export/xlsx.py#L163)。仅实现翻页会出现“采集多页、导出仍 100 条”的隐蔽错误；需要在新的 all 路径单独解除这些限制，同时保持 page 模式兼容。

## 可复用的底层与必须独立适配的边界

可复用的是机制，而非产品字段：逐页原子落盘、文件 SHA256、任务目录边界检查、冻结账号和查询指纹、重试次数/总时间预算、checkpoint、generation/owner/lease 防旧 worker 覆盖、进度和完整性摘要。当前具体实现见 [product_pagination.py:26](../../opscli/seller_sprite/services/product_pagination.py#L26)、[task_queue_store.py:1229](../../opscli/seller_sprite/services/task_queue_store.py#L1229)、[task_scheduler.py:1709](../../opscli/seller_sprite/services/task_scheduler.py#L1709)。这些代码今天仍带 product 名称和产品专属状态，不代表已存在通用引擎。

需要逐场景声明并通过样本证明的部分：

1. 请求传输、页码起点、页键/offset 键、size 优先级、referer 和分页时必须保留的筛选。
2. rows/total/hasNext 路径，total 是否可信，响应 page/size 能否校验；缺失不能静默当成 0 或“全量完成”。
3. 网页允许的 page size、可访问总数、导出数、账号等级限制。2000 目前只在选产品本轮网页验证中成立。
4. 行唯一键。产品可用 ASIN；关键词类需要 keyword 或站点+周期+keyword；市场需要类目 ID/path；商标需要商标记录 ID。身份字段选择属于待验证设计，不是现有事实。
5. prepare、变体选择、远程 taskId、SP/SB 投影是否只初始化一次，恢复时如何保证上下文不变。replay_safe=false 的场景不得由通用重试重复提交任务或重复扣额。
6. 导出 schema/动态列与辅助聚合。词频、百分比、ASIN 辅助表必须以全查询范围产生，不能简单把多份工作簿连接。

当前流式导出函数仅支持选产品，`Workbook(write_only=True)` 见 [xlsx.py:21](../../opscli/seller_sprite/export/xlsx.py#L21)。普通导出仍构造所有格式化行，流量词对比另有动态矩阵，见 [xlsx.py:71](../../opscli/seller_sprite/export/xlsx.py#L71)、[keyword_comparison_xlsx.py:36](../../opscli/seller_sprite/export/keyword_comparison_xlsx.py#L36)。扩展时应先保留列转换/样式合同，再加入行迭代器和有界辅助汇总，不能因 2000 条的内存测试通过就认为所有场景都安全。all 当前不进入普通结果缓存，见 [collection_storage_integration.py:121](../../opscli/seller_sprite/collection_storage_integration.py#L121)，建议在各场景范围与账号可见性被证明前保留该原则。

| 关键词反查 `keyword-reverse` | 页面示例 ASIN 和已验证竞品 ASIN 均返回 0 条 | 已确认页面能稳定显示零结果状态，但当前账号/样本没有拿到非零列表，因此不能据此开放 all 或声明页上限 | 保留 page 模式；先补一条可复现的非零响应与第二页证据，再实现 `limit/skip` 翻页 |
| 查流量来源 `traffic-source` | US、最近 30 天、ASIN `B075BHK571`；先 50 条/页再改 20 条/页 | 50 条/页显示 1–41；20 条/页第 1 页显示 1–20、第 2 页显示 21–40，总数均为 41；页面使用 `pageNo/pageSize` 语义 | 可按页请求；解析器只依赖 `data.pager.items` 与 total，不校验历史响应里的 `pager.page/size` |

关键词挖掘的自然末页为 5 条，证明页面会按实际总数返回短页；选竞品和选产品的 2,000 条提示不能作为全站上限。以上实测尚未替代各场景的脱敏请求/响应夹具，正式实现仍要求把请求字段和响应路径写入每个场景的合同测试。

## 建议分批网页验收顺序

| 批次 | 场景 | 主要验收目标 |
| --- | --- | --- |
| A：普通 JSON | 选竞品、关键词挖掘、关键词反查、查流量来源 | 第1/2页请求差异、自然末页、零结果、size变更、总数口径和独立上限；优先复用历史结构夹具，补新分页证据 |
| B：固定首页和前置上下文 | ABA选品、关联流量、流量词对比、拓展流量词 | 去除固定首页前验证真实翻页；冻结prepare/变体；确认动态列和辅助表覆盖所有页 |
| C：HTML | 关键词选品、选市场 | 从各自主结果区域读取总数/当前页；确认表单翻页、排序和过滤稳定；空表区别于登录页/页面结构失效 |
| D：任务/额度流程 | 关键词转化率、实时查竞价 | 初始化一次、翻页不重复建任务；远程taskId/扣额证据；SP/SB两路页边界一致及恢复 |
| E：官方下载及单报告 | 出单词反查、全球商标库、Listing Analysis | 下载范围是否本就覆盖全部/仅选中；分页参数是否被导出忽略；单报告显式“不适用”，不强行加入页循环 |

每个列表场景至少保留：首两页的脱敏请求/响应与唯一键对照、自然末页和零结果、超页面可访问范围时的 UI 行为、账号会话失效/节流/中途恢复、最终 Excel 行数与抽样字段对照。页面不显示或无法验证的上限保持“未知”，不得继承其他场景的数值。只有证据达标的场景才开放 all；其他场景继续 page 或明确采用“官方导出/单报告”的能力说明。
