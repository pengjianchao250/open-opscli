# 卖家精灵选产品分页网页实测

日期：2026-09-28。环境：用户已登录的 Chrome，卖家精灵 `v3/product-research`。本轮仅查询和切换筛选，没有调用网页导出、批量采集全部 2000 条或修改账号设置。

## 结论

1. 本账号、本页面接受 `size=100`，第一页与第二页均显示 100 个商品。
2. 翻页改变 URL 中的 `page`，页大小、业务筛选、排序等保持一致；更改每页数量或重新筛选会回到第一页。
3. **页面最多查看前 2000 条。** 查询显示总量 4830，不代表可以翻到第 49 页。跳转第 49 页和第 21 页均未发生页面切换；第 21 页测试明确出现“主人~ 只支持查看前2000条，建议输入过滤条件获取精准结果”。
4. 第 20 页显示 1901–2000，实际 100 个商品，不再显示可操作的下一页按钮。这是来源访问边界，不是自然短页。
5. 缩小筛选后，21 条数据按 20 条分页形成 20 + 1，合并后与一次取 100 条获得的 21 个 ASIN **顺序完全相同**，没有重复或遗漏。
6. 跳页输入框不是当前页状态：点击下一页、重新筛选后，它可能仍显示此前输入值。实现必须使用请求/响应分页信息，不能读取这个输入框判断当前页。

## 测试条件

基础条件：美国站、最近 30 天、关键词 `LOFT`、模糊匹配 `selectType=2`、展示所有变体、按月销量降序、增长率环比。

## 当前官方页面代码对照

通过当前页 DOM 确认加载了下列资源；对照内容为官方静态 JS，没有读取 Cookie、Token 或隐藏账号数据。

- [列表与请求逻辑](https://www.sellersprite.com/v3/webapp/static/js/chunk-2bd9164c.c6711696d05e.js)：分页组件传入 `maxTotal:2e3`；`handleCurrentChange(a)` 修改 `form.page` 后调用 `initData()`；`handleSizeChange(a)` 设置 `page=1,size=a`；结果总数从 `i.data.total` 读取。`initData()` 从同一 form 构造查询、生成 URL，并对 POST 的 `symbolFlag` 取反。
- [分页组件](https://www.sellersprite.com/v3/webapp/static/js/chunk-commons.cc139cf67922.js)：展示总数仍为真实 `total`，可分页总数 `showTotal` 则取 `maxTotal` 上限；超限跳页显示提示。`goPageNum` 是独立输入状态，不持续同步 `currentPage`。

因此应分别保存 `total_reported` 和 `access_limit`，不能把界面总数直接当可访问条数。

## 证据边界

- 本轮浏览器工具没有网络请求/响应捕获接口。以上是**真实网页交互、URL、DOM 行数和当前官方源代码**的交叉验证，不是重新抓取的 HTTP POST/response 原文。
- 先前真实 POST 的业务 body 见 `tests/fixtures/seller_sprite/product-research/page-request-20260928.json`；它证明请求字段形态，不能代替本轮各页响应证据。
- 尚未证明所有分页响应都会返回 `page/size/pages/hasNextPage`，不能把 manifest 中列出的字段全部设为必填。开发第一步须用授权的既有 worker 请求日志补齐脱敏响应样本，确定哪些字段实际存在。
- 没有尝试通过改请求、换账号或拆分条件绕过 2000 条限制。缩小品牌条件用于验证自然末页，不用于拼接超限结果。
- 没有对真实线上查询做超时、限流、断网、进程崩溃注入；这些应在本地 mock 与受控测试环境验证。
- 本轮未执行 20 页连续采集，也未测网站每次翻页扣额和服务器峰值内存。不能将边界抽样测试称为全量端到端或容量验收。
