# 卖家精灵广告洞察场景参数调研

> 调研日期：2026-07-30
>
> 候选场景标识：`ads-insights` / `competitor-ad-activity`（均未注册）
>
> 官方页面：<https://www.sellersprite.com/v3/ads-insights>
>
> 当前阶段：仅完成页面、接口和官方工作簿结构调研；未实现、未注册正式场景。

## 1. 结论

广告洞察用于查看竞品广告组、投放周期和关键词排名历史。主列表接口只返回广告组及周期摘要，不能单独生成官方工作簿；要取得关键词、翻译、广告排名、自然排名、ABA 排名和月搜索量，必须继续按“广告组 × 周期”请求关键词明细。

单次列表首页最多包含 50 个广告组，近 6 个月按周约有 26 个周期，理论上可形成约 `50 × 26 = 1,300` 个广告组周期组合。即使跳过关键词数为 0 的周期，仍可能产生数百次明细请求，并且明细超过 50 条时还需分页。该执行模型容易超过 SellerSprite 当前约 600 秒的任务总时限，并增加限流、验证码、登录态失效和部分结果的风险。

因此当前不将广告洞察注册为正式 SellerSprite 场景。后续需先确定数据范围、分页、并发、失败和部分结果契约，再评估实现。

## 2. 业务边界

广告洞察提供的是第三方观测到的竞品广告活动和关键词历史情报，不是 Amazon Ads 第一方广告效果数据。

可用于：

- 识别竞品投放过的关键词；
- 观察广告排名和自然排名的历史变化；
- 对比不同广告组和周期的关键词覆盖；
- 结合 ABA 排名、月搜索量评估关键词规模。

不能据此计算或替代：

- 真实曝光、点击、花费和订单；
- CTR、CPC、CVR、ACOS 和 ROAS；
- 广告账户预算、归因和投放效果事实。

## 3. 页面输入与主查询

页面输入包括：

- 站点；
- 周期；
- 单个父体或子体 ASIN，也可输入 Amazon 产品链接。

本次实测主查询：

```http
GET /v3/api/xds/stat
```

请求参数形状：

| 参数 | 样例 | 说明 |
| --- | --- | --- |
| `asin` | `B08FLKHG8J` | 单个查询 ASIN |
| `market` | `1` | 美国站内部编号 |
| `interval` | `week` | 按周聚合 |
| `months` | `6` | 查询近 6 个月 |
| `pageNum` | `1` | 广告组列表第一页 |
| `pageSize` | `50` | 本次页面请求每页 50 条 |
| `desc` | `false` | 页面请求排序方向 |
| `orderByEffectiveness` | `false` | 是否按有效性排序 |
| `combination` | `false` | 页面请求组合开关 |

脱敏响应形状：

```json
{
  "code": "OK",
  "data": {
    "adCount": 186,
    "pageNum": 1,
    "pageSize": 50,
    "campaignCount": 129,
    "maxKeywordsCount": 85,
    "groups": [
      {
        "adId": "<opaque-id>",
        "campaignId": "<opaque-id>",
        "asin": "B07H3QKN2Z",
        "type": "SPV",
        "totalCount": 569,
        "history": [
          {
            "beginDate": 1772294400000,
            "endDate": 1772899199999,
            "dateLabel": null,
            "keywordsCount": 59
          }
        ]
      }
    ]
  }
}
```

数据层级：

```text
主查询
  └─ groups[]（广告组）
      ├─ adId
      ├─ campaignId
      ├─ asin
      ├─ type
      └─ history[]（周期）
          ├─ beginDate
          ├─ endDate
          ├─ dateLabel
          └─ keywordsCount
```

页面历史观察曾显示 187 个投放小组，本次接口返回 `adCount=186`，官方文件则有 186 个业务工作表和 1 个 `Notes`。这些数字的口径尚未完全确认，不应直接视为同一个稳定计数。

## 4. 周期关键词明细

每个需要导出的有效周期还需请求：

```http
GET /v3/api/xds/stat/keyword
```

请求参数形状：

| 参数 | 说明 |
| --- | --- |
| `adId` | 主列表广告组标识 |
| `interval` | 本次为 `week` |
| `beginDate` | 周期开始时间戳 |
| `endDate` | 周期结束时间戳 |
| `pageSize` | 本次页面请求为 50 |
| `pageNum` | 请求从 1 开始 |
| `keyword` | 可选关键词筛选，本次为空 |
| `orderField` | 本次为 `updatedTime` |
| `desc` | 本次为 `true` |
| `market` | 站点内部编号 |

脱敏响应形状：

```json
{
  "code": "OK",
  "data": {
    "page": 0,
    "size": 50,
    "total": 59,
    "items": [
      {
        "asin": "B08JCD4PS6",
        "keyword": "art supplies for kids 9-12",
        "keywordCn": "9-12 岁儿童美术用品",
        "spRankHistory": [0, 117, 11, 0, 0, 0, 108],
        "rankHistory": [0, 38, 49, 45, 40, 56, 33],
        "searchesRank": 76625,
        "searches": 25822
      }
    ]
  }
}
```

分页注意事项：

- 请求使用 `pageNum=1`，响应内部页号为 `page=0`，实现前必须继续验证后续页换算；
- `total > size` 时需要继续分页才能得到该周期完整关键词；
- 可以根据主列表的 `keywordsCount=0` 跳过空周期，但不能据此取得非空周期的关键词内容；
- 明细响应还包含 PPC、竞价区间、趋势、点击、展示和 Top ASIN 等字段，但官方样例业务表仅使用其中六个字段。

### 5.1 工作表与表头

业务工作表名示例：

- `US-B08FLKHG8J-VLS4`
- `US-B08FLKHG8J-FXVM`
- `US-B08FLKHG8J-CNS_`

当前样本显示，工作表后缀为 `adId` 最后 4 个字符转大写。例如末尾为 `vLS4` 时，工作表后缀为 `VLS4`。该规则仍需更多样本验证。

每个业务工作表使用三层表头：

```text
Row 1: 日期 | 周期1（合并6列） | 周期2（合并6列） | ...
Row 2: ASIN | ASIN1（合并6列） | ASIN2（合并6列） | ...
Row 3: # | 关键词 | 关键词翻译 | 广告排名 | 自然排名 | ABA排名 | 月搜索量 | ...
Row 4+: 数据
```

每个周期固定六列：

1. 关键词；
2. 关键词翻译；
3. 广告排名；
4. 自然排名；
5. ABA 排名；
6. 月搜索量。

第 2 行的周期 ASIN 来自该周期关键词明细中的 `asin`，不保证等于查询 ASIN或主列表广告组顶层 ASIN。

### 5.2 接口字段映射

| 官方列 | 明细字段 | 备注 |
| --- | --- | --- |
| 关键词 | `keyword` | 原始关键词 |
| 关键词翻译 | `keywordCn` | 中文翻译 |
| 广告排名 | `spRankHistory` | 以文本数组写入 |
| 自然排名 | `rankHistory` | 以文本数组写入 |
| ABA 排名 | `searchesRank` | 整数显示 |
| 月搜索量 | `searches` | 整数显示 |

已验证样例：

```text
关键词       art supplies for kids 9-12
关键词翻译   9-12 岁儿童美术用品
广告排名     [0,117,11,0,0,0,108]
自然排名     [0,38,49,45,40,56,33]
ABA排名      76,625
月搜索量     25,822
```

排名历史中的 `0` 用于补齐周期内没有排名记录的日期，但其官方精确业务含义仍待确认。

### 5.3 格式画像

- 所有业务表冻结窗格为 `A4`；
- 无自动筛选、Excel Table、公式、图表、图片、条件格式和外部连接；
- `A` 列宽为 8；
- 每个周期六列列宽依次为 `22、22、22、22、10、10`；
- 字体为等线 10pt；
- 第 3 行使用白字、橙色 `#E98A00` 填充；
- 关键词和翻译左对齐，广告及自然排名居中，ABA 排名及月搜索量右对齐；
- 无边框。

第一个业务工作表有 614 行、481 列、80 个周期块和 160 个合并区域，说明该格式是动态多工作表、动态周期列块，不能直接复用当前固定列单表导出器。

## 6. 为什么主列表不能单独生成官方文件

主列表只提供：

- 广告组和活动标识；
- 广告组 ASIN 与类型；
- 周期起止时间；
- 每周期关键词数量。

官方工作簿业务行还需要：

- 关键词及翻译；
- 广告排名历史；
- 自然排名历史；
- ABA 排名；
- 月搜索量；
- 明细行中的周期 ASIN。

这些字段只能从周期关键词明细取得。因此，列表首页不是“官方文件第一页”的等价数据集，也不存在只请求一次主列表即可生成类似官方工作簿的安全映射。

## 7. 请求量与执行风险

按“主列表首页 + 所有周期完整明细”估算：

```text
1 次主列表请求
+ 首页广告组 × 有效周期的明细请求
+ 明细超过 50 条产生的额外分页请求
```

极端示例：

```text
50 个广告组 × 约 26 个周周期 = 约 1,300 个组合
```

实际数量可通过跳过 `keywordsCount=0` 降低，但仍可能达到数百次请求。主要风险：

- 超过当前约 600 秒任务总时限；
- 高频访问触发限流、验证码或临时封控；
- 长任务期间登录态过期或浏览器页面关闭；
- 任一广告组或周期失败导致文件缺块；
- 重试可能放大请求数量；
- 强并发可能缩短耗时，但会提高站点风控风险；
- 部分结果工作簿需要明确标识缺失范围，否则消费方可能误判为完整数据。

## 8. 后续可选获取方案

| 方案 | 获取范围 | 优点 | 主要缺点 |
| --- | --- | --- | --- |
| 最新有效周期完整明细 | 每个首页广告组只取最新一个非空周期，并完成明细分页 | 请求量最低，能保留完整关键词集合 | 缺少历史趋势，不能复刻官方多周期结构 |
| 最近若干有效周期完整明细 | 每个首页广告组取最近 N 个非空周期，并完成分页 | 可观察短期变化，请求量可配置 | N 越大耗时增长越快，仍需定义周期空洞 |
| 所有有效周期首屏 | 所有非空周期只取明细第一页 | 覆盖历史周期，执行量相对可控 | 关键词超过每页大小时数据不完整，完整性难解释 |
| 所有有效周期完整分页 | 首页广告组的全部非空周期和全部关键词 | 最接近官方业务工作簿 | 请求量和耗时最高，当前任务模型难以可靠完成 |

无论选择哪种方案，都还需确定：

- 明细安全并发度；
- `pageSize` 是否可提高；
- 单个明细失败是否跳过；
- 所有明细失败时是否令任务失败；
- 达到总时限时是否生成部分文件；
- 部分文件如何记录缺失广告组、周期和页码；
- 是否需要断点续跑及长任务专用调度模型。

## 9. 待确认事项

- 页面旧数量 187、接口 `adCount=186` 和官方 186 个业务工作表的精确关系；
- 接口类型 `SPV` 与页面所称广告类型的稳定映射；
- 官方文件为何可能包含多于当前页面选择范围的历史周期；
- 明细后续页的 `pageNum` 与响应 `page` 换算；
- 排名数组中 `0` 的官方精确定义；
- 周期标签由前端生成还是存在于其他接口；
- 更大 `pageSize`、低并发和限流条件下的稳定性。

## 10. 当前决策

- 不修改 SellerSprite 生产代码；
- 不注册 `ads-insights` 或 `competitor-ad-activity`；
- 不调用官方有限次数的导出能力；
- 不提交用户提供的官方样例文件；
- 将该能力在数据地图中标记为“待方案评估/暂缓实现”；
- 后续确认数据范围和长任务契约后，再重新进入实现评估。
