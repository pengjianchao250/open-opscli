# 跨境电商全链路数据能力地图

> **文档定位**：用于系统梳理跨境电商从趋势发现、选品、产品开发到运营优化的业务决策、数据需求、数据来源和建设优先级，并作为后续逐项盘点、补齐和验收的数据能力工作底稿。
>
> **当前基线**：卖家精灵已正式接入 7 个数据场景，Keepa 已正式接入 10 个数据场景；西柚找词与 SIF 已有项目底层实现，但主 CLI/MCP 入口及 quota 当前关闭；运营系统数据集导航页已确认 Amazon SP/SC、Ads 和 Brand Analytics 模块，`ops-dataset-query` 可作为内部销售、库存、广告、物流和流量的统一查询底座；Sorftime 仅完成静态能力调研。本文区分“数据集存在”“账号已授权”“代码已实现”“正式入口已暴露”“场景已验收”。
>
> **适用范围**：以 Amazon 为第一阶段主战场，同时兼顾 Walmart、eBay、TikTok Shop、Temu、AliExpress、Shopee、Lazada 和 Shopify 独立站等渠道。
>
> **版本**：v0.7（确认 Amazon SP/SC、Ads 与 Brand Analytics 内部数据版）
> **更新时间**：2026-07-21
> **维护方式**：业务、数据和技术团队共同维护，每完成一次能力盘点、数据接入或场景验收，更新本文档对应状态。

内部数据集能力证据：[运营系统数据集导航页](../../../../运营系统数据集-数据集导航页.csv)。

## 一、文档目标与使用方法

### 1.1 文档目标

本文档回答四个核心问题：

1. 跨境电商从选品到运营优化有哪些关键业务环节？
2. 每个环节需要哪些数据才能支撑高质量决策？
3. 卖家精灵和 Keepa 已经覆盖了什么，还有哪些能力需要盘点或补齐？
4. 应该按照什么优先级建设，才能最快形成可验证的业务闭环？

### 1.2 能力状态定义

后续维护时统一使用以下状态，避免“接入了数据”与“业务可用”混为一谈。

| 状态 | 含义 | 判定标准 |
|---|---|---|
| 已知已接入 | 已确认存在数据接口或采集能力 | 能稳定取得原始数据 |
| 代码已实现、入口关闭 | Provider/Client/任务/导出已存在，但主 CLI/MCP 或配额未开放 | 可静态验证代码和测试，当前 Agent/用户不能通过正式入口调用 |
| 待盘点 | 当前尚未确认覆盖程度 | 需要核对内部数据集、工具、授权和历史数据 |
| 计划中 | 已确认需要建设并进入排期 | 有负责人、数据源和目标时间 |
| 部分可用 | 已有数据，但完整性、稳定性或场景覆盖不足 | 可支持部分分析，尚不能形成稳定决策 |
| 场景可用 | 已形成业务分析或决策输出 | 有固定输入、规则、输出和使用人 |
| 已验收 | 已通过业务效果验证 | 有质量指标、使用记录和效果复盘 |
| 暂不建设 | 当前投入产出比不足 | 已记录原因和重新评估条件 |

### 1.3 建设闭环

数据能力的完成标准不是“接口调用成功”，而是形成完整闭环：

```text
业务问题
  → 明确决策与指标
  → 获取并治理数据
  → 生成诊断与建议
  → 执行运营动作
  → 观察结果变化
  → 复盘并优化规则
```

## 二、跨境电商全链路总览

```text
趋势与热点发现
      ↓
市场与类目选择 → 关键词需求 → 竞品与商品研究 → 选品立项
      ↓
消费者洞察 → 产品定义 → 供应商与成本 → 定价与合规 → 备货
      ↓
Listing 内容 → 新品冷启动 → 广告与营销 → 销售与转化优化
      ↓
库存与物流 → 售后与口碑 → 多平台扩张 → 产品组合与迭代
      ↑__________________________________________________|
```

### 2.1 全链路数据地图

| 编号 | 业务环节 | 核心决策 | 关键数据 | 主要产出 |
|---|---|---|---|---|
| S01 | 趋势与热点发现 | 哪些需求正在增长，是否来得及进入 | 搜索趋势、社媒话题、内容热度、节日事件、技术与政策变化 | 趋势机会池、热度生命周期、关联商品方向 |
| S02 | 市场与类目选择 | 市场是否足够大，竞争是否可接受 | 类目销量、销售额、增速、集中度、新品占比、季节性 | 类目吸引力评分、进入难度、目标市场 |
| S03 | 关键词需求研究 | 用户在搜什么，需求如何细分 | 搜索量、趋势、点击份额、购买份额、CPC、长尾词、关联词 | 需求主题树、关键词机会池、流量成本判断 |
| S04 | 竞品与商品研究 | 谁在卖、卖什么、为什么卖得好 | ASIN、销量、价格、BSR、变体、促销、内容、上架时间、库存 | 竞品矩阵、价格带、生命周期、差异化方向 |
| S05 | 评论与消费者洞察 | 用户为什么买、为什么不满意 | 评论、星级、Q&A、退货原因、客服记录、社媒讨论 | VOC 标签、痛点排序、购买动机、改进机会 |
| S06 | 选品评估与立项 | 这个产品是否值得做 | 市场、竞争、利润、趋势、风险、供应链能力 | 选品评分、GO/NO-GO、立项依据 |
| S07 | 产品定义与差异化 | 产品应该做成什么样 | 参数、材质、尺寸、场景、人群、评论痛点、竞品卖点 | 产品需求文档、规格建议、核心卖点 |
| S08 | 供应商与采购 | 谁来生产，成本、质量和交期是否可控 | 报价、MOQ、产能、交期、良率、质检、历史履约 | 供应商评分、目标采购价、生产计划 |
| S09 | 利润测算与定价 | 卖多少钱才能赚钱并具备竞争力 | 采购、包材、头程、关税、佣金、仓储、广告、退货、汇率 | 单品利润模型、盈亏平衡点、建议售价 |
| S10 | 合规与风险 | 是否可以合法、安全地销售 | 商标、专利、认证、危险品、受限词、平台政策、召回 | 合规清单、风险等级、上架前检查结果 |
| S11 | Listing 与内容 | 如何获得曝光并提高转化 | 标题、五点、A+、图片、视频、关键词覆盖、内容版本 | Listing 诊断、内容方案、关键词布局 |
| S12 | 新品冷启动 | 如何获得第一批流量、订单和评论 | 收录、自然排名、广告位、促销、流量来源、首批反馈 | 冷启动计划、预算节奏、排名目标 |
| S13 | 广告与站外营销 | 预算投到哪里，如何增量获客 | 曝光、点击、CPC、转化、ACOS、ROAS、新客、归因 | 投放诊断、搜索词优化、预算分配 |
| S14 | 销售与转化运营 | 销售变化由什么造成 | 流量、订单、销量、CVR、价格、促销、Buy Box、自然与广告占比 | 异常归因、经营日报、转化优化动作 |
| S15 | 库存、补货与物流 | 何时补货、补多少、走什么运输方式 | 在库、在途、库龄、预测、生产周期、物流时效、费用、丢损 | 补货计划、断货预警、滞销预警、物流方案 |
| S16 | 售后、退货与口碑 | 差评和退货的根因是什么 | 退货原因、退款、差评、客服对话、批次、质检、物流异常 | 根因分析、责任归属、产品和服务整改 |
| S17 | 多平台扩张 | 商品适合在哪些平台和国家销售 | 各平台商品、价格、销量代理、评价、流量、履约与费率 | 平台适配度、渠道机会、跨平台定价策略 |
| S18 | 产品组合与生命周期 | 哪些 SKU 应加码、维持、清仓或退出 | 收入、利润、增长、周转、广告依赖、退货、生命周期 | SKU 分层、资源分配、退出与迭代计划 |

### 2.2 卖家精灵 + Keepa 已实现能力覆盖矩阵

本节只统计当前正式实现：

- 卖家精灵 7 个场景：`competitor-lookup`、`product-research`、`keyword-miner`、`keyword-reverse`、`traffic-source`、`market-research`、`listing-analysis`。
- Keepa 10 个场景：`product`、`product-search`、`product-finder`、`category-search`、`category-lookup`、`seller`、`top-seller`、`bestsellers`、`deals`、`lightning-deals`。

证据来源：[卖家精灵数据能力与业务场景实测](./卖家精灵数据能力与业务场景实测.md)、[Keepa 数据能力与业务场景梳理](./Keepa数据能力与业务场景梳理.md)、[卖家精灵场景注册表](../../../opscli/seller_sprite/api/scenarios.py)、[Keepa 场景注册表](../../../opscli/keepa/api/scenarios.py)。

覆盖等级说明：

- **强**：主要外部市场决策数据已经有正式场景，可直接进入业务规则建设。

- **弱**：只有代理指标或外围信号，不能支撑核心决策闭环。
- **空白**：当前 17 个正式场景没有对应核心数据。

总体覆盖结论：

- **强覆盖 3 个**：S02 市场与类目、S03 关键词、S04 竞品商品。
- **中覆盖 4 个**：S06 选品立项、S09 定价、S11 Listing、S12 新品冷启动。
- **弱覆盖 9 个**：S01、S05、S07、S10、S13、S14、S15、S16、S18。
- **空白 2 个**：S08 供应商采购、S17 多平台扩张。

“强覆盖”仍只表示外部情报数据较完整，不表示业务场景已经验收。当前组合最适合解决选市场、找产品、查竞品、做关键词和验证商品历史；从广告执行到订单、库存、利润、售后和供应链，仍必须接入第一方及内部数据。

### 2.3 推荐卖家精灵补充场景

推荐按照“先组合现有能力，再补 Keepa 不具备的数据，最后扩展外围平台”的顺序推进。

#### A. 不新增卖家精灵接口即可建设的组合场景

这类场景复用现有 7 个卖家精灵场景，并按需用 Keepa 验证历史。

| 优先级 | 组合场景 | 卖家精灵组合 | Keepa 分工 | 主要输出 |
|---|---|---|---|---|
| P0 | 选品机会评分卡 | 选市场 + 选产品 + 关键词挖掘 + 选竞品 | 验证价格、BSR、Offer 和口碑历史 | 市场、需求、竞争、利润代理、物流难度和 GO/NO-GO 草案 |
| P0 | 竞品 360 情报 | 选竞品 + 关键词反查 + 流量来源 + Listing Analysis | 补价格、Buy Box、Offer、变体和促销历史 | 竞品规模、流量、内容、价格、供给竞争和可攻击弱点 |
| P0 | 关键词机会矩阵 | 关键词挖掘 + 关键词反查 + 流量来源 | 补关键词对应商品和头部商品历史 | 高需求低供给词、购买率、PPC、竞品强弱和用途分类 |
| P0 | `competitor-keyword-gap` 竞品关键词差距 | 对我的 ASIN 与 1—10 个竞品批量执行关键词反查，并补关键词需求指标 | 补关键词头部商品的价格、BSR 和历史表现 | 共有/独有/缺失词、流量份额差、自然/广告排名差和高价值追赶词 |
| P0 | `multi-asin-traffic-expansion` 多 ASIN 流量词扩展 | 对任意最多 20 个 ASIN 批量反查并合并词池，补关键词需求、竞争和 ABA 指标 | 验证相关商品的价格、BSR 和历史表现 | 关键词—ASIN 覆盖矩阵、共同/独有词、相关商品网络、高频词组和高份额机会词 |
| P0 | 新品 30/60/90 天验证 | 新品筛选 + 反查 + 流量来源 + Listing Analysis | 补 BSR、价格、Offer、Buy Box 和评论数历史 | 阶段表现、流量结构、关键词覆盖、内容和竞争变化 |
| P1 | 父子变体结构诊断 | 选产品/选竞品中的父子体、销量和价格 | 补父子关系、变体属性和历史 | 父体去重、主力/低效变体、价格梯度和新增变体机会 |
| P1 | 数据口径与可信度评分 | 卖家精灵页面/API/导出对照 | 与 Keepa 及第一方数据交叉校验 | 字段来源、估算/代理/事实标记、完整率和可信度 |

#### B. 推荐新增卖家精灵数据场景

以下优先补卖家精灵擅长且 Keepa 无法替代的数据，不建议重复建设 Keepa 已经较强的价格、BSR、Buy Box、Offer 和 Deal 历史。

| 优先级 | 推荐场景 | 建议接入的卖家精灵能力 | 解决的全链路缺口 | 与 Keepa 的关系 |
|---|---|---|---|---|
| P0 | `association-traffic` 关联流量 | 关联流量页面的免费/付费占比、关联类型、关联 ASIN、引流时间及关联商品表现 | S04、S12、S13 的商品关联图谱、竞品/互补品和可争夺广告位置 | 与现有 `traffic-source` 分工：后者看关键词/入口来源，本场景看 ASIN—ASIN 关系；Keepa 可补商品历史 |
| P0 | `competitor-ad-activity` 竞品广告活动洞察 | 广告洞察页面的广告活动、广告组、商品 ASIN、SP/SBV 类型及周/月时间序列 | S12、S13 的竞品投放周期、活动结构、主推变体和启停变化 | 当前是查询与历史洞察，不代表定时监控；不能替代 Amazon Ads 第一方曝光、点击、花费、订单、ACOS/ROAS |
| P0 | `aba-order-keyword-reverse` ABA 出单机会词反查 | 指定 ABA 周期的周搜索量、ABA 排名变化、点击/转化占比、集中度、点击前三 ASIN 和效果分类 | S03、S06、S11、S12、S13 的高意图词、增长词、垄断词和无效曝光词 | “出单”是 ABA 代理信号，不是自有订单或广告 Search Term；Keepa 不提供关键词点击/转化份额 |
| P0 | `product-change-monitoring` 产品变化监控 | 产品监控页面已确认按站点批量添加子 ASIN/商品链接，并有监控额度约束 | S04、S12、S18 的持续商品变化追踪 | 监控指标、频率、历史、告警和导出待接入验收；Keepa 商品历史可用于交叉验证 |
| P0 | `aba-market-opportunity` ABA 市场机会发现 | ABA 数据选品页面的六类市场模式、1/4/12 周排名变化、展示/点击、PPC、SPR、标题密度和 Top 3 ASIN/品牌份额 | S01、S02、S03、S06 的热门、异动、持续增长、快速飙升、潜力和长尾市场 | Keepa 用商品 BSR、价格和榜单历史验证关键词趋势是否传导到商品 |
| P1 | `external-trend-opportunity` 外部趋势补充 | Google Trends、社媒和事件趋势；接入前验证数据接口与授权 | S01 的站外热点、事件和趋势生命周期 | 卖家精灵 ABA 负责 Amazon 搜索行为，Keepa 验证商品表现，外部源补站外热度 |
| P1 | `traffic-deep-dive` 流量明细扩展 | 优先组合现有反查、挖词和 ABA 数据；专用 `traffic_extend` 仅作候选 | 在已有 `traffic-source` 之上补 S03、S04、S11、S12、S13 的多 ASIN 词池和商品—关键词关系 | 只有相关 ASIN、聚合份额、流量预估、高频词组或调用效率通过验收后才新增原子接口；Keepa 负责商品历史验证 |
| P1 | `keyword-demand` 关键词需求验证 | `keyword_research`、`keyword_research_trends`、`bsr_prediction` | S03 的单词深挖、趋势和销量区间 | Keepa 只能搜商品，不能替代搜索量和需求分析 |
| P1 | `keyword-conversion-economics` 关键词转化与投放经济性 | 关键词转化率页面的周搜索/点击/购买量、两种转化率、PPC/CPA 三档、价格区间、ACOS 三档、预算和 ABA 集中度 | S03、S06、S09、S12、S13 的词级意图、获客成本、价格承受力和测试预算 | 全部属于 ABA 或公式派生代理，必须验收公式；不能替代 Amazon Ads 真实 CPC、CPA、ACOS 和预算效果 |
| P1 | `asin-demand-forecast` ASIN 需求预测 | `asin_prediction`、`asin_sales_trend`，组合现有流量和关键词 | S04、S06、S12、S18 的销量估算与需求趋势 | 不重复接入 `keepa_info`；历史价格、BSR、Offer 继续由 Keepa 提供 |
| P2 | Listing 内容工作台 | Listing 生成器 + 关键词 + VOC + Listing Analysis | S11 从诊断进入内容草案和版本管理 | Keepa 提供历史验证，不负责内容生成 |
| P2 | TikTok 商品与达人验证 | TikTok 商品和达人入口，接入前先验证 API 与授权 | S01、S13、S17 的内容电商机会 | 属于卖家精灵外围能力，不与 Keepa 重合 |

当前页面实测后，关联流量、竞品广告活动洞察、ABA 出单机会词反查、产品变化监控和 ABA 市场机会发现都具备独立场景价值；关键词转化率也有新增价值，但应以 `keyword-conversion-economics` 的 P1 场景接入，先验收所有转化、CPA、ACOS 和预算公式。“拓展流量词”验证了 `multi-asin-traffic-expansion` 的组合场景价值：最多 20 个 ASIN 的合并词池、关键词—ASIN 关系和高频词组可补充 S03/S04/S11/S12/S13，但默认复用现有反查、挖词和 ABA 数据，只有专用接口保留不可复现字段或明显节省额度时才新增原子能力；其“内测版”流量占比和流量预估只能作为代理。`market-research`（选市场）已经正式实现；另一个浏览器插件“市场分析”因不便稳定获取而放弃，不再建设 `market-deep-dive`。关键词监控受前50范围限制，店铺上新监控额度受限，二者都不作为通用数据获取场景。实时查竞价只确认了六种“竞价策略 × 匹配方式”字段设计，历史示例详情为 0 条且日期无效，暂不计入正式场景。广告洞察只能判定竞品活动结构和投放时间，不能宣称获得曝光、点击、花费或转化；“出单词”只能作为 ABA 点击/转化代理信号，不能宣称获得真实订单搜索词。ABA 数据选品的新增价值是全市场趋势和集中度分析，但仍是外部行为代理。产品监控当前只确认批量添加对象和额度，具体监控指标必须在接入时验收。专利相关页面和全球商标库均按业务决定跳过，不纳入本轮卖家精灵新增场景；S10 的知识产权需求仍应由独立合规数据源或人工法律审查承担。`asin-demand-forecast` 有价值，但应只保留卖家精灵独有的销量估算和需求预测，避免再次包装 Keepa 的历史能力。

#### C. 不建议由卖家精灵单独承担的场景

| 场景 | 应接入的数据源 | 原因 |
|---|---|---|
| 第一方广告诊断 | Amazon Ads、Google/Meta/TikTok Ads | 卖家精灵只能提供 PPC 和竞品流量线索，没有真实花费、订单、ACOS 和 ROAS |
| 销售与转化经营 | SP-API、VC/SC、内部订单 | 第三方销量、购买率和排名不能代替 Sessions、Units、CVR 和归因 |
| 库存补货与物流 | ERP、WMS、FBA、货代和仓储系统 | 外部库存代理、尺寸和销量估算不能生成可执行补货计划 |
| 真实利润 | ERP、财务、结算、物流和广告 | 页面毛利率和价格只能作为早期代理，不能用于财务决策 |
| 供应商采购和质量 | SRM、ERP、质检和生产批次 | 卖家精灵没有报价、MOQ、产能、交期、良率和履约事实 |
| 退货售后根因 | 平台退货、客服、质检和物流 | 评论 VOC 只能说明外部反馈，不能定位内部责任链 |
| 多平台经营与站外归因 | 各平台官方接口、独立站和广告平台 | 商品入口或趋势信号不等于真实交易、履约和归因数据 |
| 完整合规审查 | 官方商标专利库、认证和法规系统 | 商标查询只能做初筛，不能给出法律和上架放行结论 |

推荐的数据源职责边界：

```text
卖家精灵：Amazon 市场需求、关键词、流量和竞争情报；浏览器插件评论仅供客户端/人工辅助，不进入服务端采集、入库或 VOC 分析
Keepa：价格、BSR、Buy Box、Offer、促销、榜单和商品历史验证
第一方/内部系统：订单、广告、利润、库存、物流、退货、采购和执行效果
其他外部平台：社媒趋势、多平台商品、站外营销和合规权威数据
```

## 三、各环节数据需求明细

### S01 趋势与热点发现

**业务问题**

- 哪些品类、功能、使用场景和消费人群正在升温？
- 热点是短期事件、周期性需求，还是长期结构性趋势？
- 热点是否已经传导到电商搜索、商品上新和销售表现？
- 从发现、开发到上架的时间是否赶得上机会窗口？

**所需数据**

| 数据主题 | 关键字段或指标 | 可选来源 | 建议频率 |
|---|---|---|---|
| 搜索趋势 | 关键词热度、地域、时间曲线、关联查询 | Google Trends、搜索引擎建议、平台搜索词 | 日/周 |
| 社媒趋势 | 提及量、互动量、增速、内容主题、创作者数量 | TikTok、YouTube、Instagram、Pinterest、Reddit | 日 |
| 事件日历 | 节日、赛事、影视、游戏、技术发布、政策事件 | 公共日历、行业媒体、新闻数据 | 日/周 |
| 创新品趋势 | 新项目数量、筹资、关注、功能创新 | Kickstarter、Indiegogo、行业展会 | 周 |
| 电商传导 | 平台搜索量、相关商品数、新品数、销量或排名变化 | 卖家精灵、Amazon 前台、其他平台商品数据 | 日/周 |

**分析产出**：趋势机会卡、增长拐点、预计窗口期、关联关键词、关联商品、目标国家和风险提示。

### S02 市场与类目选择

**业务问题**

- 类目容量和增速是否足够？
- 头部品牌或卖家是否高度垄断？
- 新品是否仍有进入和爬升机会？
- 价格带、评价门槛和广告成本是否与公司能力匹配？

**关键数据**

- 类目销售额、销量、搜索量及同比/环比增速。
- Top 10、Top 20、Top 100 商品的销售集中度和品牌集中度。
- 新上架商品占比、新品进入榜单速度、存活率。
- 主流价格带、评分分布、评论数门槛、促销密度。
- 季节性、地域差异、主要站点差异。
- CPC、自然排名难度、广告商品密度。

**分析产出**：市场规模、竞争强度、盈利空间、增长性、季节性和风险六维评分。

### S03 关键词需求研究

**业务问题**

- 用户用什么词表达需求？
- 关键词背后对应什么人群、场景、功能和痛点？
- 哪些词流量大但竞争高，哪些长尾词更适合切入？

**关键数据**

- 搜索量、搜索频率排名、趋势和季节性。
- 点击份额、购买份额、搜索结果数量和广告密度。
- CPC、CTR、CVR、自然排名和广告排名。
- 关联词、同义词、长尾词、竞品流量词。
- 关键词对应的主流产品形态、价格带和评价门槛。

**分析产出**：关键词聚类、需求主题树、机会词评分、核心词与长尾词组合、目标流量成本。

### S04 竞品与商品研究

**业务问题**

- 市场上的核心竞争者是谁？
- 竞品通过产品、价格、内容、广告还是评价获得优势？
- 竞品处于导入、增长、成熟还是衰退阶段？

**关键数据**

- ASIN/SPU/SKU、品牌、卖家、类目、上架时间、变体关系。
- 价格、优惠券、Deal、会员价、Buy Box、跟卖数量。
- BSR、销量估算、销售额估算、库存状态及历史变化。
- 标题、五点、A+、图片、视频、属性和内容变更。
- 星级、评论数、评论增速、Q&A 数量。
- 自然词、广告词、广告位和站外内容曝光。

**现有基础**：卖家精灵可支撑部分关键词、市场和竞品研究；Keepa 可支撑部分价格、排名、Offer 和历史趋势。具体字段、站点、频率与配额仍需单独盘点。

**分析产出**：竞品矩阵、竞争壁垒、价格策略、产品生命周期、内容差距和可攻击机会。

### S05 评论与消费者洞察

**业务问题**

- 用户购买产品的核心动机是什么？
- 用户在哪些场景下使用，期望完成什么任务？
- 哪些问题导致低星、退货或放弃购买？
- 不同国家、变体、时间和批次的问题是否不同？

**关键数据**

| 数据 | 需要保留的关键信息 |
|---|---|
| 评论 | 正文、标题、评分、时间、国家、变体、已验证购买、点赞、图片和视频 |
| Q&A | 问题、回答、时间、回答主体、主题分类 |
| 退货 | 原因码、用户描述、时间、SKU、批次、退款金额 |
| 客服 | 咨询主题、问题描述、处理方案、是否解决、情绪 |
| 社媒内容 | 场景、提及功能、正负反馈、互动、创作者和受众 |

**建议 VOC 标签体系**

```text
VOC
├─ 用户：新手 / 专业用户 / 家庭 / 商务 / 户外等
├─ 场景：购买前、安装、首次使用、长期使用、售后等
├─ 购买动机：功能、价格、外观、品牌、兼容性等
├─ 正向卖点：质量、易用性、性能、设计、服务等
├─ 负向问题：故障、尺寸、兼容、描述不符、物流等
├─ 严重程度：轻微不便 / 影响体验 / 无法使用 / 安全风险
├─ 根因归属：产品 / 包装 / 内容 / 物流 / 服务 / 用户误用
└─ 建议动作：改产品 / 改质检 / 改说明书 / 改 Listing / 改服务
```

**分析产出**：痛点排行榜、购买驱动因素、未满足需求、问题趋势、竞品对比和产品整改建议。

### S06 选品评估与立项

**业务问题**

- 综合市场、竞争、利润、供应链和风险后，产品是否值得立项？
- 结论依赖哪些事实，哪些部分仍属于假设？

**建议评估维度**

| 维度 | 示例指标 | 建议权重 | 数据状态 |
|---|---|---:|---|
| 市场空间 | 销售额、销量、搜索量、增速 | 20% | 待盘点 |
| 竞争难度 | 集中度、评论门槛、品牌壁垒、广告成本 | 20% | 待盘点 |
| 消费者机会 | 高频痛点、未满足需求、差异化空间 | 15% | 待盘点 |
| 盈利能力 | 毛利率、盈亏平衡 ACOS、资金占用 | 20% | 待盘点 |
| 供应链可行性 | MOQ、交期、良率、产能、模具投入 | 10% | 待盘点 |
| 趋势与周期 | 增长性、季节性、机会窗口 | 10% | 待盘点 |
| 合规与风险 | 专利、认证、危险品、政策 | 5% | 待盘点 |

> 权重仅作为初始模板，不同品类应由业务负责人调整并记录调整原因。

**分析产出**：选品评分卡、证据清单、关键假设、GO/NO-GO 结论和立项后验证计划。

### S07 产品定义与差异化

**所需数据**

- 竞品参数、功能、材质、尺寸、包装和配件。
- 评论与 Q&A 中的场景、痛点、购买动机和期望。
- 不同价格带对应的功能组合和内容表达。
- 供应商可实现规格、模具能力、质量水平和目标成本。
- 认证、专利、安全和运输限制。

**分析产出**：目标人群、核心场景、必须具备功能、差异化功能、目标成本、目标售价、验证指标和产品需求文档。

### S08 供应商与采购

**所需数据**

- 供应商基本信息、主营品类、合作记录和风险记录。
- 阶梯报价、MOQ、打样费、模具费、付款条件。
- 产能、排期、打样周期、生产周期和准时交付率。
- 检验标准、抽检结果、不良率、返工率和客诉关联。
- 原材料价格、包装成本和关键部件供应风险。

**分析产出**：供应商评分、成本拆解、质量风险、交付风险、备选供应商和采购建议。

### S09 利润测算与定价

**利润模型至少应包括**

```text
销售收入
- 折扣与促销
- 平台佣金
- 采购与包装成本
- 头程、关税和清关费用
- 平台仓储和尾程配送费用
- 广告与站外营销费用
- 退货、退款和售后成本
- 汇率损益、税费及其他费用
= 单品贡献利润
```

**核心指标**

- 单件贡献利润、贡献毛利率、净利率。
- 盈亏平衡售价、盈亏平衡 ACOS、最大可接受 CPC。
- 库存资金占用、回款周期和现金周转周期。
- 不同售价、广告费率、退货率和汇率下的敏感性。
- 竞品价格带、历史价格、促销频率和价格弹性。

**分析产出**：建议售价、促销底价、盈亏边界、广告约束和情景模拟。

### S10 合规与风险

**所需数据**

- 商标、外观专利、发明专利和版权。
- 目标国家产品认证、标签、包装和环保要求。
- 电池、液体、磁性、化学品等危险品与运输要求。
- 平台禁限售政策、敏感词、类目审核要求。
- 产品召回、安全事故、监管通报和竞品下架记录。
- 供应商检测报告、证书有效期和证书主体。

**分析产出**：风险等级、阻断项、整改项、所需认证、责任人和上架前放行结论。

### S11 Listing 与内容

**所需数据**

- 标题、五点、描述、A+、主图、辅图、视频、属性完整度。
- 核心词和长尾词覆盖、索引状态、自然排名和广告排名。
- 页面流量、CTR、CVR、跳失代理指标和设备差异。
- 竞品内容结构、卖点顺序、视觉表达和内容变更。
- 评论与 Q&A 中的购买障碍、误解和高频咨询。
- 每次内容修改的版本、时间和修改后效果。

**分析产出**：内容质量评分、关键词缺口、卖点结构、图片与视频脚本、A/B 测试方案和效果复盘。

### S12 新品冷启动

**所需数据**

- 上架日期、收录状态、核心关键词自然排名。
- 广告曝光、广告位、点击、CPC、搜索词和转化。
- Coupon、Deal、站外引流和促销效果。
- Sessions、CVR、订单、评论数量和评分变化。
- 同期竞品价格、促销、库存和广告动作。
- 每日库存、补货周期和可承受的推广节奏。

**分析产出**：30/60/90 天冷启动计划、分阶段目标、预算节奏、关键词爬升路径和止损条件。

### S13 广告与站外营销

**覆盖渠道**

- Amazon Ads：SP、SB、SBV、SD、DSP 等。
- 搜索广告：Google Ads、Microsoft Ads 等。
- 社媒广告：Meta、TikTok、Pinterest 等。
- KOL、联盟营销、Deal 站、EDM 和短信。

**核心数据**

- Campaign、Ad Group、Target、Search Term、Placement、Creative。
- 曝光、点击、CTR、CPC、花费、转化、销售额、CVR、ACOS、ROAS。
- 品牌词与非品牌词、新客与老客、广告订单与自然订单。
- 素材版本、受众、地域、设备、时段和频次。
- 站外点击到站内访问、加购和订单的归因链路。

**分析产出**：浪费识别、扩量机会、否定词建议、竞价建议、预算重分配、素材诊断和渠道增量评估。

### S14 销售与转化运营

**核心诊断漏斗**

```text
市场需求
  → 搜索与内容曝光
  → 商品点击
  → 页面访问
  → 加购
  → 下单
  → 支付
  → 签收
  → 留评与复购
```

**所需数据**

- Sessions、Page Views、订单量、销量、销售额和 CVR。
- 自然流量、广告流量、站外流量和品牌流量占比。
- 售价、Coupon、Deal、Buy Box 和配送承诺。
- 搜索排名、类目排名、竞品价格和促销变化。
- 新客、复购、取消、退款及订单地域分布。

**分析产出**：销量异动归因、漏斗流失点、价格与促销建议、自然/广告结构健康度和运营动作清单。

### S15 库存、补货与物流

**四段数据范围**

| 阶段 | 关键数据 |
|---|---|
| 生产 | 采购单、生产进度、交期、良率、可用产能 |
| 头程 | 运输方式、货代报价、航线、预计与实际时效、延误、清关 |
| 平台仓/海外仓 | 在库、在途、可售、预留、库龄、仓储费、调拨、丢损 |
| 尾程 | 配送时效、妥投率、配送异常、物流投诉、区域差异 |

**核心指标**

- 日均销量、预测销量、可售天数、在库加在途周转天数。
- 建议补货日期、建议补货量、断货概率。
- 90/180/270/365 天库龄和长期仓储风险。
- 单件头程、仓储、尾程成本及物流时效达成率。
- 预测偏差、到货偏差、丢损率和库存准确率。

**分析产出**：补货计划、运输方式建议、断货与滞销预警、仓间调拨建议和物流异常根因。

### S16 售后、退货与口碑

**所需数据**

- 退款、退货、取消、换货和补寄记录。
- 平台原因码、用户描述、客服工单、差评和 A-to-z 等投诉。
- SKU、变体、供应商、生产批次、质检结果和物流轨迹。
- 售后处理方案、处理时长、成本和用户是否满意。

**分析产出**：问题类型、严重程度、根因归属、批次聚集、供应商关联、整改动作和整改后验证。

### S17 多平台扩张

**平台范围**

- 成熟货架电商：Amazon、Walmart、eBay。
- 内容电商：TikTok Shop。
- 区域和价格驱动平台：Temu、AliExpress、Shopee、Lazada。
- 品牌独立站：Shopify/DTC。

**统一采集维度**

- 商品、类目、品牌、卖家、价格、促销和变体。
- 销量或销量代理指标、评论、评分和内容质量。
- 平台流量成本、佣金、履约模式、配送承诺和退货政策。
- 国家、语言、币种、税务、合规和消费偏好。
- 同款商品跨平台映射和渠道价差。

**分析产出**：平台适配度、国家机会、渠道利润、内容本地化要求、跨平台定价和库存策略。

### S18 产品组合与生命周期

**所需数据**

- SKU 收入、贡献利润、增长率、现金占用和库存周转。
- 广告依赖、自然流量、退货率、评分和质量问题。
- 市场增速、竞争变化、趋势阶段和新品替代关系。
- SKU、SPU、产品线、品牌、国家和平台间的关联。

**分析产出**

| 分层 | 典型特征 | 建议动作 |
|---|---|---|
| 明星产品 | 高增长、高利润、市场仍增长 | 加预算、扩渠道、扩变体 |
| 现金牛 | 增长稳定、利润和自然流量健康 | 稳定供货、控制成本、延长生命周期 |
| 潜力产品 | 市场有机会，但流量或转化存在短板 | 定向优化、设定验证周期 |
| 问题产品 | 退货高、广告依赖高或库存风险高 | 根因整改、限期改善 |
| 退出产品 | 市场衰退、长期亏损且无战略价值 | 清仓、停采、迁移流量和评价资产 |

## 四、数据能力分层

为了避免按照供应商建设数据孤岛，建议将数据能力分成六层。

### 4.1 市场与竞争数据

- 类目、关键词、竞品、价格、排名、Offer、促销和内容。
- 当前已知基础：卖家精灵、Keepa。
- 主要服务：趋势验证、选品、竞品研究、定价、Listing 优化。

### 4.2 消费者声音数据

- 评论、Q&A、退货原因、客服记录和社媒讨论。
- 主要服务：产品定义、内容优化、质量整改和产品迭代。

### 4.3 第一方经营数据

- 销售、流量、订单、广告、库存、退货、费用、利润和账号绩效。
- 主要服务：经营诊断、广告优化、库存补货和利润管理。

### 4.4 供应链与履约数据

- 供应商、采购、生产、质检、物流、仓储和尾程。
- 主要服务：可行性评估、成本核算、补货和风险预警。

### 4.5 站外趋势与营销数据

- 搜索趋势、社媒热点、内容、广告、KOL 和独立站行为。
- 主要服务：趋势发现、站外获客、品牌建设和渠道归因。

### 4.6 合规与风险数据

- 知识产权、认证、危险品、平台政策、监管与召回。
- 主要服务：选品拦截、上架放行和持续风险监控。

## 五、统一数据对象建议

后续数据建模应围绕业务对象，而不是围绕卖家精灵、Keepa 或某个平台分别建模。

| 业务对象 | 说明 | 关键标识 |
|---|---|---|
| 市场 Market | 国家、平台和目标消费市场 | 平台 + 国家/站点 |
| 类目 Category | 平台类目与公司品类体系 | 平台类目 ID、内部类目 ID |
| 需求主题 Demand Topic | 对关键词、场景和痛点的统一聚类 | 主题 ID |
| 关键词 Keyword | 搜索词及标准化词根 | 平台 + 站点 + 标准词 |
| 品牌 Brand | 自有与竞品品牌 | 标准品牌 ID |
| 产品 Product | 脱离平台的真实产品概念 | 内部产品 ID/SPU |
| 平台商品 Listing | 某产品在某平台的销售页面 | 平台 + 站点 + Listing ID/ASIN |
| SKU | 可销售或可库存的具体变体 | 内部 SKU、渠道 SKU |
| Offer | 卖家、价格、促销、配送和 Buy Box | Listing + Seller + 时间 |
| 内容 Content | 标题、卖点、图片、视频和版本 | Listing + 内容类型 + 版本 |
| VOC | 评论、Q&A、退货和客服声音 | 来源 + 原始记录 ID |
| 广告 Advertising | 活动、广告组、投放和搜索词 | 平台广告层级 ID |
| 订单 Order | 交易和售后事实 | 平台订单 ID |
| 库存 Inventory | 各位置各状态的库存快照 | SKU + 仓库 + 时间 |
| 物流 Shipment | 采购、头程、调拨和尾程过程 | Shipment ID/物流单号 |
| 供应商 Supplier | 生产、报价、质量和交付主体 | 供应商 ID |
| 财务 Finance | 收入、费用、结算和利润 | 交易/结算单据 ID |
| 趋势事件 Trend Event | 热点、节日、技术和政策事件 | 事件 ID |
| 合规风险 Compliance Risk | 产品、国家和平台相关风险 | 风险 ID + 关联对象 |

### 5.1 重点映射关系

```text
一个真实产品 Product
├─ 多个平台商品 Listing
│  ├─ 多个 SKU/变体
│  ├─ 多个 Offer/卖家
│  ├─ 多个内容版本
│  └─ 多条评论与 Q&A
├─ 多个关键词与需求主题
├─ 多个广告活动与搜索词
├─ 多个平台和仓库的库存
├─ 多个供应商与生产批次
└─ 多笔订单、退货、费用和利润
```

## 七、建议建设优先级

### 7.1 P0：先闭合 Amazon 经营循环

目标是从“看市场”升级为“发现问题、定位原因、执行动作、验证结果”。

1. 盘点并标准化卖家精灵、Keepa 已接入字段和能力边界。
2. 打通第一方销售、流量、订单、广告、库存、退货和费用。
3. 补齐评论、Q&A、退货原因和客服 VOC。
4. 统一 Product、SPU、SKU、ASIN、Listing、广告商品和库存商品映射。
5. 优先落地经营诊断、广告诊断、Listing 优化、VOC 洞察、补货和单品利润六个场景。

**P0 验收结果**

- 能解释销量变化来自市场、流量、转化、价格、广告、库存还是口碑。
- 能计算 SKU/ASIN 的真实贡献利润和盈亏边界。
- 能从评论、退货和客服中定位产品与内容问题。
- 能给出补货、广告和 Listing 优化建议，并追踪执行后效果。

### 7.2 P1：增强选品、产品开发和供应链能力

1. 接入 Google Trends、社媒热点和外部内容信号。
2. 用 Sorftime 小样本验证 Walmart、Shopee、Temu、TikTok 商品市场和 TikTok 内容趋势，避免先重复接入 Amazon 基础数据。
3. 验证 Sorftime 1688 货源线索，并与内部供应商、打样、质检和履约事实衔接。
4. 恢复西柚找词和 SIF 的受控测试入口，先验收项目现有 Provider、账号、导出和字段口径，再考虑新增接口。
5. 将西柚公开 OpenAPI 与现有 9 个 function 做差异分析，只补日/小时排名、竞品广告变化等独有字段。
6. 将 SIF 十个 XLSX 中的高价值字段进入统一模型，并与卖家精灵、Keepa、西柚和自有样本校准。
7. 打通供应商、采购、生产、质检、物流和售后批次关系。
8. 建立知识产权、认证和平台政策风险检查。
9. 落地趋势机会雷达、选品评分、产品定义和供应链可行性评估。

### 7.3 P2：构建多平台和全渠道增长能力

1. 接入 Google、Meta、TikTok 等站外广告。
2. 打通 Shopify/独立站、CRM、联盟营销和 KOL 数据。
3. 建设跨平台商品映射、价格监控、库存协同和本地化分析。
4. 建立跨渠道归因、新客识别和用户生命周期分析。

## 九、数据接入与质量标准

### 9.1 数据源评估维度

每个拟接入数据源都应回答以下问题：

| 评估维度 | 需要确认的内容 |
|---|---|
| 业务价值 | 支撑哪些决策，不能接入会损失什么 |
| 合规授权 | 官方 API、账号授权、许可数据、公开数据或其他合法方式 |
| 覆盖范围 | 平台、站点、国家、类目、时间范围、数据粒度 |
| 更新能力 | 实时、小时、日、周；全量与增量机制 |
| 历史深度 | 是否提供历史，最早时间和历史补采能力 |
| 准确性 | 官方值、估算值或代理指标；误差如何验证 |
| 稳定性 | 成功率、延迟、限流、配额和降级策略 |
| 成本 | 授权、订阅、调用、存储、维护和人工成本 |
| 可关联性 | 是否包含 ASIN、SKU、订单、广告等可用主键 |
| 可审计性 | 是否保留来源、采集时间、口径版本和原始记录 |

### 9.2 最低数据质量要求

| 质量维度 | 定义 | 建议监控指标 |
|---|---|---|
| 完整性 | 必填字段和应有记录是否缺失 | 字段非空率、日期缺口率 |
| 准确性 | 数据与权威源或抽样事实是否一致 | 抽样一致率、金额差异率 |
| 及时性 | 数据是否在业务可接受时间内到达 | 延迟 P50/P95、超时率 |
| 唯一性 | 是否存在重复对象和记录 | 主键重复率 |
| 一致性 | 同一指标跨系统口径是否一致 | 对账差异、口径冲突数 |
| 可追溯性 | 是否能定位来源、时间和处理过程 | 血缘覆盖率、原始记录保留率 |
| 稳定性 | 接入任务是否持续可靠 | 成功率、连续失败次数、恢复时长 |

### 9.3 官方值、估算值与推断值必须区分

| 数据类型 | 示例 | 使用要求 |
|---|---|---|
| 官方事实 | 自有订单、广告花费、FBA 库存 | 可直接用于财务和经营核算，但仍需统一口径 |
| 第三方估算 | 竞品销量、搜索量、类目销售额 | 展示来源和误差，不应伪装成官方精确值 |
| 代理指标 | BSR、评论增速、最大可购数量 | 说明其与目标指标的关系和失效条件 |
| 模型推断 | 情感、主题、根因、销量预测 | 保存模型版本、置信度并支持人工抽检 |
