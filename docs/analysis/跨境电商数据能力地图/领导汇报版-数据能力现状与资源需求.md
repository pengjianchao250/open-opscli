# 跨境电商数据能力现状与资源需求（领导汇报版）

> **更新时间**：2026-07-30
> **汇报结论**：当前外部选品情报和内部 Amazon 经营数据均已有较好基础。公司数据集已覆盖 Amazon SP/SC、Ads 和 Brand Analytics；下一步重点不是重复采购 Amazon 广告或经营报表工具，而是把现有内部数据与卖家精灵、Keepa 打通，并补齐评论 VOC、多平台外部趋势和供应链线索。

## 一、现状与所需支持

| 数据领域 | 当前现状 | 已有数据来源 | 主要缺口 | 需要的支持 | 优先级 |
|---|---|---|---|---|---|
| 市场与选品 | **基本覆盖** | 卖家精灵已接入场景；Keepa 10 个场景 | 缺统一评分、跨源校验和持续复盘 | 保持现有卖家精灵、Keepa 账号与额度；暂不重复采购同类 Amazon 基础数据工具 | P0 |
| 关键词、流量与竞品广告情报 | **部分覆盖** | 卖家精灵；西柚找词、SIF 项目已有底层实现 | 西柚/SIF 主 CLI、MCP 入口关闭；部分能力未形成正式场景 | 确认并购买/续费西柚、SIF 所需账号或 API 权限，恢复正式入口 | P0 |
| Amazon SP/SC 经营分析 | **模块已确认** | 即时综合/销售、发货、区域、SC 流量转化、活动、FBA 退货退款、店铺绩效和 ASIN 运营事件等内部数据集 | 尚未统一接入选品与运营诊断场景；字段和账号权限需执行验收 | 指定内部数据 Owner，授权分析服务账号并统一 SKU、ASIN、店铺、站点和日期口径；无需外购同类数据 | P0 |
| Amazon Ads 经营分析 | **强覆盖，模块已确认** | 19 个广告数据集：广告费、SP/SD/SB/SBV、关键词、搜索词、投放词、广告位及预算；支持小时级、两小时级和日级更新 | 尚未形成统一广告诊断、预算优化和结果追踪场景 | 开放内部 Ads 数据集权限，复用 `ops-dataset-query` 建设广告诊断；不采购重复广告报表工具 | P0 |
| Amazon Brand Analytics | **模块已确认** | 亚马逊目录绩效、亚马逊搜索词绩效，周粒度覆盖国家、平台、ASIN、搜索词和报告周期 | 尚未与卖家精灵关键词、Keepa 商品历史和 Ads 搜索词联合分析 | 开放 Brand Analytics 数据集权限，建设“搜索需求—商品—广告—转化”联合分析 | P0 |
| 公司商品多平台信息 | **已有跨平台经营数据，商品主数据待统一** | 部门、渠道、渠道 SKU 维度经营数据；TikTok 流量转化；Walmart、TikTok、Temu、Shein、Shopify、Wayfair 等退货退款数据 | CSV 未证明完整商品目录、Listing 状态和平台商品 ID 已统一 | 指定数据 Owner，盘点商品主数据并统一 SKU、ASIN、店铺、站点和平台商品 ID | P0 |
| 销售、库存、物流与经营结果 | **内部可补，尚未形成统一闭环** | `ops-dataset-query` 支持销售、库存、物流、流量等运营数据；ERP/OMS/WMS/TMS | 外部市场信号与真实订单、库存、在途、物流时效未统一关联 | 协调业务系统权限与口径；建设统一商品主数据和日粒度经营宽表 | P0 |
| 评论与消费者 VOC | **明显缺口** | Amazon Customer Feedback 聚合主题；客服、退货数据；合规第三方候选 | 缺稳定评论正文、Q&A、退货原因和客服主题融合 | 协调平台授权、客服与退货数据；如需正文，先评估并购买合规第三方接口 | P0 |
| 多平台趋势与热点 | **覆盖较弱** | Google Trends、平台官方趋势；Sorftime 候选 | TikTok 内容、达人、视频，以及 Shopee/Walmart/Temu 跨平台趋势不足 | 先购买 Sorftime 试用/低配账号做样本验收，通过后再决定正式采购 | P1 |
| 供应链与货源 | **线索不足** | 内部采购系统；Sorftime 1688 货源候选 | 供应商、价格阶梯、MOQ、交期、质检和履约未打通 | 先用 Sorftime 试用账号验证 1688 线索；同时协调 SRM/采购数据 | P1 |
| 利润与决策闭环 | **尚未统一** | 财务、结算、采购、物流和广告内部数据 | 缺单品真实利润、预算边界和选品后复盘 | 财务、供应链、广告共同确认成本口径和数据权限 | P0 |

## 二、账号与资源采购建议

| 平台/资源 | 当前判断 | 建议动作 | 采购目的 |
|---|---|---|---|
| 卖家精灵 | 已采购、已接入 | 保持续费与必要额度 | Amazon 市场、选品、关键词、竞品和流量情报 |
| Keepa | 已采购、已接入 | 保持续费与必要额度 | 价格、BSR、Buy Box、Offer、促销和商品历史验证 |
| 西柚找词 | 项目已有实现、入口关闭 | 确认账号/API 套餐并恢复入口 | 多 ASIN 反查、关键词分析、历史流量、广告/自然放映机 |
| SIF | 项目已有实现、入口关闭 | 确认账号/API 套餐并恢复入口 | 变体销量结构、流量词与自然位、多产品对比 |
| Sorftime | 仅完成调研 | **先买试用或最低套餐** | 验证 TikTok、多平台市场、1688 货源三类独有增量 |
| 评论数据服务 | 尚未确定 | 合规评审通过后再采购 | 评论正文、媒体、变体和 VOC；不使用卖家精灵浏览器插件作为服务端数据源 |
| Amazon/各平台官方权限 | 属于内部授权，不是第三方采购 | 协调开通 SP-API、Ads、Brand Analytics、店铺及报表权限 | 获取自有商品、销售、流量和广告第一方事实 |
| 公司内部数据平台权限 | Amazon SP/SC、Ads、Brand Analytics 模块已确认 | 给运营分析服务账号开放必要数据集，并完成字段验收 | 复用广告、销售、流量、活动、退货、库存、物流及跨平台经营数据 |

## 三、建议管理层本阶段拍板事项

1. 确认西柚找词、SIF 的账号/API 套餐与恢复接入预算。
2. 批准 Sorftime 试用账号，只验收 TikTok、多平台市场和 1688，不重复验收 Amazon 基础商品数据。
3. 指定内部数据 Owner，将 Amazon SP/SC、Ads、Brand Analytics 数据集接入统一分析，并完成服务账号授权。
4. 明确评论数据的合规边界；卖家精灵浏览器插件只用于客户端/人工辅助，不进入服务端。
5. 要求各数据源统一 SKU、ASIN、店铺、站点、平台商品 ID 和日期口径，形成跨源经营宽表。

## 四、口径说明

- `ops-dataset-query` 的正式能力说明覆盖销售、库存、广告、物流和流量，并支持趋势、环比同比、ACOS/ROAS 与导出。
- [运营系统数据集导航页](../../../../运营系统数据集-数据集导航页.csv)已确认 Amazon SP/SC、Ads 和 Brand Analytics 模块存在。Ads 包含 19 个数据集；Brand Analytics 包含目录绩效和搜索词绩效。
- 导航页证明“模块和数据集存在”，但不等于当前服务账号已经拥有全部字段权限，也不等于场景已完成验收；执行接入时仍需用 `ops-dataset-query` 元数据逐项确认。
- 详细依据见[跨境电商全链路数据能力地图](./跨境电商全链路数据能力地图.md)和[电商运营数据需求与平台来源地图](./电商运营数据需求与平台来源地图.md)。
