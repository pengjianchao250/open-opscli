### 2.5 可优先补充的业务场景

#### 场景 A：竞品池自动构建

**输入**：站点、时间、类目、关键词、品牌、卖家或 ASIN。
**处理**：按销量、销售额、BSR、上架时间、价格、评分数和变体数进行筛选与分层。
**输出**：核心竞品、成长竞品、新品竞品、价格竞品和内容标杆。

#### 场景 B：高增长新品发现

**输入**：上架时间、父体销量、增长率、月新增评分、BSR 和销售额。
**处理**：识别上架时间短、销量增长快、评论门槛相对低的产品。
**输出**：新品机会榜、增长原因待验证项和跟踪清单。

#### 场景 C：高需求低口碑门槛机会

**输入**：销量、销售额、评分数、月新增评分、评分和 Q&A。
**处理**：识别需求较高但评论壁垒较低、用户疑问较多或评分存在改善空间的商品。
**输出**：潜在差异化机会和后续 VOC 分析对象。

#### 场景 D：竞品利润与物流初筛

**输入**：价格、FBA 费用、毛利率、商品和包装重量尺寸、配送方式。
**处理**：排除低毛利、超大件、履约成本过高或价格空间不足的商品。
**输出**：利润初筛结果和需要进入精细成本模型的候选商品。

> 页面毛利率只能作为初筛指标，不能替代包含采购、头程、关税、广告、仓储、退货、税费和汇率的内部真实利润模型。

#### 场景 E：Listing 内容竞争力对标

**输入**：A+、视频、LQS、评分、Q&A、销量和销售额。
**处理**：比较内容完整度与市场表现，识别高销量内容标杆和内容不足但仍有销量的商品。
**输出**：Listing 对标清单、内容补齐建议和 A/B 测试对象。

#### 场景 F：选品到供应链与合规联动

**输入**：候选商品、类目、商品图片、专利入口、1688/Alibaba 和 TikTok 达人入口。
**处理**：将市场机会继续传递到专利初筛、货源发现和站外内容验证。
**输出**：选品候选的供应链线索、合规待办和站外热度验证任务。

### 2.6 数据使用限制与风险

| 风险 | 当前观察 | 后续处理 |
|---|---|---|
| 估算值风险 | 竞品销量和销售额并非卖家第一方交易事实 | 明确标记为第三方估算，抽样与内部或其他来源交叉验证 |
| 精度不一致 | 页面同时存在精确值、`100K+` 和空值 | 确认 API/MCP 返回的是原始值还是页面展示值 |
| 字段缺失 | 部分商品父体趋势、FBA、毛利率、包装信息为空 | 建立字段完整率监控和缺失原因分类 |
| 口径不清 | 父体销量、子体销量、最近 30 天和自然月可能存在口径差异 | 获取卖家精灵字段说明并建立指标字典 |
| 类目混杂 | 当前全类目结果不适合比较商品机会 | 后续按细分类目、关键词和价格带分组分析 |
| 时间延迟 | 页面提示当月月销量通常在下月月初上线 | 盘点不同数据字段的更新频率和可用月份 |
| 外部跳转依赖 | 专利、TikTok、1688、Alibaba 等入口未完成数据闭环验证 | 分别确认是否可通过 API/MCP 获取结构化结果 |

### 2.8 初步结论

卖家精灵“查竞品”并不只是竞品销量查询工具。页面已经把市场表现、口碑门槛、内容质量、履约成本、利润代理指标、合规初筛和供应链线索连接在同一商品对象上，可以优先作为以下数据场景的入口：

1. 竞品池和成长商品发现。
2. 选品市场验证和口碑门槛判断。
3. Listing 内容竞争力对标。
4. 利润及物流的早期粗筛。
5. 从 Amazon 商品向专利、TikTok 达人和供应链线索延伸。

当前最大的待确认项不是“页面是否有数据”，而是这些字段在卖家精灵 API/MCP 中的开放范围、返回精度、查询配额、更新频率以及与现有 opscli 能力的重合程度。

|---|---|

### 3.2 与“查竞品”的核心区别

| 对比项 | 查竞品 | 选产品 |
|---|---|---|
| 主要入口 | 已知关键词、品牌、卖家、ASIN 或类目 | Amazon 全站商品池和类目商品池 |
| 核心目标 | 查询已知竞争对象和市场表现 | 通过多维条件主动发现机会产品 |
| 筛选方式 | 基础查询条件为主 | 销售、商品、竞争、物流和内容条件组合 |
| 策略复用 | 查询历史 | 推荐模式、自定义模式、保存当前模式 |
| 典型输出 | 竞品池、竞品表现 | 候选产品池、选品榜单、机会分层 |

两者结果表字段高度接近，平台接入时可以共享商品结果模型；差异主要应保留在查询策略、过滤条件和场景语义上。

### 3.3 页面推荐选品模式

页面已经将常见选品经验封装成推荐模式：

| 模式分组 | 页面实际模式 | 可支持的决策方向 |
|---|---|---|
| 长尾与低价 | 低价长尾选品、低价商品 | 低客单、长尾需求和低价资格商品发现 |
| 新品与增长 | 研发新品榜、销量飙升榜 | 新品开发和增长商品跟踪 |
| 结构机会 | 潜力单变体、未被满足的市场 | 寻找变体结构简单或供给不足的机会 |
| 市场机会 | 潜力市场、高需求低要求市场、投机市场 | 需求、竞争门槛和短期窗口筛选 |
| 库存策略 | 不压库存的市场 | 低资金占用、轻小件或较低库存风险筛选 |
| 经营模式 | 全品类铺货、精品铺货、新手推荐 | 匹配不同团队和经营策略 |
| 榜单 | BSR1000 榜单 | 头部商品扫描；本次页面显示为不可用状态 |

页面还支持“我的模式”“保存当前模式”和模式管理，适合将团队选品规则固化为可重复执行的筛选模板。

### 3.4 可组合的筛选字段

#### 3.4.1 销售表现

- 月销量、月销售额、子体销量。
- 月销量环比增长率。
- BSR、小类 BSR。
- BSR 增长数、BSR 增长率。

#### 3.4.2 产品与口碑

- 变体数、价格、Q&A。
- 评分数、月评新增、评分值、留评率。
- 上架时间、LQS。
- 主图是否有视频。
- Best Seller、Amazon's Choice、New Release、A+ 和不含 A+。

#### 3.4.3 成本、物流与商品资格

- FBA 运费、页面毛利率。
- 包装重量、包装尺寸、买家运费。
- AMZ、FBA、FBM 配送方式。
- 低价商品资格。

#### 3.4.4 竞争结构

- 卖家数量、卖家所属地。
- 包含或排除品牌。
- 包含或排除卖家。

### 3.7 本次实测发现的数据口径风险

#### 3.7.1 同一父体重复占榜

在“展示所有变体”开启时，前三条结果均来自同一父 ASIN。若直接取 Top N，会把一个父体的多个子体误当成多个独立机会。

**建议处理**：

- 选品榜默认按父 ASIN 去重，每个父体保留代表子体。
- 另建父子变体分析，专门评估变体结构和子体贡献。
- 明确“按父体选品”与“按可售子体选品”两个不同场景。

#### 3.7.2 页面销售额可能是派生估算值

三个子体显示完全相同的父体销量 `734,197`，但页面销售额分别为 `$9,537,219`、`$11,005,613` 和 `$16,879,188`。这些数值分别接近父体销量乘以各自子体价格。

**初步推断**：页面“销售额”可能采用“父体销量 × 当前子体价格”计算，而不是父体各子体真实成交额加总。该推断必须通过卖家精灵字段说明、导出数据或 API/MCP 返回值验证。

**使用限制**：在口径确认前，不应直接使用该字段计算市场容量、品牌份额或父体真实收入。

#### 3.7.3 页面毛利率不是内部真实毛利率

页面筛选仅能看到价格、FBA 运费等有限成本信息，无法确认是否包含采购、头程、关税、广告、退货、仓储、税费和汇率。

**建议处理**：卖家精灵毛利率只用于早期粗筛；进入立项候选池后，必须使用内部成本模型重新计算。

### 3.8 可优先落地的场景

| 场景 | 关键输入 | 主要处理 | 输出 |
|---|---|---|---|
| 规则化选品池 | 推荐模式或自定义筛选条件 | 定时执行、去重、评分和分层 | 候选产品池 |
| 高增长新品雷达 | 上架时间、销量增长、BSR、月评新增 | 识别近期快速爬升产品 | 新品机会榜 |
| 单变体机会发现 | 变体数、销量、评分和价格 | 找出高销量、低复杂度产品 | 单变体候选池 |
| 低库存风险筛选 | 包装重量尺寸、价格、销量、配送 | 排除大件和高资金占用商品 | 轻量化候选池 |
| 低内容门槛机会 | LQS、A+、视频、销量和评分 | 识别内容不强但需求已被验证的产品 | 内容差异化机会 |
| 供给竞争过滤 | 卖家数、卖家所在地、配送方式、品牌 | 排除强垄断、自营或跟卖拥挤市场 | 可进入商品池 |

### 3.10 初步结论

“选产品”是卖家精灵最适合承载规则化选品的入口。其核心价值不是结果字段比“查竞品”更多，而是提供了多维筛选、推荐模式和自定义模式，可以把运营选品经验转化为可重复运行的规则。

落地时应优先解决父 ASIN 去重、销售额口径和毛利率口径问题。否则即使筛选规则丰富，也可能因为同父体重复和派生估算值导致市场容量、产品排名和利润判断失真。

### 4.4 对跨境电商全链路的覆盖程度

覆盖等级定义：

- **强**：已有正式场景和较完整数据，可直接进入业务规则建设。
- **中**：已有部分数据，但缺少关键维度、组合分析或效果验证。
- **弱**：只能提供少量代理字段或外围线索。
- **空白**：当前卖家精灵正式场景未覆盖。

| 跨境业务环节 | 覆盖等级 | 当前覆盖场景 | 主要缺口 |
|---|:---:|---|---|
| 趋势与热点发现 | 弱 | 关键词挖掘中的搜索需求、购买和月份数据 | 缺少 Google、TikTok、社媒和事件趋势，缺少趋势生命周期判断 |
| 市场与类目选择 | 强 | 选市场、选产品 | 需要统一市场评分、口径校验和跨站点对比 |
| 关键词需求研究 | 强 | 关键词挖掘、关键词反查、查流量来源 | 缺少关键词聚类、意图分类和与内部转化利润的联动 |

| 选品评估与立项 | 中 | 选产品、选市场、关键词挖掘 | 有原始数据和筛选，但缺少统一评分、GO/NO-GO 与假设验证 |

#### 4.5.1 “关联流量”页面本轮实测结论

当前页面已确认提供以下数据：

- 可同时输入最多 20 个 ASIN，输出关联商品池和各输入 ASIN 的关联数量。
- 区分免费关联与付费关联，并给出数量和占比。
- 关联类型包括看了又看、相似产品、看了还看、看了却买、捆绑销售、组合购买、更多相关、买了又买、品牌推荐、商品广告、四星产品和品牌广告。
- 结果包含关联 ASIN、关联 ASIN 数、引流时间，并附带关联商品的 BSR、父/子体销量和销售额、价格、评分数、留评率、月新增、配送、运费和上架时间等商品指标。

它与现有 `traffic-source` 的职责不同：

| 场景 | 核心问题 | 主要对象 | 主要输出 |
|---|---|---|---|

| 一组商品共同覆盖哪些需求 | 最多 20 个 ASIN 的合并词池和相关 ASIN 数 | 共同词、独有词、覆盖率和关键词—ASIN 矩阵 |
| 哪些词连接了最多相关商品 | 相关 ASIN 列表/数量、流量占比和流量预估 | 相关商品网络、核心流量枢纽词和商品簇 |
| 多个商品的核心语义组件是什么 | 一词、两词和 N 词高频统计 | 高频词根、功能/场景/人群组件和长尾组合方向 |
| 哪些扩展词更值得进入 Listing 或广告测试 | 搜索、购买、购买率、竞争、PPC 和集中度 | 高份额低竞争词、高意图词和测试优先级 |

它与已有场景的分工是：

| 场景 | 核心输入与输出 |
|---|---|
| `keyword-reverse` | 单个 ASIN 的关键词、排名和流量结构 |
| `competitor-keyword-gap` | 我的 ASIN 与 1—10 个竞品的横向差距、缺失词和强弱比较 |
| 建议新增 `multi-asin-traffic-expansion` | 任意最多 20 个 ASIN 的合并词池、关键词—ASIN 关系、高频词组和商品关联网络 |

底层搜索、购买、竞争和 PPC 指标与现有 `keyword-reverse`、`keyword-miner` 和 ABA 场景高度重合，因此默认先通过批量反查和关键词指标组合落地，不直接新增原子数据能力。只有专用 `traffic_extend` 接口能够稳定保留相关 ASIN 列表/数量、聚合流量占比、流量预估和高频词组，或显著降低调用次数与额度消耗时，才值得独立接入。

边界必须保留：页面将流量占比标注为“内测版”，流量数量也是预估值，只能用于相对排序、词池筛选和竞品比较，不能当作 Amazon 官方精确流量或自有广告曝光、点击和订单数据。

评论分析不进入上述服务端接入顺序。卖家精灵浏览器插件留在客户端/人工辅助侧，其评论数据不进入服务端采集、入库、调度、建模或报告/VOC 分析；服务端如需评论能力，应另接平台授权数据、内部客服/退货数据、用户提供的授权数据或合规第三方接口。

### 4.6 不新增卖家精灵接口即可先落地的组合场景

这些场景可以复用现有七个场景，主要工作是统一对象、口径和分析规则。

#### P0-1 选品机会评分卡

**组合数据**：选市场 + 选产品 + 关键词挖掘 + 选竞品。
**输出**：市场空间、增长、竞争、口碑门槛、利润代理和物流难度评分，以及 GO/NO-GO 建议。
**必须修正**：按父 ASIN 去重；第三方估算值和内部事实分开；页面毛利率只作为代理指标。

#### P0-2 竞品 360 度情报

**组合数据**：选竞品 + 关键词反查 + 查流量来源 + Listing Analysis。
**输出**：竞品规模、价格、口碑、自然与广告流量、核心词、内容质量和可攻击弱点。
**适用人群**：产品开发、Listing 运营和广告运营。

#### P0-3 关键词机会矩阵

**组合数据**：关键词挖掘 + 关键词反查 + 查流量来源。
**输出**：高需求低供给词、高购买率词、低竞价词、竞品强我方弱的词，以及关键词用途分类。
**建议分类**：核心类目词、功能词、场景词、人群词、痛点词、竞品词和品牌词。

#### P0-3A 竞品关键词差距分析

**组合数据**：对我的 ASIN 与 1—10 个竞品批量执行关键词反查，并用关键词挖掘补充搜索、购买、竞争和需供指标。
**输出**：共有词、我方独有词、竞品独有词、我方缺失词，以及按流量占比、曝光、自然/广告排名和转化代理排序的机会清单。
**实现建议**：优先复用现有场景组合；专用“流量词对比”接口只有在额度、效率或分类字段更优时再接入。

#### P0-3B 多 ASIN 流量词扩展

**组合数据**：对任意最多 20 个 ASIN 批量执行关键词反查，合并去重后补充关键词需求、购买、竞争、PPC 和 ABA 集中度指标。
**输出**：合并词池、关键词—ASIN 覆盖矩阵、共同/独有词、相关商品网络、高频词根/词组，以及高份额低竞争机会词。
**实现建议**：默认复用现有场景；只有专用“拓展流量词”接口能稳定提供不可复现的相关 ASIN、聚合份额、流量预估或词频字段，或明显节省调用额度时再接入。

#### P0-4 新品 30/60/90 天验证

**组合数据**：选产品的新品与增长条件 + 关键词反查 + 流量来源 + Listing Analysis。
**输出**：上架后销量、排名、关键词覆盖、自然/广告结构和内容变化的阶段性验证结果。
**当前限制**：没有持续监控接口时只能按计划重复查询，效率和时效有限。

#### P0-5 父子变体结构诊断

**组合数据**：选产品或选竞品中的父/子 ASIN、父/子体销量、价格、变体数和评分。
**输出**：父体去重榜、主力变体、低效变体、价格梯度和新增变体机会。
**业务价值**：避免同一父体重复占榜，提升选品和竞品排名的真实性。

#### P0-6 数据口径校验与可信度评分

**组合数据**：页面结果、官方导出、API/MCP 结果，以及 Keepa 或内部自有商品数据。
**输出**：字段来源、精确值/区间值/估算值标记、完整率、更新延迟和可信度。
**业务价值**：避免将父体估算销售额、页面毛利率等代理指标直接用于立项。

### 4.8 卖家精灵无法单独补齐的数据

卖家精灵应定位为“外部市场与竞争情报源”，不能替代跨境运营的全部数据底座。

| 运营数据 | 卖家精灵可提供 | 仍需补充的数据源 |
|---|---|---|
| 自有销售与转化 | 市场估算、搜索和竞品代理指标 | Amazon SP-API、内部销售数据、Shopify/其他平台订单 |
| 自有广告效果 | PPC、广告排名和竞品广告线索 | Amazon Ads、Google、Meta、TikTok Ads 第一方授权 |
| 真实利润 | 价格、FBA 运费和页面毛利率代理 | ERP、采购、财务、物流、平台结算和汇率 |
| 库存与补货 | 商品重量尺寸、销量估算 | ERP、WMS、FBA 库存、在途、交期和销售预测 |
| 售后与质量 | 评论 VOC 可作为外部反馈 | 退货原因、客服、质检、供应商和生产批次 |
| 供应链 | 货源搜索入口 | 供应商报价、MOQ、产能、交期、良率和验厂数据 |
| 合规 | 卖家精灵专利与全球商标库本轮不接入 | 官方专利商标库、认证、危险品和各国法规；必要时结合人工法律审查 |
| 趋势热点 | Amazon 搜索趋势和 TikTok 线索 | Google Trends、社媒内容、新闻、节日和行业数据 |
| 多平台经营 | TikTok 等少量入口 | Walmart、eBay、Temu、Shopee、Lazada、独立站数据 |

### 4.9 推荐建设顺序

| 阶段 | 建设重点 | 目标结果 |
|---|---|---|
| 第一阶段 | 标准化现有七个场景；解决父 ASIN 去重、销售额和毛利率口径；建设六个组合场景 | 让已有数据真正支撑选品、竞品和关键词决策 |
| 第二阶段 | 接入广告洞察、关联流量和产品监控；卖家精灵插件评论排除在服务端建设范围外 | 从一次性市场查询升级为持续运营闭环；关键词监控和店铺上新监控不作为取数场景 |
| 第三阶段 | 接入 ABA、关键词资产、专利商标和利润工具 | 补齐需求份额、合规和立项评估 |
| 第四阶段 | 接入 Listing 内容、产品库、TikTok 达人和货源线索 | 延伸到内容执行、多平台趋势和供应链 |
| 并行建设 | 对接第一方销售、广告、库存、利润、退货和物流 | 将外部情报与真实经营结果闭环验证 |

### 4.10 总体判断

当前 opscli 对卖家精灵的接入已经覆盖了最有价值的基础数据面：市场、产品、竞品、关键词、流量和 Listing。技术底座也已经具备异步、批量、额度和导出能力，因此短期价值最高的动作不是继续无序增加页面，而是先把现有七个场景组合成选品评分、竞品 360、关键词机会、新品验证、父子变体诊断和数据可信度六个业务产品。

第二优先级应补广告洞察、关联流量和产品变化监控；关键词监控与店铺上新监控因范围或额度限制，不作为取数场景。卖家精灵浏览器插件评论仅供客户端/人工辅助，不进入服务端处理；评论 VOC 应由平台授权数据、内部客服/退货数据、用户提供的授权数据或合规第三方接口补齐。这些能力能让卖家精灵从“选品取数工具”升级为“产品开发与运营优化情报源”。但真实销售、广告、利润、库存、物流、售后和供应链仍必须由第一方及内部系统补齐，不能通过卖家精灵估算值替代。

### 5.6 上游能力仍不能补齐的数据

从完整注册表可见，上游领域只覆盖 ASIN、商品、关键词、流量、市场、趋势/评论和商标。以下是基于完整工具注册表的边界推断，即使 43 个工具全部接入也仍需其他数据源：

| 业务环节 | 上游可提供 | 仍需的数据源与原因 |

| 自有广告优化 | PPC 建议、广告排名、广告词数量和竞品流量 | Amazon Ads、Google/Meta/TikTok Ads；需要真实花费、展示、点击、订单、ACOS、ROAS 和预算 |
| 真实利润与定价 | 市场价格、商品尺寸代理、价格带和促销趋势 | ERP、采购、物流、关税、结算、退货、汇率和财务 |
| 库存、补货与物流 | 重量、尺寸、履约类型、销量趋势 | ERP/WMS、FBA 库存、在途、库龄、交期、头尾程报价和仓网时效 |

Google Trend 工具只提供关键词、链接和时间序列热度值；ABA 提供的是 Amazon 站内搜索排名、搜索/购买/点击等指标。这两者适合做需求趋势交叉验证，但不能代表社媒内容热度、事件舆情或多平台成交趋势。

### 5.7 接入与维护建议

1. **保留上游为项目外只读参考仓库**：继续使用 `D:\Gitlab\tmp\sellersprite-cli`，不复制进 open-opscli，也不设 Git Submodule，避免外部发布节奏绑定本项目提交。

### 5.9 源码对照后的结论

1. **43 个原子工具、27 个分析配方、7 个 opscli 正式场景是三个不同层级**：不能相加，也不能用 Skill 数量表示数据接口覆盖。
2. **先把现有七场景做成六个组合业务产品**；这是最快形成运营价值的路径。
3. **新增数据 P0 顺序为关联流量、广告洞察、产品变化监控和趋势机会**；选市场已实现，浏览器插件“市场分析”不便获取，本轮放弃。多 ASIN 流量词扩展先按组合场景建设，专用接口通过独有字段或效率验收后再接。关键词监控和店铺上新监控排除在通用取数场景之外；卖家精灵浏览器插件评论也排除在服务端建设范围外。
4. **上游广告配方只是第三方广告情报建议，不是第一方广告数据能力**；真实广告、库存、物流、利润、退货和多平台经营仍需外部或内部数据源。
5. **卖家精灵 + Keepa + 第一方经营数据应形成分层事实体系**：卖家精灵负责外部市场与竞争情报，Keepa 负责价格/排名历史验证，第一方和内部系统负责经营事实与执行闭环。
