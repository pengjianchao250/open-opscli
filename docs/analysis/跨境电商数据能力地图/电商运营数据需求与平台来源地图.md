# 电商运营数据需求与平台来源地图

> **文档定位**：把“运营需要什么数据”进一步落到“由什么平台、什么入口、以什么方式取得”，作为数据接入、场景设计和数据治理的来源目录。
> **适用范围**：Amazon 为第一阶段主战场，兼顾 Walmart、TikTok Shop、Shopify、Shopee、Temu 和 1688 货源生态。
> **当前基线**：卖家精灵与 Keepa 已正式接入；西柚找词与 SIF 已有完整项目实现，但主 CLI/MCP 入口暂时关闭；运营系统数据集导航页已确认 Amazon SP/SC、Ads 和 Brand Analytics 数据集，`ops-dataset-query` 可作为内部数据统一查询入口；具体服务账号权限和场景仍待验收；Sorftime 只完成静态调研。
> **版本**：v0.3
> **更新时间**：2026-07-21

内部数据集能力证据：[运营系统数据集导航页](../../../../运营系统数据集-数据集导航页.csv)。

## 一、读图规则

### 1.1 数据性质

| 类型 | 含义 | 典型来源 | 能否直接用于经营核算 |
|---|---|---|:---:|
| 官方第一方事实 | 自有账号产生的平台事实 | Amazon/Walmart/TikTok Shop/Shopify 后台及官方 API | 是，但需统一时区、币种和归因口径 |
| 内部经营事实 | 企业内部执行与财务事实 | ERP、OMS、WMS、TMS、SRM、财务、客服、质检 | 是，但需建立主键和跨系统对账 |
| 第三方估算 | 第三方模型估计竞争对手或市场表现 | 卖家精灵、西柚找词、SIF、Sorftime | 否，适合研究、比较和预警 |
| 代理指标 | 与目标指标相关但不等价 | Keepa BSR、评论增速、Offer 数、最大可购数量 | 否，必须说明代理关系和失效条件 |
| 模型推断 | 对原始数据进行分类、预测或归因 | VOC 主题、情感、根因、销量预测 | 否，需保存模型版本、置信度和证据 |

### 1.2 接入状态

| 状态 | 含义 |
|---|---|
| **已接入** | 当前已有正式工具场景和可验证输出 |
| **代码已实现、入口关闭** | Provider/Client/任务/导出存在，但主 CLI/MCP 注册或配额未开放 |
| **页面/报表可取** | 人工后台或浏览器页面可见，但未形成稳定接口 |
| **候选待 POC** | 已确认文档能力，尚未用真实账号验收 |
| **待盘点授权** | 平台或内部可能具备，需确认账号、权限和历史范围 |
| **不建议采集** | 合规、额度、稳定性或投入产出不适合作为通用数据源 |

### 3.4 内部系统：最终经营事实的归属

| 内部系统 | 应提供的数据 | 关键关联键 | 对外部平台数据的作用 |
|---|---|---|---|
| `ops-dataset-query` / 内部数据平台 | Amazon SP/SC、Ads、Brand Analytics，以及销售、库存、物流、流量和跨平台经营数据 | 数据集授权、SKU、ASIN、店铺、站点、平台商品 ID、日期 | 作为统一查询入口复用内部事实；模块已确认，具体字段需按服务账号权限验收 |
| PIM/PLM/刊登系统 | Product、SPU、SKU、属性、规格、内容版本、发布记录 | Product ID、SPU、SKU、Listing ID、ASIN | 统一产品定义和 Listing 版本 |
| ERP/OMS | 采购、订单、销量、成本、调拨、渠道和店铺 | SKU、订单号、站点、店铺、时间 | 形成销售与成本主事实 |
| SRM/采购系统 | 供应商、报价、MOQ、合同、交期和履约 | Supplier ID、SKU、采购单、批次 | 把 1688 线索转为真实供应关系 |
| MES/QMS/质检 | 生产、工单、批次、良率、缺陷和质检结果 | SKU、供应商、生产批次、质检单 | 与差评和退货定位产品根因 |
| WMS/FBA 库存 | 在库、可售、预留、库龄、调拨和在途 | SKU、FNSKU、仓库、批次 | 形成补货和滞销事实 |
| TMS/货代/承运商 | 头程、尾程、轨迹、签收、丢损、时效和运费 | Shipment ID、Tracking No.、订单号 | 计算履约时效与真实物流成本 |
| 财务/结算 | 回款、平台费、广告费、税、退款、汇率和贡献利润 | 订单号、SKU、结算单、费用类型 | 形成利润唯一事实源 |
| CRM/客服/售后 | 工单、咨询、投诉、退款、退货描述和处理结果 | Customer/Order/SKU/Ticket ID | 与评论、批次、物流形成 VOC 根因链 |
| 广告数据仓库 | 各渠道 Campaign 到 Search Term 明细和归因 | Channel、Account、Campaign、Ad、Keyword、ASIN/SKU | 统一 ACOS、ROAS、新客和跨渠道归因 |
| BI/指标平台 | 统一口径、快照、指标血缘、告警和分析结果 | 统一维表与日期版本 | 将平台事实、内部事实和外部情报组合成场景 |

## 五、数据源选择规则

### 5.1 同一指标的优先顺序

```text
自有经营事实：平台官方 API/报表 ↔ 内部系统对账
        ↓
市场与竞品事实：平台公开信息或许可数据
        ↓
第三方估算：卖家精灵 / Keepa / 西柚找词 / SIF / Sorftime
        ↓
模型推断：主题、情感、根因、预测和建议
```

具体规则：

1. 自有订单、广告、库存、费用和利润不得被第三方估算覆盖。
2. 竞品销量无法取得官方事实时，可使用第三方估算，但必须保存来源、抓取时间和模型口径。
3. 价格、BSR、Offer 等历史优先复用 Keepa，避免在其他供应商重复付费。
4. Amazon 市场、选品和通用关键词优先复用卖家精灵；恢复西柚入口后复用其榜单、反查、分析、流量和放映机，公开 OpenAPI 只补现有实现缺失的日/小时序列和广告变化字段。
5. SIF 优先补变体销量结构、ASIN 流量结构和多产品对比，避免与卖家精灵/西柚再包装同义场景。
6. Sorftime 优先承担多平台、TikTok 和 1688，不优先重复 Amazon 基础商品库。
7. 评论正文优先使用平台授权 API/报表、内部客服与退货数据、用户提供的授权数据或合规第三方接口；卖家精灵浏览器插件仅供客户端/人工辅助，不进入服务端，也不建设无授权服务端爬虫。
8. 商标、专利、认证和政策结论必须来自官方权威源或专业人工审核，第三方只能提示线索。

### 5.2 每个接入项必须登记的来源字段

| 登记项 | 示例 |
|---|---|
| `provider` | amazon_sp_api / amazon_ads / seller_sprite / keepa / xiyou / sif / sorftime / erp |
| `source_location` | API、Seller Central 报表、浏览器插件、内部数据集 |
| `source_type` | official_first_party / internal_fact / third_party_estimate / proxy / inference |
| `account_scope` | 账号、店铺、站点、Marketplace、广告 Profile |
| `object_key` | Product/SPU/SKU/ASIN/Listing/Keyword/Campaign/Order/Supplier |
| `event_time` | 业务发生时间 |
| `collected_at` | 获取时间 |
| `grain` | 商品日、关键词小时、订单行、广告搜索词日等 |
| `currency_timezone` | 币种、汇率版本、时区 |
| `method_version` | API/报表/估算/模型版本 |
| `cost_quota` | 调用积分、Token、限流和订阅成本 |
| `quality` | 完整率、延迟、抽样一致率、异常率 |

## 七、推荐实施顺序

### 第一阶段：闭合 Amazon 自有经营事实

1. 以已确认的 Amazon SP/SC、Ads 和 Brand Analytics 内部数据集为基础，验收服务账号权限、字段、历史深度和更新频率，不再从“是否存在”重新盘点。
2. 打通 ERP/OMS、广告、FBA/WMS、财务、退货和客服数据。
3. 建立 Product—SPU—SKU—ASIN—Listing—Campaign—Order—Inventory 的统一映射。
4. 落地经营诊断、广告诊断、Listing/VOC、库存补货和真实利润。

### 第二阶段：补独有外部情报

1. 先恢复西柚与 SIF 的受控测试入口，验证现有 Provider、账号、XLSX/JSON 和字段口径，不重复开发底层功能。
2. 将西柚公开 OpenAPI 与项目现有 9 个 function 做字段差异，只接日/小时序列、广告变化等真实增量。
3. 将 SIF 的变体销量、流量词、自然位和多产品对比与卖家精灵/Keepa/西柚交叉校准，并对高价值 XLSX 建字段解析。
4. Sorftime 只验证 TikTok、多平台和 1688，Amazon 重叠能力暂缓。
5. 每个供应商用 3—5 个真实 ASIN、少量关键词、一个站点完成完整率、准确率、延迟和成本验收。

### 第三阶段：多平台经营复制

1. 按业务优先级接入 Walmart、TikTok Shop、Shopify、Shopee 等官方经营数据。
2. 复用统一商品、订单、广告、库存、费用和 VOC 模型。
3. 再建设跨平台商品匹配、价格对比、库存协同和全渠道归因。
