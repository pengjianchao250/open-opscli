## 四、三轮优化内容

### 第二轮：字段与合同

- 大小写敏感技术字段优先，修复 `SPU/spu` 与 `VCPM` 优先级；
- 授权字段池收紧到已选数据集；
- 显式字段按物理 `field_name` 保留，不被中文包含关系吞并；
- 输出容量与 32 字段公开上限对齐；
- 补齐默认条件严格 Schema。

### 第三轮：选表语义与组件

- 数据集身份、完整字段标签与平台筛选 span 分离；
- 连续中文改为扣词留残差；
- 低类型词查询允许当前卡片内的唯一高置信匹配；
- 空部门组件从现有关系 CSV 内存派生枚举字段；
- 同名数据集候选增加字段摘要；
- 同中文标签多物理字段改为安全澄清。

### 第四轮：状态与执行安全

- 默认时间、推荐字段、平台枚举未完成时不下发模板；
- 补齐绝对日期、季度和年份解析；
- `run_query` 强制绑定同一 query plan；
- tableId、字段集合、模板状态在执行前硬校验；
- Skill 文档、CLI 参考和默认条件覆盖语义同步；
- 版本升级到 1.3.7。

## 七、不能由当前规划器安全自动修复的剩余项

1. **快照标志缺失**：现有字段 CSV 中 `snapshot_metric=1` 为 0 条，且“ASIN最新详情快照表”的指标均为 0。不能依据表名擅自改聚合策略，必须由元数据发布源修正后再验收。
2. **query_metadata.json 漂移**：顶层 `fields=[]`，而 CSV 有 1,721 行。当前规划器明确以 CSV 为权威，不受影响；其他旁路消费者仍需上游决定同步字段或正式废弃该 JSON 字段源。
3. **同名业务表源数据**：两个“用户仪表盘分享明细”仍同名同说明。本轮通过字段摘要让用户可区分，但根治应由数据集维护方补充稳定中文名称/说明。
4. **账号所有权标识缺失**：现有 VERSION/query_metadata 没有账号指纹，无法仅凭本地文件证明跨目录 fallback 属于同一账号。Skill 已要求账号变化或所有权不明时刷新；若要代码硬校验，需要上游在现有 VERSION.json 增加账号指纹字段，无需新增索引文件。
5. **非平台筛选自动回灌**：部门/国家等组件已有合法枚举入口，但尚没有像平台一样的通用自动枚举回灌参数；当前 Skill 仍要求执行前按组件枚举并确认，不能静默写入文本值。

这些剩余项均已保持“不能证明就不猜”的安全边界，不影响本次字段与数据集覆盖结论。
