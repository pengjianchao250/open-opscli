# 卖家精灵全部场景分页实施方案

日期：2026-09-28

## 目标

让每个卖家精灵场景都有明确的采集语义：单页、可分页全量、官方文件透传、任务详情分页或单报告。实现按场景合同选择请求字段、响应解析、上限、行唯一键和导出策略，避免把选产品的 `data.items/data.total`、ASIN 判重或 2,000 条上限套到其他场景。

## 采集能力分层

| 能力 | 场景 | 实施结论 |
| --- | --- | --- |
| `page` | 全部列表和报告场景 | 保持现有默认行为，一次请求和现有导出格式不变 |
| `all` 第一批 | 选产品、选竞品 | 选产品沿用已实现的可访问范围采集；选竞品仅保留单页能力。两者各自使用独立响应解析器和行键，2,000 条只属于选产品/选竞品页面访问提示，不作为其他场景的分页验收条件 |
| `all` 第二批 | 关键词挖掘 | 使用 `pageNum/pageSize`，网页允许至少 3,705 条；上限暂定为场景合同配置，不能写死 2,000，先以返回 total 和服务端拒绝为准 |
| `all` 待补证据 | 关键词反查、查流量来源、关联流量、ABA 选品 | 已确认各自请求合同：关键词反查 `limit/skip`、来源 `pageNo/pageSize`、关联流量 `pageNum/pageSize`、ABA `page/size`；本轮只验收能翻页，不开放 all。来源接口允许 `pager.page=0,size=null`，不得做响应页大小强校验 |
| `page` 或专用流程 | 关键词选品、选市场、关键词对比、拓展流量词、关键词转化率、实时查竞价 | 关键词选品、选市场已通过真实页面确认第 2 页请求；其余场景仍保留单页。分页需要冻结 prepare、动态列、任务 ID、SP/SB 合并和聚合口径后再开放 |
| 官方文件/单报告 | 出单词反查、全球商标库、Listing Analysis | 官方 XLSX 原样透传或生成单报告，不循环分页；在结果元数据明确“不适用分页” |

## 通用合同

新增场景分页合同注册表，每项必须声明：

1. 请求传输方式、页码起点、页字段或 offset 字段、页大小字段及筛选冻结字段。
2. rows、total、has-next 的路径和类型；缺失 total 时只能返回 `unverified`，不能当作零或完成。
3. 页面可选大小、已验证访问上限和服务端拒绝特征；未知值保持未知。
4. 行唯一键和重复处理策略。关键词使用站点、周期和规范化关键词；市场使用类目 ID/path；产品使用子 ASIN。
5. 是否允许重试和恢复。`replay_safe=false` 场景不能由通用重试重复创建任务或重复扣费。
6. 导出适配器。流式写入普通行；动态列和辅助汇总先建立有限状态，再提交最终工作簿。

通用分页引擎只复用顺序请求、请求指纹、原子页文件、检查点、总时限、有限重试和进度事件。响应解析、行键、上限和导出全部由场景合同提供。

## `collection_scope=all` 的统一上限

普通网页列表场景统一设置 `MAX_ACCESS_ROWS=2000`，这是 opscli 的安全采集上限，不代表卖家精灵每个页面的真实服务端上限。一次任务的目标行数按 `min(reported_total, 2000)` 计算；如果接口没有可靠 `total`，最多请求到累计 2,000 行，或在返回短页后结束，并将覆盖状态标记为 `unverified`，不能默认为完整。

每个场景仍使用自己的有效页大小和页字段。页大小为 100 时最多 20 页，页大小为 50 时最多 40 页，offset 场景按 `skip` 递增；上限按行数计算，不能简单复用“20 页”这个数字。服务端返回总数大于 2,000 时，任务以 `stop_reason=access_limit` 正常结束，结果同时返回 `source_total`、`rows_written=2000`、`coverage=source_limited`，不能把它报告为覆盖全部匹配结果。

以下场景可作为普通列表 all 的候选，但仍需完成各自门禁后逐个开放：`competitor-lookup`、`keyword-miner`、`keyword-reverse`、`traffic-source`、`association-traffic`、`aba-research`、`keyword-research`、`market-research`。关键词选品和选市场目前缺少稳定的 total 解析，先只保留 page 模式。

`aba-reverse`、`branddb` 和 `listing-analysis` 不进入这个上限：前两者是官方文件下载，后者是单报告。`keyword-comparison`、`traffic-extend`、`keyword-conversion-rate`、`real-time-bidding` 需要先完成 prepare/任务/动态列合同，不能只把请求中的 `page=1` 改成循环。

## 异常退出、取消和恢复

每完成一页都按“原始页文件原子落盘 → SHA256 校验 → 更新检查点”的顺序提交，检查点至少记录场景合同版本、请求指纹、账号标识、有效页大小、已完成页、最后成功 offset/page、`source_total`、行数、重复数、截止时间和 `stop_reason`。异常退出、进程终止、浏览器崩溃、网络超时或用户取消时，保留已完成页并将任务标记为 `paused`/`cancelled`，绝不生成成功的完整结果。

恢复只能使用相同账号、相同查询指纹、相同站点/周期/筛选、相同场景合同版本和未过期的总时间预算。已完成页不重复请求；当前失败页按场景规则最多重试 2 次，优先处理 502/503/504 和可恢复网络错误。认证失效先刷新会话，不能换账号拼接已有页；429、额度不足、参数错误、业务拒绝和结构变化直接失败并保留检查点。检查点校验失败、页码跳跃、总数漂移、重复唯一键或单页超过字节上限时停止并返回 `unverified`。

导出阶段同样可恢复：从已提交页文件逐页读取，使用流式 XLSX 或有界聚合；中断时删除未完成的临时导出文件，保留页文件和检查点。只有页范围、行数、唯一键和导出文件全部通过校验后，才将任务置为 `succeeded`。

## 分批开发与门禁

### A 批：普通 JSON

先完成选竞品、关键词挖掘、关键词反查、查流量来源。当前验收只要求通过真实页面或用户提供的真实请求确认第 1/2 页参数和结果变化，不要求把结果推进到 2,000 条以上；自然短页、零结果和导出完整性属于后续 all 门禁。A 批中选竞品、关键词挖掘、查流量来源已有网页第 2 页证据，关键词反查已有 `limit/skip` 真实请求证据，均继续保持 page 模式。

### B 批：固定首页和附加上下文

处理 ABA 选品、关联流量、流量词对比、拓展流量词。先删除或绕过固定首页逻辑，再验证 prepare 和变体只运行一次；动态列、Unique Words、ASIN 辅助表及百分比必须在全范围聚合后导出。任何 manager/export 的 `rows[:100]` 都要在 all 分支单独解除，并保留 page 兼容。

### C 批：HTML

处理关键词选品、选市场。两者已通过真实分页控件确认第 2 页分别携带 `page=2&size=50`，并出现第 51 条结果；仍需解析各自主结果区域的当前页和总数，区分登录页、空表和结构变化。没有可靠 total 时不开放 all。

### D 批：任务和额度

处理关键词转化率和实时查竞价。任务只创建一次，翻页只查询同一 task ID；记录额度、SP/SB 两路页边界、恢复和失败语义。`replay_safe=false` 的场景先只支持 page。

### E 批：官方文件和报告

验证导出文件是完整结果还是选中范围，记录文件内行数和服务端声明；Listing Analysis 固定为单报告能力，不进入分页循环。

## 内存与导出要求

全量任务不得把所有原始响应和格式化副本同时放入内存。分页响应先原子写入任务目录，导出通过行迭代器读取一页；动态辅助数据只保留有界集合或磁盘中间结果。每个合同设置单页字节上限、总超时、页数上限和取消检查。最终结果只返回行数、覆盖状态、警告和有限预览，原始页文件留在任务目录供恢复和审计。

## 发布门禁

场景只有在网页证据、脱敏 fixture、单元测试、导出行数对照、恢复测试和内存基准均通过后，才把 `collection_scope=all` 加入 CLI/MCP 公共参数。未达到门禁的场景继续使用 page，并在 Skill 和场景列表中显示能力状态。
