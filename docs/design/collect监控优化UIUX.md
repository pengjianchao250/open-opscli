# collect 监控优化 UIUX

> 状态：方案草案
> 产品形态：内网运维监督台，不是营销页，不是聊天界面

## 1. 设计目标

- 第一屏 10 秒内回答：能否接单、队列是否可用、是否在消费、当前根因是什么。
- 区分“状态刷新”“主动探测”“业务重试”，避免误操作。
- 以表格、状态带和时间线为主，适合高频扫描与对比。
- 保持低敏，只显示运维判断需要的字段。

## 2. 冻结设计系统

### 2.1 技术与组件生态

- Starlette 服务端 + 原生 HTML/CSS/JavaScript，延续当前无 SPA 框架结构。
- 不使用外部 CDN；所有字体与资源随 wheel 本地打包。
- 组件：状态带、数据表、行内状态和页面内 `aria-live` 探测结果。
- 不创建嵌套卡片，不使用营销式大标题或装饰插画。

### 2.2 图标

- 首期明确命令按钮可使用纯文本，不用 emoji 或临时符号。
- 若后续需要图标，只允许 Lucide，并通过构建期生成的本地静态资源引入，不手绘 SVG、不使用 CDN。
- “立即探测”首期采用文字按钮，避免为单一按钮引入前端依赖。

### 2.3 字体

- 中文：Noto Sans SC Variable，本地 WOFF2。
- 英文与数字：Inter Variable，本地 WOFF2。
- 代码与标识：JetBrains Mono，本地 WOFF2。
- 字号固定，不随 viewport 宽度缩放；字距为 0。

### 2.4 Design tokens

```text
--canvas:       #F4F6F8
--surface:      #FFFFFF
--surface-subtle:#EEF2F5
--text:         #17212B
--text-muted:   #5D6975
--border:       #D5DDE4
--action:       #1769AA
--healthy:      #18794E
--warning:      #9A5B00
--critical:     #B42318
--unknown:      #66727F
--focus:        #0B6EBD
--radius-sm:    4px
--radius-md:    8px
--shadow:       0 1px 3px rgba(16, 42, 67, .08)
```

不使用渐变、紫粉主色、bokeh/orb、超大圆角和一屏卡片墙。

## 3. 页面骨架

```text
顶部栏
  Collector Monitor | 最后更新时间

常驻总览
  任务总数 | 运行中 | 异常任务 | 活动事故

主工作区 Tabs
  任务：任务表 + 选中任务进度时间线
  Collector：Collector/Bundle 状态 + Collector/队列源手动探测
  运行时：Scheduler 心跳与容量
  事故：事故历史
```

桌面端任务表使用有界滚动，时间线固定在同一视图右侧；窄屏改为单列，隐藏队列/类型列，并把时间线放到列表下方。Tabs 保持单行并允许横向滚动，避免任务量增大后把 Collector 探测入口推到长页面底部。

## 4. 第一屏信息层级

### 4.1 服务状态带

每项固定高度，不因 loading 或错误文本改变布局：

- 状态：healthy/degraded/unavailable/unknown。
- 最近成功时间。
- 延迟或最近扫描年龄。
- 失败时只显示稳定错误码。

不使用五张浮动卡片；使用一条全宽、带分隔线的状态栏。

### 4.2 根因优先

存在 critical/high incident 时，在状态带下显示单一根因横幅：

```text
队列数据库不可用  CRITICAL
SellerSprite 当前无法接收新任务，8 条相关反馈，持续 18 分钟
[查看事故] [立即探测]
```

派生事故折叠为“另有 12 项受影响”，避免告警墙。

## 5. 关键交互

### 5.1 立即探测

按钮状态固定宽度：

- Idle：`立即探测`
- Running：`探测中...`，按钮禁用
- Success：页面内结果区显示状态与探测时间，并刷新缓存状态带
- Failed：页面内结果区显示安全错误摘要，按钮恢复可用
- Cooldown：显示剩余秒数，不改变整体布局

点击后不弹确认框，因为动作不写业务状态；页面需明确标注“不会提交真实任务”。该说明放在按钮 tooltip/accessible description，不在页面堆放教程文字。

Collector Tab 提供密码类型的“临时 API Key”输入。输入值仅随下一次 Collector 探测发送，提交后立即清空；队列源探测不读取该输入。鉴权失败显示 `COLLECTOR_AUTH_FAILED`，与网络不可达分开。

### 5.2 自动刷新

使用分段控制：`暂停 / 7 秒 / 30 秒`。主动探测与普通缓存刷新分开：自动刷新只读缓存，不触发远端探测。

### 5.3 事故详情

右侧抽屉或固定详情栏显示：

- fingerprint、scope、severity、status；
- 首次/最近出现、持续时间；
- 连续失败/恢复次数；
- 影响任务数、被抑制事故数；
- 相关 feedback 数和最近时间；
- 通知状态与安全错误类；
- 最近探测事件时间线。

不展示原始异常、SQL、绝对路径、请求参数或用户身份。

### 5.4 feedback 信号

使用紧凑表格：

| 错误签名 | 60 分钟 | 趋势 | 最高严重度 | 最近出现 |
|---|---:|---|---|---|

点击只打开聚合详情，不在 Monitor 拉取完整 feedback。需要完整详情时提供受控内部工作流提示，不提供公开 URL 或密钥。

### 5.5 任务操作边界

任务表没有 retry、requeue、cancel 按钮。已有任务需要运维处置时，详情只展示状态和安全建议；真正的写操作继续走服务主机 CLI 与现有权限边界。

## 6. 页面状态

### 首次启动

- live 已就绪但还未首扫：状态带显示 `checking`，表格保持固定骨架。
- 首扫超过 5 秒：显示“首次扫描尚未完成”，不伪装为 0 任务。

### 数据源不可用

- 根因横幅置顶。
- 任务表显示“当前快照不可用”，不显示空队列文案。
- 保留上次成功时间与已有事故，不误标恢复。

### Collector 不可达

- Queue source 仍可独立显示状态。
- Collector 与 Bundle 标红，任务历史仍可读取。
- 提供立即探测，不提供任务重试。

### feedback 快照过期

- Feedback signal 显示 stale/unknown。
- 不改变 Collector 总体健康颜色，不触发业务不可用结论。

### 无事故

- 根因区收起为一行“当前无活动事故”。
- 主视图默认显示运行中和排队任务。

## 7. 可访问性与响应式

- 所有状态同时使用文字，不只依赖颜色。
- 颜色对比满足 WCAG AA。
- 键盘可访问任务行、Tabs、按钮和抽屉关闭控件。
- focus ring 使用 `--focus`，不可移除。
- 表格动态内容不改变列宽；长 job ID 允许换行或中段省略并提供完整 title。
- 移动端操作区不重叠，命令按钮最小触控高度 40px。

## 8. UI 验收

1. 1280x720、1440x900、390x844 下无重叠、裁切或横向页面滚动。
2. 最长错误码、长 job ID 和中文根因文案不撑破容器。
3. 探测 loading/success/failure 不导致状态带跳动。
4. 无 emoji、无外部 CDN、无紫粉渐变、无卡片墙。
5. 页面源码不包含 retry/requeue/cancel 业务动作。
6. 敏感字段扫描覆盖 HTML、API 响应、页面内探测结果和错误状态。
