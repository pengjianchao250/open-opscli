## 1. 背景与目标

### 1.1 问题背景

AI/Skill 在帮助用户构建数据查询时，需要了解数据集中有哪些可用字段（维度与指标）、字段含义、数据类型和计算公式。若每次实时调用数据库接口，存在以下问题：

| 问题 | 影响 |
|------|------|
| 每次调用需要网络请求 | 响应慢，Skill 启动耗时长 |
| 字段数量庞大（>2000） | 实时传输开销大，不适合搜索 |
| AI 需要语义搜索能力 | 普通 REST 接口不支持关键词相似度排序 |
| 数据集变更频率低 | 事件驱动同步成本高且复杂 |

### 1.2 解决思路

采用**本地缓存 + 显式版本发布 + 多层级更新触发**的模式：

- Skill 在本地维护一份 CSV 格式的字段清单缓存，支持 BM25 语义搜索
- 管理员在数据集发生重大变更后，通过接口显式发布新语义化版本（`v0.1.0 → v0.1.1`）
- 提供三层更新触发机制，覆盖从自动静默到主动批量的全场景需求

### 1.3 核心目标

| 目标 | 实现方式 |
|------|---------|
| **离线可用** | 本地 CSV 缓存，网络不通时正常搜索 |
| **自动同步** | Skill 启动时静默检查并更新，业务无感知 |
| **主动更新** | `opscli skills upgrade` 立即批量更新所有 Skill |
| **语义搜索** | BM25 算法，支持中英文混合关键词 |
| **版本可控** | 管理员显式发布，防止频繁 DB 变更触发不必要同步 |

## 3. 更新机制设计

本系统提供三层更新机制，覆盖不同场景：

```
┌───────────────────────────────────────────────────────────────┐
│                        三层更新机制                             │
│                                                               │
│  Layer 1  自动更新（静默）                                      │
│  ─────────────────────────────────────────────────────────   │
│  触发时机：Skill 被调用时（import core 时）                      │
│  用户感知：无（stdout 被重定向，异常被捕获）                      │
│  适用场景：日常使用，完全无感知                                   │
│                                                               │
│  Layer 2  CLI 主动更新（opscli）                               │
│  ─────────────────────────────────────────────────────────   │
│  触发时机：用户或 CI/CD 显式执行 opscli skills upgrade           │
│  用户感知：有（进度条 + 汇总报告）                               │
│  适用场景：新版本发布后需要立即同步；批量管理多个 Skill            │
│                                                               │
│  Layer 3  直接更新（updater.py）                               │
│  ─────────────────────────────────────────────────────────   │
│  触发时机：手动执行 python3 scripts/updater.py                  │
│  用户感知：有（文字输出）                                        │
│  适用场景：单个 Skill 调试；修复损坏的 CSV（--force）             │
└───────────────────────────────────────────────────────────────┘
```

### 三层机制对比

| 维度 | Layer 1 自动 | Layer 2 opscli | Layer 3 直接 |
|------|-------------|----------------|-------------|
| 触发方式 | 隐式（import） | 显式命令 | 显式脚本 |
| 管理范围 | 单个 Skill | 所有 Skill | 单个 Skill |
| 输出反馈 | 静默 | 格式化表格 | 纯文本 |
| 失败处理 | 降级本地缓存 | 报错并继续其他 | 报错退出 |
| 典型场景 | 日常使用 | 版本发布后同步 | 开发调试 |

## 4. 服务端架构

### 4.1 分层设计

```
Controller 层   DatasetSkillController（路由入口、参数校验、响应组装）
      │
Service 层      DatasetFieldsExportService（三步批量查询、数据组装）
      │
数据库层         ops_metrics 连接（dm_tables / dm_table_columns / dm_sql_metrics）
      │
配置存储层       system_constant 表（Manifest JSON 持久化，key=SKILL_DATASET_FIELDS_MANIFEST）
```

### 4.2 DatasetFieldsExportService 查询策略

一期真实字段数据分布在三张业务表，采用**三步批量查询 + 内存归一化组装**，规避 N+1 问题：

```
Step 1  查询 dm_tables
        ↓ 提取全部 table_id，建立数据集基本信息 Map

Step 2  查询 dm_table_columns   filter: chart_id IS NULL
        查询 dm_sql_metrics      filter: is_custom=0, deleted_at IS NULL
        ↓ 分别构造成 dimension rows / metric rows

Step 3  统一归一化
        ↓ 维度：column_name → field_name，field_type=dimension
        ↓ 指标：metric_name → field_name，field_type=metric
        ↓ 组装为统一的 FieldExportRow
        ↓ 投影为 Skill CSV / Excel 导出行
```

**三层过滤规则：**

| 过滤条件 | 所在表 | 排除的数据 |
|---------|--------|-----------|
| `deleted_at IS NULL` | dm_tables | 已删除数据集 |
| `dataset_alias IS NOT NULL AND dataset_alias != ''` | dm_tables | 无可用标识的数据集 |
| `is_active = 1` | dm_table_columns | 已停用字段 |
| `deleted_at IS NULL` | dm_table_columns | 软删除字段 |
| `chart_id IS NULL` | dm_table_columns | 图表临时复制的列 |
| `is_custom = 0` | dm_sql_metrics | 用户自定义指标 |
| `deleted_at IS NULL` | dm_sql_metrics | 软删除指标 |

**统一字段映射规则：**

| 统一字段 | 维度来源（dm_table_columns） | 指标来源（dm_sql_metrics） |
|---------|-----------------------------|---------------------------|
| `field_name` | `column_name` | `metric_name` |
| `verbose_name` | `verbose_name`，为空回退 `column_name` | `verbose_name`，为空回退 `metric_name` |
| `field_type` | `dimension` | `metric` |
| `data_type` | `type` | `metric_type` |
| `origin_name` | `origin_name` | `origin_name` |
| `global_alias` | `global_alias` | `global_alias` |
| `expression` | `expression` | `expression_raw`，为空时回退 `formula_config` 摘要 |
| `is_dttm` | `is_dttm` | 固定 `0` |
| `is_restricted` | 固定 `0` | `is_restricted` |
| `field_key` | `global_uuid`，为空则 `{dataset_alias}:dimension:{column_name}` | `global_uuid`，为空则 `{dataset_alias}:metric:{metric_name}` |

### 4.3 SimpleXlsxWriter（零依赖 xlsx 生成器）

`maatwebsite/excel` 因私有 GitLab 仓库访问受阻无法安装，使用 PHP 内置 `ZipArchive` 实现等效功能。

**OOXML 文件结构：**

```
{file}.xlsx（ZIP 压缩包）
├── [Content_Types].xml         MIME 类型声明
├── _rels/.rels                 根关系文件
└── xl/
    ├── workbook.xml            工作簿定义
    ├── _rels/workbook.xml.rels  关系文件（Sheet/样式/字符串）
    ├── styles.xml              样式表
    ├── sharedStrings.xml       共享字符串池（内存优化）
    └── worksheets/sheet1.xml   行列数据
```

| 样式索引 | 用途 | 配置 |
|---------|------|------|
| `s="0"` | 正文默认 | 无特殊样式 |
| `s="1"` | 表头行 | 深蓝底 `#1E40AF` + 白色粗体 + 居中 + 首行冻结 |

### 4.4 版本 Manifest 存储

Manifest 以 JSON 序列化存入 `system_constant` 表，复用现有基础设施，无需新增数据表。

```json
{
  "version":      "v0.1.2",
  "released_at":  "2026-04-20T10:00:00.000000Z",
  "description":  "新增供应链数据集字段",
  "field_count":  1991,
  "published_by": "admin@aukeys.com",
  "previous":     "v0.1.1"
}
```

**版本号规则：**
- 格式：`v主版本.次版本.修订号`（正则：`^v\d+\.\d+\.\d+$`）
- 约束：新版本必须严格大于当前版本（三元组字典序，防止降级）

## 5. 客户端 Skill 架构

### 5.1 目录结构

```
.claude/skills/dataset-fields/
├── SKILL.md                     Skill 元信息 + 使用规范（供 Claude 读取）
├── data/
│   ├── VERSION.json             本地版本记录 {"version": "vX.Y.Z"}
│   └── dataset_fields.csv       字段缓存（13列，UTF-8 BOM）
└── scripts/
    ├── updater.py               版本检查 + 流式下载 + 原子替换
    ├── core.py                  BM25 索引 + DatasetFieldIndex 单例
    └── search.py                CLI 搜索入口（供 Claude 调用）
```

### 5.2 模块依赖关系

```
search.py                    CLI 入口
    │  argparse 参数解析 + 格式化输出
    ▼
core.py                      搜索核心
    │  懒加载单例 get_index()
    │  import 时调用 _auto_update_silent()
    │  DatasetFieldIndex.load()   → 读取 CSV + 建 BM25 索引
    │  DatasetFieldIndex.search() → BM25 打分 + alias 过滤
    ▼
updater.py                   更新引擎
    │  fetch_manifest()  → GET /skill/manifest
    │  download_csv()    → GET /skill/export，流式写临时文件
    │  原子替换          → shutil.move()（同目录保证原子性）
    │  更新 VERSION.json
    ▼
opscli.auth                  认证 SDK
    └  AuthClient().get_token("ops") → 自动刷新的 JWT
```

### 5.3 自动更新时序（Layer 1）

```
import core
    │
    ├─ _auto_update_silent()        # stdout 重定向，异常全捕获
    │      ├─ get_token("ops")      # 从 Keychain/加密文件读取凭据
    │      ├─ GET /skill/manifest   # 拉取远端版本（超时 10s）
    │      ├─ 对比本地 VERSION.json
    │      │
    │      ├─ [版本相同] → 直接返回
    │      │
    │      └─ [有新版本]
    │             ├─ GET /skill/export     # 流式下载（超时 60s）
    │             ├─ shutil.move()         # 原子替换
    │             └─ 写 VERSION.json
    │
    └─ DatasetFieldIndex.load()     # 读 CSV + 建 BM25 索引
```

**静默降级保证：** 网络超时 / Token 过期 / 接口异常，均捕获后使用本地缓存继续工作，不抛出异常。

## 6. opscli 工具设计

### 6.1 定位

`opscli` 是 `opscli` 包的扩展命令组，作为 Skills 的**本地包管理器**（类比 `brew upgrade`），提供主动、可见的批量管理能力。

> **与 Layer 1 的分工：**  
> Layer 1（自动更新）解决"日常无感知同步"，opscli 解决"新版本发布后立即批量更新"。两者互为补充。

### 6.2 命令结构

```bash
opscli skills list                       # 列出所有 Skill 及本地/远端版本
opscli skills status                     # 检查更新状态（不下载）
opscli skills upgrade                    # 升级所有 Skill（有新版本才更新）
opscli skills upgrade dataset-fields     # 升级指定 Skill
opscli skills upgrade --force            # 强制全部重新下载
opscli skills upgrade --skills-dir PATH  # 指定 Skills 目录
```

### 6.3 Skill 发现机制

按以下优先级确定 Skills 根目录，扫描所有含 `data/VERSION.json` 的子目录：

```
① --skills-dir 参数显式指定
② OPSCLI_SKILLS_DIR 环境变量
③ 默认：当前目录的 .claude/skills/
```

### 6.4 升级流程

```
opscli skills upgrade
    │
    ├─ 扫描发现所有 Skill 目录
    │
    ├─ 并行调用各 Skill 的 updater.fetch_manifest() 检查版本
    │
    ├─ 打印更新预览：
    │   ┌──────────────────┬──────────┬──────────┬──────────────────────┐
    │   │ Skill            │ 本地版本  │ 远端版本  │ 状态                  │
    │   ├──────────────────┼──────────┼──────────┼──────────────────────┤
    │   │ dataset-fields   │ v0.1.0   │ v0.1.2   │ ✦ 有更新（+1991 字段）│
    │   │ another-skill    │ v0.2.0   │ v0.2.0   │ ✓ 已是最新            │
    │   └──────────────────┴──────────┴──────────┴──────────────────────┘
    │
    ├─ 逐个下载更新（带进度条）
    │   dataset-fields  下载 dataset_fields_v0.1.2.csv [████████████] ✓
    │
    └─ 打印汇总：1 个更新，1 个已是最新，0 个失败
```

## 7. 版本控制机制

### 7.1 版本生命周期

```
数据集变更（DBA/管理员操作数据库）
    │
    │  变更积累，达到发布节点
    ▼
管理员执行 POST /skill/publish
    {"version": "v0.1.2", "description": "新增供应链字段"}
    │
    ├─ 校验版本格式 vX.Y.Z
    ├─ 校验新版本 > 当前版本（防降级）
    ├─ 统计当前字段总数（field_count）
    └─ 写入 system_constant 表
    │
    ▼
客户端同步（三条路径任选）
    ├─ 自动：下次 Skill 被调用时 Layer 1 静默更新
    ├─ 主动：管理员运行 opscli skills upgrade 立即同步
    └─ 手动：python3 scripts/updater.py
```

### 7.2 同步策略选型

| 策略 | 延迟 | 基础设施 | 适用场景 |
|------|------|---------|---------|
| Pull（本方案 Layer 1） | 下次启动后生效 | 无额外依赖 | 低频变更（日/周级） |
| opscli（本方案 Layer 2） | 命令执行后立即生效 | 无额外依赖 | 版本发布后需要立即同步 |
| Redis Pub/Sub | 秒级 | 需要 Redis 可达 | 高频变更，多机实时同步 |
| Push/Webhook | 秒级 | 需要客户端暴露端口 | 外网机器，主动推送 |

> 本项目数据集字段变更频率为周/月级别，Layer 1 + opscli 已满足需求，无需引入额外基础设施。

### 7.3 版本回滚

当前设计不支持版本降级（防误操作）。若必须回滚：

```bash
# 紧急方式：直接更新 system_constant 表（需 DBA 权限）
UPDATE system_constant
SET value = '{"version":"v0.1.0","released_at":"...","field_count":1800,...}'
WHERE name = 'SKILL_DATASET_FIELDS_MANIFEST';
```

**设计结论：**

- `skill/export` 继续保持轻量 13 列，专注搜索与离线索引
- 新增 `query-metadata` 专注构建可执行查询 JSON
- 两者都按用户权限裁剪，避免越权暴露

**服务端组装规则：**

| 输出字段 | 规则 |
|------|------|
| `from_table` | 一期优先返回可直接用于 Python 查询的 SQL/表模板；优先使用 `dm_tables.default_endpoint`，若不足以表达完整查询模板，则由服务端从现有 QueryBuilder 配置恢复 |
| `database` | 通过 `database_id` 关联数据源配置生成；子查询 SQL 允许返回空串 |
| `permission` | 从 `dm_tables.permission` 解析为数组；为空返回 `[]` |
| `inner_where_enabled` | 直接由 `dm_tables.inner_where_enabled` 输出布尔值 |
| `default_aggregation` | 优先取指标 `field_config.aggregationType`；其次由指标类型规则推导 |
| `translate` | 由字段名到 translate 枚举映射表推导；无映射则返回 `null` |

**权限过滤规则：**

- 仅返回用户有权限的数据集 `getCombinedDataSetIds($userId)`
- 仅返回 `deleted_at IS NULL` 且 `dataset_alias` 非空的数据集
- 维度字段：`is_active=1 AND deleted_at IS NULL AND chart_id IS NULL`
- 指标字段：`is_custom=0 AND deleted_at IS NULL`
- 受限指标：`is_restricted=1` 时，只有 `metric_name` 在 `fieldValidation($userId)` 列表中才返回
- 响应中的 `fields.table_id` 必须总能在 `datasets.table_id` 中找到对应项

**服务端伪代码：**

```php
public function queryMetadata(Request $request): JsonResponse
{
    $user = auth()->user();
    $allowedDatasetIds = (new UserOrm())->getCombinedDataSetIds($user->id);
    $fieldPermissions = collect((new AuthService())->fieldValidation($user->id)->toArray());

    $tables = DmTable::query()
        ->whereIn('id', $allowedDatasetIds)
        ->whereNull('deleted_at')
        ->whereNotNull('dataset_alias')
        ->where('dataset_alias', '!=', '')
        ->get();

    $tableIds = $tables->pluck('id');

    $columns = DmTableColumn::query()
        ->whereIn('table_id', $tableIds)
        ->where('is_active', 1)
        ->whereNull('deleted_at')
        ->whereNull('chart_id')
        ->get();

    $metrics = DmSqlMetric::query()
        ->whereIn('table_id', $tableIds)
        ->where('is_custom', 0)
        ->whereNull('deleted_at')
        ->get()
        ->filter(fn ($metric) => !$metric->is_restricted || $fieldPermissions->contains($metric->metric_name));

    return ApiResponse::success([
        'datasets' => $this->buildQueryMetadataDatasets($tables),
        'fields' => $this->buildQueryMetadataFields($tables, $columns, $metrics),
    ]);
}
```

## 11. 搜索引擎设计

### 11.1 BM25 算法

BM25 Okapi 是信息检索领域的标准排序函数，综合考虑词频、逆文档频率和文档长度：

```
Score(D, Q) = Σ IDF(q) × f(q,D)×(k1+1) / (f(q,D) + k1×(1−b+b×|D|/avgdl))

参数：k1=1.5（词频饱和），b=0.75（文档长度归一化）
```

### 11.2 分词策略

```python
def _tokenize(text: str) -> list[str]:
    tokens = re.split(r"[^\w\u4e00-\u9fff]+", text.lower())
    return [t for t in tokens if t]
```

中文保留字符级别（不做词典分词），适合字段名、业务术语的精确匹配。英文小写化后按非单词字符切分。

### 11.3 索引结构

```
DatasetFieldIndex
├── rows: list[dict]       原始 CSV 行（命中后取完整字段信息）
└── bm25: BM25
        ├── N              文档总数
        ├── avgdl          平均文档长度
```

## 12. 运维操作手册

### 12.1 发布新版本

```bash
# Step 1：确认数据集字段已在数据库更新完毕

# Step 2：发布新版本
curl -X POST https://https://ops.api.qa.aukeyit.com/api/v1/data-metrics/datasets/skill/publish \
  -H "Authorization: Bearer $(opscli auth token get -s ops)" \
  -H "Content-Type: application/json" \
  -d '{"version": "v0.1.2", "description": "新增供应链数据集：采购入库单、调拨单"}'

# Step 3：验证发布结果
curl https://https://ops.api.qa.aukeyit.com/api/v1/data-metrics/datasets/skill/manifest \
  -H "Authorization: Bearer $(opscli auth token get -s ops)"

# Step 4（可选）：立即推送到本地所有 Skill
opscli skills upgrade
```

### 12.2 Skill 更新操作

```bash
# 查看所有 Skill 版本状态
opscli skills list

# 检查哪些 Skill 有更新（不下载）
opscli skills status

# 升级所有 Skill
opscli skills upgrade

# 升级指定 Skill
opscli skills upgrade dataset-fields

# 强制重新下载（修复损坏的 CSV）
opscli skills upgrade dataset-fields --force

# 直接更新单个 Skill（调试用）
python3 .claude/skills/dataset-fields/scripts/updater.py
python3 .claude/skills/dataset-fields/scripts/updater.py --check
python3 .claude/skills/dataset-fields/scripts/updater.py --force
```

### 12.3 故障排查

| 症状 | 原因 | 处理方式 |
|------|------|---------|
| 搜索返回空结果 | CSV 不存在或为空 | 运行 `opscli skills upgrade --force` |
| 自动更新不生效 | Token 过期 / 网络不通 | 运行 `opscli auth login` 重新授权；检查网络 |
| opscli 命令不存在 | 未安装/未更新 opscli | `pip install -U opscli` |
| 版本发布被拒绝 | 版本号不合规或未递增 | 确认格式 `vX.Y.Z` 且大于当前版本 |
| CSV 下载中断 | 网络抖动 | 重新运行 `updater.py`（原子替换保证不破坏现有缓存） |
