# 新建标准站点持久化业务数据隔离需求

状态：已确认实施范围（2026-11-06）

## 1. 目标与边界

新版 opscli 创建**标准模板站点**时，由创建人明确选择持久化业务数据策略。拥有站点访问权限是进入站点的前提；站点内实时 OPS 查询仍由 OPS 服务按访问者 Token 授权。本需求只处理站点自行保存、加工、缓存和导出的业务数据，不改变 OPS 实时取数或 AppHub 站点访问权限。

已上线站点、通过源码复制迁移创建的站点和其他旧创建入口继续使用现有行为，不自动改造业务代码。它们在平台策略标记中按 `N` 兼容展示；该标记仅表示未启用本需求的用户隔离，不保证历史站点每张表实际共享。

## 2. 创建人选择

建站 Skill 在 `opscli app create` 前询问：

> 当前站点是否启用持久化业务数据按用户隔离？
>
> 是（Y）：业务记录、数据快照和加工结果按当前访问用户分别保存和读取；没有个人数据时仍可进入页面，显示空状态。
>
> 否（N）：拥有站点访问权限的成员可共享站点持久化业务数据，包括创建人基于自己 OPS 权限保存的结果。
>
> 页面结构配置与 OPS 实时查询不受此选择影响。

标准新建站点必须显式传入 `Y` 或 `N`，无答案不得替创建人选择。迁移内部创建明确传 `N`。选择值进入现有创建请求摘要；结果不明时只能核对 AppHub 并沿用原目录、原选择进行受控人工重试。

## 3. 平台策略标记

AppHub 应用注册表保存 `persistent_data_isolation: Y | N`。新建标准站点以创建请求为准，其他创建入口及旧站点为 `N`。字段在应用创建时确定，只读返回给管理页面与访问权限面板；普通访问权限设置、源码发布、`app.yaml` 修改和版本回滚均不能改变它。`app.yaml` 与 `.opscli` 不是平台策略事实源。

访问权限弹窗复用现有面板及访问策略查询：标记 `Y` 不显示提示；`N` 或标记缺失时，在顶部持续显示：

> 当前站点未启用用户数据隔离。持久化业务数据按站点共享，拥有站点访问权限的成员可能看到其他成员保存的数据。请确认数据可共享后再配置成员权限。

弹窗提示不改变当前授权。标记声明创建时选择，**不等同于对已发布业务代码完成隔离验证**。

## 4. 数据分类与实施规则

| 内容 | `Y` | `N` |
| --- | --- | --- |
| 页面布局、组件、表格列定义、标题、字段类型、空白模板、固定枚举 | 共享 | 共享 |
| 从业务记录派生的账号、SKU、人员等动态筛选项 | 当前访问者可见数据派生 | 依据站点共享数据派生 |
| OPS 实时结果 | 当前访问者 Token 取数，不持久化时不额外处理 | 同左 |
| 第三方实时结果 | 保持现有请求级取数；持久化后按下行处理 | 同左 |
| 业务记录、OPS/第三方快照、跨源加工和报表结果 | 当前访问者私有 | 站点成员共享 |
| 个人输入、查询历史、收藏、备注及个人配置 | 当前访问者私有 | 仍为个人私有 |
| 业务缓存、异步任务、下载文件和导出结果 | 按其所含业务数据的用户范围隔离 | 按实际共享/个人来源限定范围 |

`Y` 复用 `get_current_user` 与可信 `owner_user_id`：业务表创建、读取、更新、删除、聚合、唯一约束、幂等键、缓存键和任务复用均纳入归属；详情及下载接口不能通过猜测 ID 越权。缺少稳定用户 ID 时，线上私有读写失败关闭；不可回退到邮箱、创建人数据或全站共享数据。用户身份不接受请求体、查询参数或浏览器自报。前端只请求本站 `/api`。

`N` 的共享业务数据必须由项目明确实现共享写入、刷新和覆盖权限；不能让任一访问者用本人受限 OPS 结果无意覆盖创建人的共享结果。个人行为数据不转为共享。当前 `ops-app-data-builder` 中第三方快照和 OPS 加工结果一律私有的规则，需要仅为明确选择 `N` 的**新建标准站点**补充共享业务数据例外，其他项目沿用现有私有约定。

Codex 提供的 Excel/JSON 按内容而非扩展名划分。结构与空白模板可作为共享源码资产；真实业务条目在 `Y` 模式不得进入前端 bundle、`public`、源码 JSON、空白模板库或无鉴权静态路径。需要保留创建人初始记录时，通过站点业务导入入口写入创建人的私有存储；其他用户须用自己的授权取数或导入建立其数据。混合文件先拆出结构与业务条目，不做无依据的通用自动分类。

## 5. 交付验收

1. CLI 缺少选择值拒绝标准新建，`Y/N` 均进入创建意图与 AppHub 注册表；迁移与旧站点为 `N`。
2. Y 站点访问权限弹窗不显示共享提示；N/无标记显示；切换应用或账号不短暂展示上一个应用的结论。
3. A/B 两个真实身份验证 Y：A/B 各自读取、编辑、搜索、聚合、刷新、下载和导出均只触及自己的业务数据；B 无数据仍能打开完整页面并见空状态；动态筛选项不泄露 A 的记录。
4. 检查 Y 站点仓库、前端产物及公开静态路径中没有私有业务记录；伪造 `owner_user_id` 请求参数不能改变归属。
5. N 站点的明确共享业务数据对授权成员可见；未获站点访问权限者仍不能进入；个人历史仍私有。
6. 发布顺序为 AppHub 先接受标记并返回面板字段，再发布新版 opscli/Skill，最后更新标准模板并以新站点做 A/B 验证。若某项目的数据产品无法满足隔离验收，不得仅凭 Y 标记宣称数据已隔离。

## 6. 实施边界

AppHub 站点负责人/平台管理员现有源码与数据库管理能力不属于普通站点页面访问。Y 的承诺限于普通访问者经站点页面及业务 API 读取的数据；更强的管理员不可见要求需单独修改平台管理权限。

Y/N 创建后不在访问权限弹窗切换；修改已创建站点的策略不属于本期。
