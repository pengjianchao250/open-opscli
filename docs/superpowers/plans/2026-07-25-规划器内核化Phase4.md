# 规划器内核化（Phase 4）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `ops-dataset-query` Skill 的取数规划器（5 文件约 165KB）迁入 opscli 内核，暴露为 `opscli query plan` / `opscli query flow` CLI 命令与 MCP `query_plan` / `query_flow` 工具，数据源从 Skill `data/*.csv` 改为后端 `query-metadata?include_all_fields=1`（经用户级元数据缓存），实现彻底解耦（A 方案）。

**Architecture:** 迁移型工作，不是全新开发。核心策略：把规划器"读 CSV → 行字典"的数据源层替换为一个**元数据适配器**（`metadata_adapter`），它把 `QueryManager.metadata_all()` 的 JSON payload 映射为与 `scoped_dataset_reader` **完全同形的行字典**（含去重/快照一致性/filter_config 解析），从而下游选表/字段指导/schema linking 逻辑**近乎逐字移植**。3 处 `subprocess opscli` 换为内核内部调用。`intent_rules.json` + `query_plan.schema.json` 打包为内核静态资源。安全网是**回归对拍**：迁移前后对同一批请求产出的规划合同关键字段必须一致。

**Tech Stack:** Python 3.10+；标准库 + `importlib.resources`（静态资源）；复用 `opscli.query.services.manager.QueryManager`（`metadata_all` / `build_simple_and_run`）、`opscli.query.services.metadata_cache`；测试 `pytest` + `respx` + `tmp_path`；回归对拍对本地后端 `http://ops.cm/api` 验证。

## Global Constraints

- Python >= 3.10；所有代码注释与 docstring 用中文（技术术语可保留英文）（铁律17）。
- 依赖方向：`opscli.query` 不得 import `opscli.mcp`；规划器包只依赖 `opscli.query.*` + `opscli.config` + `opscli.shared` + 标准库（铁律2）。
- 迁移**不得改变规划合同语义**：`query_plan_model_contract_v2` 的 `model_view` / `answer_contract` / `execution_ref` 结构与字段值必须与旧 Skill 规划器对同一输入一致（回归对拍为准）。
- 3 处 subprocess 换内部调用后，失败回退语义保持（内嵌 recovery_command / 手动路径，不阻塞）。
- 静态资源 `intent_rules.json` 校验保持 fail-fast（`schema_version==3`，根键/domains/slots 精确匹配）。
- 测试用 `tmp_path` + `respx`，不碰真实网络/Keychain；回归对拍脚本可对 `http://ops.cm/api` 打真实本地后端（需本地登录态）。
- 迁移期间**旧 Skill 脚本保持可用**，不删除 `scripts/`，直到 CLI/MCP 入口验收通过并切换 SKILL.md 入口。
- 依赖前置：**Phase 0（后端 `include_all_fields` + `snapshot_metric`/`has_formula_config`）已在本地 ops.cm 验收通过**；远程生产验证待部署。

**范围边界（本计划不做）**：后端 Phase 0（已完成）；用户级元数据缓存基础设施（已合入 release）；chart 异常分析 / Excel 导出的内核化（属另一支线，独立计划）。

```python
"""规划器内核入口：组装缓存/适配器/规划器/执行。"""
from __future__ import annotations
from pathlib import Path
from opscli.query.services.manager import QueryManager
from opscli.query.services.metadata_cache import invalidate_metadata_cache
from opscli.query.services.planner.metadata_adapter import MetadataAdapter
from opscli.query.services.planner import query_plan


def _build_adapter(qm: QueryManager, user_email: str, base_dir: Path | None) -> MetadataAdapter:
    result = qm.metadata_all(user_email=user_email, base_dir=base_dir)
    return MetadataAdapter(result.payload)


def run_plan(request: str, *, user_email: str, base_dir: Path | None = None,
             top_n: int | None = None) -> dict:
    """自然语言请求 → query_plan_model_contract_v2。"""
    qm = QueryManager()

    def refresh_fn():
        # 元数据未就绪：失效缓存并重取全量
        invalidate_metadata_cache(base_dir=base_dir, user_email=user_email)
        return qm.metadata_all(user_email=user_email, base_dir=base_dir).payload

    def enum_fn(component_table_id, **kw):
        # 权限枚举：复用内核 simple 查询（替代 subprocess opscli query simple）
        return qm.build_simple_and_run(table_id=component_table_id, **kw)

    adapter = _build_adapter(qm, user_email, base_dir)
    return query_plan.build_model_query_plan(
        adapter, request, refresh_fn=refresh_fn, enum_fn=enum_fn, top_n=top_n
    )


def run_flow(request: str, *, user_email: str, base_dir: Path | None = None,
             result_dir: Path | None = None) -> dict:
    """一体化：规划 + planned 时直接执行原始模板。"""
    contract = run_plan(request, user_email=user_email, base_dir=base_dir)
    if contract.get("status") != "planned":
        return contract  # clarify/blocked/chart_uuid 交由调用方处置
    qm = QueryManager()
    exec_ref = contract.get("execution_ref", {})
    # 按 execution_ref.query_template 执行（对齐旧 run_query.py：完整性校验由 build_model_query_plan 内已绑定）
    run_result = qm.run_query_template(exec_ref)  # 见 Task 6 说明
    return {**contract, "result": run_result}
```

> 说明：`qm.run_query_template(exec_ref)` 若 `QueryManager` 无对应方法，则在本任务同时新增一个薄方法：按 `execution_ref` 的 table_id/dimensions/metrics/filters/time_scope/data_comparison 调 `build_simple_and_run`，等价旧 `run_query.py` 的执行段（含 orderBy 兜底可后续补）。Step 3 需实现该方法并单测。
