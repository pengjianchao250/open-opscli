# 新品计算器 Skill 优化实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 `ops-new-product-calculator` 重构为核心路由加两个按需参考文件，并补齐 `show`、`copy` 与三类任务入口的测试契约。

**Architecture:** `SKILL.md` 只保留所有场景共享的触发、路由、认证和安全门禁；草稿字段细节迁移到 `references/draft-workflow.md`，任务结果细节迁移到 `references/result-workflow.md`。测试从主文件和参考文件分别验证职责边界，并继续用真实 `validate_draft_data()` 校验 JSON 示例。

**Tech Stack:** Markdown、Python 3.10+、pytest、`opscli.calculator.draft.validate_draft_data`

## Global Constraints

- 不修改 `opscli/calculator/` 下的 CLI 或业务实现。
- 不修改 `opscli/skills/templates/ops-new-product-calculator/data/VERSION.json`，保持 `v0.0.1`。
- 不执行 `opscli calculator submit`，不创建真实试算任务。
- frontmatter 只保留 `name`、`description`。
- 主 `SKILL.md` 目标不超过 220 行。
- 非认证类 `opscli` 失败、认证处理、提交确认和敏感信息保护规则不得弱化。

```python
def _reference_text(path: Path) -> str:
    assert path.exists(), f"缺少参考文件：{path}"
    return path.read_text(encoding="utf-8")


def _full_skill_text() -> str:
    text = _skill_text()
    for path in (DRAFT_REFERENCE, RESULT_REFERENCE):
        if path.exists():
            text += "\n" + path.read_text(encoding="utf-8")
    return text
```
