## 一、目标与范围

一期目标是在现有 `opscli auth` 能力基础上，打通 AI 取数底座的最小闭环：

1. auto-scheduler 提供带权限校验的 `cli-query` 查询代理接口
2. auto-scheduler 提供用户态字段搜索导出 `skill/export`
3. auto-scheduler 新增可执行查询元数据接口 `query-metadata`
4. auto-scheduler 提供 `manifest/publish` 版本发布能力
5. opscli 新增 `skills` 命令组，支持安装、扫描、升级、状态检查
6. dataset-fields Skill 可基于本地缓存搜索字段，并通过 `opscli query` 辅助构造与执行查询

**不在一期范围：**

- AI 自动生成完整业务查询 DSL 的智能编排策略
- 高级 comparison 算法在 Skill 侧的自动生成器
- 增量同步、差量发布、回滚管理界面
- 非 Claude Code / OpenClaw 的完整多工具适配实现

## 二、实施原则

### 2.1 总体策略

- 保持 `skill/export` 的 13 列 CSV 稳定，不破坏已有 Skill 搜索兼容性

## 六、风险与注意事项

| 风险 | 说明 | 应对 |
|------|------|------|
| `default_endpoint` 不足以表达 `from.table` | 部分数据集可能需要 QueryBuilder 现有配置恢复 | 在模块 C 引入 `from_table` Resolver |
| `permission` 字段格式不统一 | `dm_tables.permission` 可能存在空值或非数组 JSON | Service 层做标准化 |
| 默认聚合函数难以可靠推导 | 某些指标不能简单映射 `SUM/AVG` | 返回 `null`，要求调用方显式指定 |
| `translate` 映射缺失 | 过滤字段不一定能自动推导 | 一期先维护白名单映射表 |
| 跨项目联调成本高 | auto-scheduler 与 opscli 不在同一仓库 | 先完成接口契约，再分阶段联调 |
