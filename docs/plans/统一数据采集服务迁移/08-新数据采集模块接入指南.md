# 新数据采集模块接入统一 MCP 服务指南

## 1. 目的

本文定义新数据采集模块接入 `opscli-collector-mcp` 的准入条件、代码契约、测试、迁移和交付物。

“统一数据采集服务”是受控部署边界，不是所有 HTTP 或第三方 API 模块的默认归宿。未经评审不得仅在注册表追加一行后上线。

## 2. 准入判断

满足以下一项或多项，可考虑接入：

- 使用浏览器自动化、Cookie、验证码或本地 Profile；
- 调用第三方数据采集接口，具有账号、额度或反爬限制；
- 任务耗时长，需要异步队列和状态查询；
- 生成较大结果文件，需要持久化和上传；
- 依赖与通用 MCP 不同的网络、系统包或故障治理；
- 需要与通用 MCP 隔离发布和资源。

不应直接接入：

- 纯计算、无外部依赖的短时 Tool；
- 通用认证、配置、技能或数据查询能力；
- 仅供开发调试的抓包、绕过、账号管理工具；
- 依赖与现有 Bundle 冲突且无法隔离的模块；
- 必须多实例但状态尚未外置的模块；
- 无法声明数据、Secret、并发和回滚边界的模块。

## 3. 接入前决策记录

模块负责人提交以下信息：

| 项目 | 内容 |
|---|---|
| Bundle ID | 稳定 snake_case 标识 |
| Tool 前缀 | 例如 `future_collector_` |
| 业务范围 | 公开能力和明确非目标 |
| CLI | 现有/新增命令面及兼容要求 |
| 第三方依赖 | 域名、协议、账号和限流 |
| Python/System 依赖 | extra、浏览器、系统包、字体 |
| Secret | 来源、权限、缓存、轮换和脱敏 |
| 状态 | 数据库、Profile、结果、锁和缓存 |
| 并发 | 实例、Worker、账号和任务互斥 |
| 外部副作用 | 是否创建远端任务，幂等键是什么 |
| 额度 | 扣减时机、退回、查询和重置 |
| 健康 | ready/degraded/draining 判断 |
| 停写 | 哪些 Tool 禁止、哪些查询保留 |
| 迁移 | 旧入口、数据和客户端切流 |
| 回滚 | 权威数据和恢复方向 |
| 资源 | CPU、内存、磁盘、网络和峰值 |

## 4. Tool 设计

### 4.1 命名

所有公开 Tool 使用 Bundle 前缀：

```text
<bundle_prefix>spec_must_read
<bundle_prefix>scenarios
<bundle_prefix>run
<bundle_prefix>job_status
<bundle_prefix>export
```

不是所有模块都必须复制 SellerSprite 的 Tool 结构，应按业务协议设计，但名称必须全局唯一且边界明确。

### 4.2 提交与状态

长任务推荐：

```text
submit/run → 立即返回持久 job_id
status     → 查询，不重复提交
result     → 读取最终业务结果
export     → 返回 HTTPS 文件信息
```

必须定义：

- 顶层 Tool 成功与后台业务完成的区别；
- pending 和终态；
- 状态等待上限；
- 重复提交和幂等策略；
- 扣额度时机；
- 外部远程任务续查；
- 任务所有权和批量授权语义。

### 4.3 禁止公开

默认禁止：

- 账号密码绑定和展示；
- 删除、重排全部任务；
- 任意文件读取、任意输出路径；
- 浏览器 debug、抓包和原始 Cookie；
- 运行任意 URL 或脚本；
- 关闭其他 Bundle 或整个服务；
- 返回服务器绝对路径和 Secret。

管理员能力保留本地 CLI，并明确只能在服务主机执行。

## 5. Tool Bundle 实现

目标 Bundle 契约至少提供：

```python
CollectorToolBundle(
    bundle_id="future_collector",
    tool_prefix="future_collector_",
    register=register_public_tools,
    lifespan_factory=module_lifespan,
    health_check=module_health,
    required_env=(...),
    persistent_paths=module_persistent_paths,
    single_worker_required=False,
)
```

### 5.1 注册函数

- 只注册公开 Tool；
- 无 import-time 文件、数据库、网络或浏览器副作用；
- Tool schema 具有清晰类型和中文说明；
- 错误走共享稳定信封；
- Tool 注册后全部符合声明前缀；
- 由注册表校验重名和禁止清单。

### 5.2 生命周期

启动：

1. 校验配置和目录；
2. 初始化轻量状态；
3. 恢复持久队列；
4. 启动模块 supervisor/worker；
5. 达到 ready 后接受提交。

关闭：

1. 进入 draining；
2. 停止领取新任务；
3. 有界等待执行；
4. 关闭浏览器/连接/协程；
5. 保留持久状态。

后台协程不得继承某个请求的 MCP 身份上下文。

### 5.3 健康检查

健康结果使用稳定、脱敏结构，至少检查：

- 配置是否完整；
- 持久目录是否可写；
- 队列和数据库；
- 关键第三方依赖；
- worker/scheduler；
- 文件上传能力。

健康检查不能产生昂贵业务请求、扣额度或修改第三方数据。

## 6. 状态目录和密钥

新 Bundle 默认使用：

```text
CONFIG_DIR/collector/<bundle_id>/
├── state/
├── profiles/
└── outputs/
```

规则：

- 数据库与其他 Bundle 分离；
- 每种密文使用明确对应密钥；
- 不复用 SellerSprite 绑定密钥；
- 不把 Session/JWT/密码写任务队列；
- 绝对路径不接受客户端输入；
- 结果保留、清理和补传策略明确；
- 提供一致性备份和恢复验证。

如果必须使用共享 `credentials_by_key` 或 quota，要说明隔离 key、迁移和回滚影响。

## 7. 认证、权限和所有权

模块接入共享认证链：

```text
API Key
  → verify-key
  → 已验证用户身份和 Tool 白名单
  → API Key + clientInfo.name 隔离凭证
  → 模块业务 Tool
```

要求：

- 身份缺失时失败关闭；
- 不信任 Tool 参数中的邮箱；
- 不从客户端透传本机 Session/JWT；
- 任务入队原子记录所有权；
- 单任务和批量查询先完成授权；
- 不通过错误类型泄露其他用户 job 是否存在；
- 后台任务重新加载非敏感凭证作用域并校验预期用户。

## 8. 额度设计

每个收费/限额 Tool 声明：

- 服务和 Tool 额度 key；
- 身份维度；
- 每日/周期限制；
- 何时预占；
- Tool/业务失败是否退回；
- 专属账号或特殊用户策略；
- 状态、结果和导出是否免费；
- 存储不可用时失败关闭还是降级。

不能复用 `seller_sprite_run` 的额度 key 表示其他业务。

## 9. 并发与资源

声明：

- 是否支持多实例；
- 是否支持多 Uvicorn Worker；
- SQLite/文件锁/浏览器是否进程安全；
- 单账号是否串行；
- 最大任务并发；
- 超时和取消语义；
- CPU、内存、磁盘和子进程峰值；
- 与现有 SellerSprite Bundle 共同运行的容量测试。

若 `single_worker_required=true`，必须说明这会限制整个统一服务。评审需判断是否接受，还是先外置状态或使用独立部署 Profile。

## 10. Remote Adapter 和 CLI

业务 CLI 继续保持自己的命令组，通过 Remote Adapter 调用 Tool：

```python
super().__init__(
    preferred_name="BI运营系统",
    require_preferred=True,
)
```

要求：

- 通用 MCP URL 和用户 API Key 来自 OPS 配置中心；
- CLI 不发现或配置 Collector 地址；
- 严格选择 `BI运营系统`，不回退；
- 401 重新获取配置最多重试一次；
- 参数映射有单元测试；
- 不透传 Session/JWT；
- CLI help 明确异步和状态语义；
- 本地管理员命令与远端用户命令清晰区分。

## 11. 配置中心和权限

接入时同步：

1. 通用 MCP 已配置 Collector 内部 URL，并注册新增模块的代理 Tool；
2. 通用 MCP 和 Collector 的 Tool Catalog 均包含新增 Tool；
3. 后端可按用户/角色授权新 Tool；
4. 未授权用户不可发现或调用敏感 Tool；
5. 灰度用户先获得 Tool 权限；
6. 其他用户和现有 Bundle 权限不变；
7. 回滚时可撤销该 Bundle Tool 权限而不移除整个服务。

## 12. 测试门槛

### Bundle 契约

- Bundle ID、前缀和 Tool 集合；
- 未注册 admin/debug Tool；
- import 无副作用；
- 生命周期启动/关闭；
- 健康状态转换；
- draining 阻止提交保留查询；
- 持久路径位于模块根目录。

### 安全与隔离

- 未认证和未授权拒绝；
- 用户任务所有权；
- 批量接口不泄露失败位置；
- Secret、路径和 API Key 日志脱敏；
- 任意输出路径和文件访问被拒绝；
- Bundle 不修改其他模块状态。

### 业务

- 成功、失败、超时、重试和幂等；
- 队列重启恢复；
- 第三方账号失效；
- 额度预占和退回；
- 导出 HTTPS URL；
- 旧 CLI 兼容。

### 服务集成

- 与 SellerSprite 同进程运行；
- Tool 无重名；
- Profile 和权限清单正确；
- 资源峰值在预算内；
- 一个模块 degraded 不破坏其他模块；
- 服务重启按顺序关闭和恢复。

## 13. 上线流程

1. 合并代码和文档，但 Profile 暂不启用 Bundle；
2. 构建包含依赖的固定版本；
3. 测试环境启用 Bundle；
4. 完成状态迁移演练和回滚演练；
5. 生产 Profile 启用 Bundle，但不开放用户权限；
6. 无流量验证 Tool、健康和依赖；
7. 旧入口模块级 draining、排空和备份；
8. 恢复模块私有状态；
9. 灰度 Tool 权限和 Remote Adapter 路由；
10. 验证后全量；
11. 回滚窗口结束后从旧入口移除 Tool；
12. 更新运维告警和备份任务。

## 14. 回滚要求

模块上线前必须回答：

- 如何只停止该 Bundle 提交；
- 如何保持状态和结果查询；
- 哪些任务可以重放；
- 如何避免重复第三方副作用；
- 最新权威数据在哪一端；
- 是否涉及共享 quota/CredentialStore；
- 如何恢复旧入口而不影响其他 Bundle；
- 如何撤销该模块 Tool 权限；
- 回滚后如何查询迁移期间 job ID。

不能提供模块级回滚的 Bundle 不得上线统一服务。
