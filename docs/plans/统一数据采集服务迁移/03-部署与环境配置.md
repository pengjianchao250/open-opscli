# 统一数据采集 MCP 服务部署与环境配置

> `opscli-collector-mcp` 是目标命令，当前基线尚未实现。本文以首期只启用 SellerSprite Bundle 的 Linux 单机部署为例。

## 1. 部署模型

```text
同一个 aukeys-opscli Wheel
├── 通用服务器：opscli-mcp
└── 数据采集服务器：opscli-collector-mcp
```

| 项目 | 首期要求 |
|---|---|
| Python | 3.10 及以上，与发布 Wheel 支持范围一致 |
| 包版本 | 使用经过批准的固定版本 |
| 服务进程 | 1 个实例、1 个 Uvicorn Worker |
| 运行用户 | 独立低权限用户，例如 `opscli` |
| 内部传输 | Streamable HTTP `/mcp` |
| 网络入口 | 仅允许通用 MCP 访问的内网域名或内网 IP |
| 持久化 | 单个服务器持久卷，内部按 Bundle 分目录 |
| 首期 Bundle | `seller_sprite` |
| 浏览器 | Patchright/Chrome；无桌面 Linux 使用 Xvfb |

统一服务中只要一个 Bundle 要求单 Worker，整个服务都必须单 Worker。首期 SellerSprite 明确具有该约束。

## 2. 目录规划

当前 `CONFIG_DIR` 固定为 `Path.home() / ".config" / "opscli"`。在配置根目录覆盖能力实现前，通过固定服务用户的 `HOME` 保证路径稳定：

```env
HOME=/var/lib/opscli
```

建议目录：

```text
/opt/opscli/
├── venv/
└── releases/

/etc/opscli/
└── collector.env

/var/lib/opscli/
└── .config/opscli/
    ├── credentials_by_key/          # 服务公共隔离凭证
    ├── mcp_quota/quota.sqlite3      # 当前共享 quota 仓储
    ├── seller_sprite/               # SellerSprite 兼容现有路径
    │   ├── task_queue.sqlite3
    │   ├── account_bindings.sqlite3
    │   ├── .account_bindings.key
    │   ├── browser_profiles/
    │   └── api_runs/
    └── collector/                     # 后续新 Bundle 默认根目录
        └── <bundle_id>/
            ├── state/
            ├── profiles/
            └── outputs/
```

首期不强制把 SellerSprite 从现有目录移动到 `collector/seller_sprite/`，避免同时引入路径迁移。新 Bundle 应直接使用统一模块根目录规范。

权限建议：

```bash
install -d -o opscli -g opscli -m 0700 /var/lib/opscli
install -d -o opscli -g opscli -m 0700 /var/lib/opscli/.config/opscli
install -d -o root -g opscli -m 0750 /etc/opscli
install -o root -g opscli -m 0640 /dev/null /etc/opscli/collector.env
```

## 3. 安装依赖

安装同一个项目包并启用生产 Profile 所需 extra：

```bash
python3 -m venv /opt/opscli/venv
/opt/opscli/venv/bin/pip install "aukeys-opscli[seller-sprite]==<approved-version>"
/opt/opscli/venv/bin/python -m patchright install chrome
```

SellerSprite 还需要：

- Chrome/Chromium 系统依赖；
- Xvfb；
- 字体和 CA 证书；
- SQLite 命令行工具；
- 足够的 `/dev/shm`、内存和磁盘；
- OCR 依赖所需运行库。

安装和浏览器启动必须用 `opscli` 服务用户验证。

### 3.1 后续 Bundle 依赖规则

新 Bundle 必须在接入文档中声明：

- Python extra 和固定依赖范围；
- 浏览器/runtime 类型；
- 系统包、字体和证书；
- CPU、内存、磁盘和并发预算；
- 是否增加镜像体积或启动时间；
- 与已启用 Bundle 的版本冲突。

生产镜像只安装 Profile 实际启用 Bundle 的依赖。不能为了“以后可能使用”把所有 debug 和浏览器依赖无限叠加。

## 4. 配置分层

### 4.1 服务级公共配置

服务级配置负责：

- 服务 Profile；
- OPS API Key 校验地址；
- 监听地址和端口；
- 传输模式；
- 公共 quota 存储；
- 日志、遥测和文件上传；
- Bundle 白名单和健康聚合策略。

目标示例：

```env
HOME=/var/lib/opscli
OPSCLI_COLLECTOR_PROFILE=production
OPSCLI_COLLECTOR_BUNDLES=seller_sprite
OPSCLI_MCP_QUOTA_ENABLED=1
OPSCLI_MCP_QUOTA_SQLITE_PATH=/var/lib/opscli/.config/opscli/mcp_quota/quota.sqlite3
```

其中 `OPSCLI_COLLECTOR_PROFILE` 和 `OPSCLI_COLLECTOR_BUNDLES` 是目标设计，当前代码尚未读取。生产环境更推荐 Profile 在版本控制中固定 Bundle；若提供环境变量覆盖，必须校验其值是 Profile 允许集合的子集，不能加载任意 Python 模块。

通用 MCP 另行配置 Collector 内部地址：

```env
OPSCLI_COLLECTOR_MCP_URL=https://collector-mcp.internal.example.com/mcp
```

该地址不包含共享 `api_key`，也不下发给 CLI 或 MCP Host。

### 4.2 SellerSprite 模块配置

```env
OPSCLI_SELLER_SPRITE_MODE=browser-route
OPSCLI_SELLER_SPRITE_OUTPUT_DIR=/var/lib/opscli/.config/opscli/seller_sprite/api_runs
OPSCLI_SELLER_SPRITE_BROWSER_PROFILE_DIR=/var/lib/opscli/.config/opscli/seller_sprite/browser_profiles
OPSCLI_SELLER_SPRITE_PAGE_SIZE=100
OPSCLI_SELLER_SPRITE_ACCOUNT_CACHE_TTL_SECONDS=600
OPSCLI_SELLER_SPRITE_TASK_TIMEOUT_SECONDS=600
OPSCLI_SELLER_SPRITE_BROWSER_RUNTIME=patchright
OPSCLI_SELLER_SPRITE_BROWSER_CHANNEL=chrome
OPSCLI_SELLER_SPRITE_BROWSER_HEADLESS=false
OPSCLI_SELLER_SPRITE_BROWSER_PAGE_PREPARE=true
OPSCLI_SELLER_SPRITE_BROWSER_TASK_INTERVAL_SECONDS=5
OPSCLI_SELLER_SPRITE_BROWSER_COOLDOWN_SECONDS=10
OPSCLI_SELLER_SPRITE_BROWSER_IDLE_TTL_SECONDS=1800
OPSCLI_SELLER_SPRITE_BROWSER_MAX_LIFETIME_SECONDS=21600
OPSCLI_SELLER_SPRITE_BROWSER_CAPTCHA_OCR_ENABLED=true
OPSCLI_SELLER_SPRITE_BROWSER_CAPTCHA_OCR_MAX_ATTEMPTS=2
```

`browser_headless=false` 是当前默认值；无显示环境由 browser-route 尝试启动 Xvfb。应以实际服务器验证为准。

### 4.3 Secret

服务 Secret：

- OPS 远程 API Key 校验所需配置；
- 文件上传服务认证配置；
- 遥测所需认证配置。

SellerSprite Secret：

```env
INTEGRATION_ACCOUNT_ENCRYPT_KEY=<secret>
```

公共账号优先从 OPS 集成账号接口获取。仅作为临时兜底时使用：

```env
OPSCLI_SELLER_SPRITE_ACCOUNTS=<secret-json-array>
```

要求：

- Secret 不写镜像、Git、命令行和普通日志；
- 不同 Bundle 的业务密钥分别管理；
- 不因统一部署复用不相关的加密密钥；
- 专属账号密码通过本地隐藏输入写入绑定库，不放环境变量；
- Secret 轮换必须评估已排队任务和缓存会话。

## 5. 启动命令

目标命令：

```bash
opscli-collector-mcp \
  --transport http \
  --host 127.0.0.1 \
  --port 8766 \
  --auth-verify-url https://ops.example.com/api/v1/mcp/verify-key
```

服务启动时应输出脱敏信息：

- 服务 ID 和版本；
- Profile 名；
- 已启用 Bundle ID；
- 实际公开 Tool 数量；
- 单 Worker 约束；
- 持久目录是否可写；
- 不输出完整 URL Query、API Key、账号或内部凭证。

## 6. systemd 示例

```ini
[Unit]
Description=opscli Collector MCP
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=opscli
Group=opscli
WorkingDirectory=/var/lib/opscli
EnvironmentFile=/etc/opscli/collector.env
ExecStart=/opt/opscli/venv/bin/opscli-collector-mcp --transport http --host 127.0.0.1 --port 8766 --auth-verify-url https://ops.example.com/api/v1/mcp/verify-key
Restart=on-failure
RestartSec=5
TimeoutStopSec=120
UMask=0077
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

约束：

- 不增加 `--workers`；
- 不用 Gunicorn 多 Worker；
- 同一持久卷不能由第二个服务实例写入；
- `TimeoutStopSec` 覆盖 Bundle 有界关闭；
- 浏览器安全沙箱与 systemd hardening 选项需实际验证，不能直接照搬导致 Chrome 无法启动。

## 7. 内网 HTTPS 反向代理

Collector 与通用 MCP 不同服务器时，可使用仅内网可达的 Nginx：

```nginx
log_format mcp_safe '$remote_addr - $request_method $uri $status $body_bytes_sent';

server {
    listen 443 ssl;
    server_name collector-mcp.internal.example.com;

    access_log /var/log/nginx/collector-mcp.access.log mcp_safe;

    location /mcp {
        proxy_pass http://127.0.0.1:8766;
        proxy_http_version 1.1;
        proxy_buffering off;
        proxy_read_timeout 180s;
        proxy_send_timeout 180s;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

安全要求：

- 使用 `$uri`，禁止记录包含 Query 的 `$request_uri` 或 `$request`；
- Uvicorn 只监听回环地址；
- 仅暴露批准的 MCP 和健康端点；
- APM、tracing 和错误页也要脱敏 Query/Header；
- 客户端支持时优先 Bearer API Key；
- TLS、证书和防火墙遵循公司基线；防火墙仅放行通用 MCP 来源。

## 8. 网络依赖

服务级依赖：

| 目标 | 用途 |
|---|---|
| OPS `verify-key` | 校验 MCP API Key 和恢复身份 |
| OPS 登录/Token 接口 | 建立隔离 OPS 凭证 |
| 文件上传接口 | 生成用户可访问的 HTTPS URL |
| DNS/NTP | 域名、Token 和额度时间一致性 |

SellerSprite 模块依赖：

| 目标 | 用途 |
|---|---|
| OPS 集成账号接口 | 获取公共 SellerSprite 账号 |
| SellerSprite 域名和静态资源 | 登录、查询和 Listing Analysis |

后续 Bundle 的域名白名单必须单独声明，不使用“允许全部公网”替代依赖清单。

## 9. 资源预算

统一服务需要同时计算全部 Bundle 的预算：

```text
服务内存预算 = MCP 基础开销 + 各 Bundle 常驻开销 + 最大并发任务峰值
服务磁盘预算 = 各 Bundle 状态 + Profile + 结果 + 临时文件 + 备份缓冲
```

首期重点监控：

- Chrome 子进程数量和 RSS；
- Xvfb 状态；
- SellerSprite 工作账号槽；
- SQLite 锁等待；
- `api_runs` 增长；
- 文件上传积压；
- 服务进程 FD 和子进程数。

新 Bundle 不得在没有容量评估的情况下与 SellerSprite 共享生产实例。

## 10. 文件上传要求

所有 Bundle 的生产导出统一要求：

1. 文件先落模块私有持久目录；
2. 上传到受控文件服务；
3. 对外响应使用 HTTPS URL；
4. 不向普通用户展示服务器绝对路径；
5. 上传失败保留本地文件、产生告警并支持补传；
6. 每个 Bundle 声明保留期和清理规则。

SellerSprite 当前可能回退 `file://`，上线前必须按目标设计收紧。

## 11. 启动前检查

```bash
sudo -u opscli test -w /var/lib/opscli/.config/opscli
sudo -u opscli test -r /etc/opscli/collector.env
sudo -u opscli /opt/opscli/venv/bin/python -c "import opscli; import patchright"
```

并验证：

- Profile 只启用批准 Bundle；
- Tool Catalog 与预期一致；
- 未认证请求返回 401；
- 合法测试 Key 可读取服务信息和模块健康；
- SellerSprite 场景查询成功；
- Chrome/Xvfb 由服务用户启动；
- 重启不丢持久数据；
- 第二实例或第二 Worker 被拒绝；
- 文件上传返回 HTTPS URL。

数据迁移见[状态数据迁移方案](04-状态数据迁移方案.md)。
