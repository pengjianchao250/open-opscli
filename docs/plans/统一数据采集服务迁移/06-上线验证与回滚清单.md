# 统一数据采集 MCP 服务上线验证与回滚清单

> 首次上线只迁移 SellerSprite Bundle。服务级框架与 SellerSprite 模块级验收必须同时通过，其他数据采集模块不随本次切流。

## 1. 上线原则

1. 服务框架和业务 Bundle 分层验证。
2. 每次只迁移一个 Bundle，避免同时改变多个状态源。
3. 同一 Bundle 同一时刻只能有一个权威写入者和消费者。
4. 先停止新提交，再排空、备份、恢复和切流。
5. 服务路由、Tool 权限和状态数据必须同步切换。
6. 模块回滚不能覆盖其他 Bundle 的最新数据。
7. 配置中心变更、服务版本和数据权威位置均需记录。

## 2. 服务级上线前检查

### 2.1 代码与发布

- [ ] 共享 MCP App Factory 已实现并通过回归测试。
- [ ] `opscli-collector-mcp` 入口已注册。
- [ ] Collector Service Profile 使用版本控制中的生产白名单。
- [ ] Tool Bundle 注册表不做自动扫描。
- [ ] 未知 Bundle、重复 ID、Tool 重名和越界前缀会阻止启动。
- [ ] 管理员和 debug Tool 未公开。
- [ ] 通用 MCP 的 Collector 内部路由已实现，缺失或不可用时不回退本地执行。
- [ ] API Key 鉴权、Tool 权限、额度、遥测和错误信封测试通过。
- [ ] 服务级和模块级健康检查已实现。
- [ ] 模块级 `draining` 能阻止提交并保留查询。
- [ ] 单 Worker 约束会从 Bundle 聚合到服务启动校验。
- [ ] 已保留回滚版本和安装包。

### 2.2 环境

- [ ] 新服务器固定一个服务实例、一个 Worker。
- [ ] 持久卷和模块私有目录已创建。
- [ ] 服务用户、目录属主和权限正确。
- [ ] HTTPS、证书、代理超时和防火墙生效。
- [ ] 代理、APM 和 tracing 不记录 Query API Key。
- [ ] OPS `verify-key`、登录、文件上传、DNS 和 NTP 可用。
- [ ] Profile 实际 Bundle 清单与批准内容一致。
- [ ] CPU、内存、磁盘和子进程预算已配置告警。
- [ ] 第二实例或第二 Worker 会被部署配置及启动校验拒绝。

## 3. SellerSprite 模块上线前检查

### 3.1 运行环境

- [ ] Patchright、Chrome、Xvfb、字体和 OCR 依赖已安装。
- [ ] 使用 `opscli` 服务用户完成浏览器启动测试。
- [ ] `INTEGRATION_ACCOUNT_ENCRYPT_KEY` 与现网一致。
- [ ] OPS 集成账号接口和 SellerSprite 网络连通。
- [ ] SellerSprite Bundle Tool 集合与批准清单一致。
- [ ] 绝对 `output_dir` 已拒绝或被约束到模块根目录。
- [ ] 文件上传返回 HTTPS URL。

### 3.2 数据准备

- [ ] 旧端 `CONFIG_DIR` 已确认。
- [ ] 队列、绑定库、绑定密钥、quota、凭证、Profile 和结果已盘点。
- [ ] 三个 SQLite 的 schema 和完整性已记录。
- [ ] 专属账号绑定数量及脱敏摘要已记录。
- [ ] 当前 SellerSprite quota 快照已记录。
- [ ] 未完成 Listing Analysis job ID 已登记。
- [ ] 备份恢复已在演练目录成功执行。
- [ ] 新旧绝对路径一致，或路径迁移脚本已验证。

## 4. SellerSprite 停写与排空

### 4.1 停写

将旧入口 SellerSprite 模块设为 `draining`：

- [ ] 禁止 `seller_sprite_run`。
- [ ] 禁止 `seller_sprite_listing_analysis_submit`。
- [ ] 状态、结果和导出仍可访问。
- [ ] 其他通用 MCP Tool 不受影响。
- [ ] 记录停写时间和配置版本。
- [ ] 配置中心尚未让普通用户访问新 Bundle。

### 4.2 排空

```bash
opscli seller-sprite queue status
opscli seller-sprite queue list --state queued --limit 500
opscli seller-sprite queue list --state running --limit 500
```

- [ ] `queued=0`。
- [ ] `running=0`。
- [ ] 旧库没有新的 SellerSprite 提交。
- [ ] 失败任务已经登记。
- [ ] 未完成 Listing Analysis 的 job ID、ASIN 和远端状态已登记。

无法排空时停止切流。不得把未知 `running` 批量重排到新服务。

## 5. SellerSprite 最终备份与恢复

- [ ] 停止旧 SellerSprite 消费能力。
- [ ] 确认旧 Chrome/Xvfb 子进程退出。
- [ ] 使用 SQLite `.backup` 备份队列、绑定和 quota。
- [ ] 三个备份库 `PRAGMA integrity_check` 为 `ok`。
- [ ] 绑定库与原 `.account_bindings.key` 成对备份。
- [ ] CredentialStore 密文与各自 `.key` 成对备份。
- [ ] Profile 和结果完成最终同步。
- [ ] 哈希清单在目标服务器校验通过。
- [ ] 新服务器文件属主和权限正确。
- [ ] 恢复后 SQLite 完整性再次通过。
- [ ] 其他 Bundle 数据未被创建、覆盖或修改。

详细步骤见[状态数据迁移方案](04-状态数据迁移方案.md)。

## 6. 新服务无生产流量验证

### 6.1 服务级

- [ ] systemd 状态为 active，只有一个服务进程和一个 Worker。
- [ ] 服务信息显示 `service_id=collector`。
- [ ] Profile 只包含 `seller_sprite`。
- [ ] 未认证请求返回 401。
- [ ] 无效 API Key 被拒绝。
- [ ] 合法测试 Key 可完成 initialize 和 Tool list。
- [ ] Tool list 不含 query、skills、Keepa、Canopy 或 debug Tool。
- [ ] 服务级健康为 ready。
- [ ] SellerSprite 模块健康为 ready。
- [ ] 第二实例无法取得同一状态目录的消费权。

### 6.2 SellerSprite 模块级

- [ ] `seller_sprite_scenarios` 成功。
- [ ] quota 与迁移前一致。
- [ ] 专属绑定数量和摘要一致。
- [ ] 受控绑定能正确解密。
- [ ] 历史成功任务可读取状态和结果。
- [ ] 历史导出返回 HTTPS URL。
- [ ] 未完成 Listing Analysis 可用原 job ID 续查。
- [ ] 浏览器 Profile 没有权限、锁或版本错误。

## 7. SellerSprite 灰度

灰度用户继续使用配置中心下发的 `BI运营系统`；灰度通过 Tool 权限和通用 MCP 的 Collector 代理控制，不下发 Collector 地址。

### 7.1 路由与权限

- [ ] 灰度 CLI 和 MCP Host 仍只访问 `BI运营系统`。
- [ ] 通用 MCP 使用内部 `OPSCLI_COLLECTOR_MCP_URL` 访问 Collector。
- [ ] API Key 只看到允许的 Tool，并由通用 MCP 和 Collector 分别校验。
- [ ] Collector URL 不包含共享 `api_key`，且未暴露给客户端。
- [ ] 通用 MCP 没有本地执行 SellerSprite。

### 7.2 普通任务

- [ ] submit 返回唯一 job ID。
- [ ] 状态符合 queued/running/succeeded/failed 语义。
- [ ] 所有者邮箱正确。
- [ ] 状态调用不重复扣额度。
- [ ] 成功结果可下载。
- [ ] 另一用户读取 job ID 被拒绝。
- [ ] 上传失败路径不会作为 `file://` 交付给用户。

### 7.3 批量任务

- [ ] 状态保持输入顺序和去重语义。
- [ ] `wait_seconds=30` 到期不改变任务。
- [ ] 混入未知、越权或 Listing Analysis ID 时整批拒绝。

### 7.4 Listing Analysis

- [ ] submit 返回本地 job ID。
- [ ] status 可续查第三方任务。
- [ ] result 未完成时返回 `ready=false`。
- [ ] 最终结果持久化并返回 HTTPS URL。
- [ ] 没有重复创建第三方任务。

### 7.5 专属账号

- [ ] quota 返回 `unlimited=true`。
- [ ] 任务使用绑定账号且不计次。
- [ ] 失效、解绑或改绑时失败，不回退公共账号。
- [ ] 密码未出现在日志、响应或队列。

至少观察一个普通任务和一个 Listing Analysis 续查周期。

## 8. SellerSprite 全量切流

- [ ] 配置中心继续为授权用户返回 `BI运营系统`。
- [ ] 通用 MCP 实例均已配置 Collector 内部 URL 并重启加载新代码。
- [ ] 新服务队列深度、成功率、延迟和错误码正常。
- [ ] 通用 MCP 持续无 SellerSprite 本地执行。
- [ ] API Key 校验、集成账号和文件上传无异常峰值。
- [ ] 服务资源没有因浏览器任务越过预算。
- [ ] 全量用户抽样复核权限和任务所有权。
- [ ] 记录切流时间、配置版本、服务版本和权威数据位置。

回滚窗口结束后：

- [ ] 通用 `opscli-mcp` 仅保留 SellerSprite 同名代理 Tool，不注册本地实现。
- [ ] 旧 SellerSprite 数据保留只读备份。
- [ ] 配置中心继续只返回通用 MCP，不暴露 Collector。

## 9. 服务级回滚触发条件

- Profile 或注册表错误导致服务无法启动；
- API Key 鉴权、权限或身份恢复大面积失败；
- Tool 越权暴露或跨模块 Tool 名冲突；
- 多 Worker/多实例导致状态竞争；
- 统一进程持续崩溃，影响全部已启用 Bundle；
- API Key、Session、JWT 或业务 Secret 泄露；
- 服务级资源耗尽且无法快速隔离模块。

涉及越权或 Secret 泄露时先停止所有提交和隔离入口。

## 10. SellerSprite 模块回滚触发条件

- 严格路由错误导致 SellerSprite 大面积不可用；
- 队列无法消费或产生重复消费；
- 任务所有权、专属账号或额度异常；
- SQLite 损坏或绑定库无法解密；
- 成功率显著低于迁移前；
- 结果只能返回不可访问的本地路径；
- SellerSprite 导致数据采集服务资源持续超限。

## 11. SellerSprite 模块级回滚

1. [ ] 只将 SellerSprite Bundle 设为 `draining`，不停止其他健康 Bundle。
2. [ ] 记录回滚开始时间和新服务最新任务状态。
3. [ ] 尽量排空 SellerSprite `queued/running`。
4. [ ] 无法排空时逐项登记，确认原进程停止前不重排。
5. [ ] 停止 SellerSprite 消费生命周期；如框架不支持单 Bundle 停止，则停止整个数据采集服务并记录影响。
6. [ ] 对新服务最新 SellerSprite 队列、绑定、quota、凭证和结果做一致性备份。
7. [ ] 恢复到旧端时使用这份最新数据，不使用切流前旧备份。
8. [ ] 共享 quota 或 CredentialStore 不得用旧全库覆盖其他 Bundle 的新数据；必要时使用事务迁移或服务级维护窗口。
9. [ ] 校验路径、SQLite、绑定密钥、额度和结果。
10. [ ] 启动旧 SellerSprite 消费能力，保持提交关闭。
11. [ ] 验证迁移前后 job ID 均可查询。
12. [ ] 通用 MCP 临时恢复已验证的 SellerSprite 本地实现，或指向已恢复的旧 Collector；配置中心仍保持 `BI运营系统`。
13. [ ] 重开 SellerSprite 提交并观察。
14. [ ] 其他 Bundle 的路由、进程和私有数据保持不变。

## 12. 中断任务处理

只有确认原消费者和浏览器已经停止、不会继续产生外部副作用后，才考虑：

```bash
opscli seller-sprite queue requeue-running --older-than-minutes <minutes>
```

Listing Analysis 可能已经创建远端任务，应优先用原 job ID 和 ASIN 续查，禁止盲目重排导致重复提交。

## 13. 服务级回滚

如果通用框架本身不可用：

1. 全部 Bundle 进入 draining；
2. 分别记录各 Bundle 的待执行和运行任务；
3. 停止统一数据采集服务；
4. 按 Bundle 分别备份最新状态；
5. 恢复上一稳定服务版本或原部署入口；
6. 按 Bundle 逐一验证和恢复路由；
7. 不使用一个 Bundle 的备份覆盖其他 Bundle；
8. 记录所有受影响模块和客户端。

## 14. 后续 Bundle 上线模板

每个新 Bundle 重复以下流程：

- [ ] 完成准入评审和迁移清单。
- [ ] Profile 加入 Bundle，但暂不开放生产权限。
- [ ] 无流量验证 Tool、健康和依赖。
- [ ] 模块级停写、排空和状态迁移。
- [ ] 只开放灰度用户 Tool 权限和客户端路由。
- [ ] 验证模块自己的业务协议和回滚。
- [ ] 全量切流。
- [ ] 从旧入口移除该 Bundle。
- [ ] 确认 SellerSprite 和其他已上线 Bundle 未受影响。

新模块接入要求见[新数据采集模块接入指南](08-新数据采集模块接入指南.md)。
