# 统一数据采集 MCP 服务状态数据迁移方案

## 1. 适用范围

本文定义所有数据采集 Tool Bundle 的状态迁移模板，并以 SellerSprite 作为首个完整实例。

统一服务不代表统一数据。每个 Bundle 必须拥有独立的数据清单、停写、备份、恢复、验证和回滚步骤。

## 2. 通用迁移原则

1. 同一模块切换期间只能有一个权威写入者和消费者。
2. 迁移前先按模块停止新提交，保留状态和结果查询。
3. 优先排空运行中任务，不迁移进程内对象和浏览器会话。
4. SQLite 不在持续写入时直接复制主文件。
5. 密文、数据库和对应密钥成对迁移。
6. 不同 Bundle 不共享数据库、Profile、业务密钥或结果目录。
7. 队列中的绝对路径和凭证作用域必须显式盘点。
8. 备份完成完整性、哈希和恢复演练后才能切流。
9. 一个模块回滚不得覆盖其他 Bundle 的最新状态。
10. 备份包按 Secret 管理，不进入 Git、聊天或普通对象存储。

## 3. 模块迁移清单模板

每个待迁移 Bundle 必须填写：

| 类别 | 必须说明 |
|---|---|
| Tool | 提交、状态、结果、导出和管理员操作清单 |
| 数据库 | 类型、路径、schema 版本、写入者、备份方式 |
| 密钥 | 密钥路径、对应密文、轮换和恢复验证 |
| 凭证 | Session/JWT/Cookie 的存储和隔离维度 |
| Profile | 浏览器 Profile、锁文件和版本依赖 |
| 结果 | 输出路径、远程 URL、保留期和补传方式 |
| 运行时状态 | 内存队列、scheduler、锁、子进程和缓存 |
| 绝对路径 | 数据库字段和配置中的路径引用 |
| 并发 | 单实例、单 Worker、账号并发和互斥条件 |
| 停写 | 禁止哪些 Tool、保留哪些查询 Tool |
| 验证 | 数据量、哈希、解密、历史任务和新任务 |
| 回滚 | 权威数据方向、同步顺序和中断任务处理 |

未完成清单的模块不得迁入统一数据采集服务。

## 4. SellerSprite 状态清单

以下路径以当前 `CONFIG_DIR` 为根：

| 数据 | 当前默认位置 | 迁移要求 |
|---|---|---|
| 任务队列 | `seller_sprite/task_queue.sqlite3` | 必须迁移 |
| 专属账号绑定库 | `seller_sprite/account_bindings.sqlite3` | 必须迁移 |
| 绑定加密密钥 | `seller_sprite/.account_bindings.key` | 与绑定库成对迁移 |
| 每日额度库 | `mcp_quota/quota.sqlite3` | 必须迁移，避免额度重置 |
| API Key 隔离凭证 | `credentials_by_key/` | 推荐迁移，密文与各自 `.key` 成对 |
| 浏览器 Profile | `seller_sprite/browser_profiles/` | 推荐迁移，敏感且依赖浏览器版本 |
| 任务结果 | `seller_sprite/api_runs/` | 必须迁移 |
| 进程内 scheduler | 无持久文件 | 不迁移，目标服务重建 |
| 浏览器进程/Xvfb | 进程状态 | 不迁移 |

首期保留当前 SellerSprite 路径，避免目录重构与服务器迁移叠加。后续如调整到 `collector/seller_sprite/`，必须单独设计路径迁移。

## 5. SellerSprite 跨机风险

### 5.1 运行中任务

SellerSprite 调度器将浏览器会话和显式逐任务凭证保存在内存。服务重启后：

- 浏览器执行上下文不会恢复；
- `runtime_auth_required=true` 的任务会因内存凭证丢失而失败；
- `running` 状态不能直接视为可安全重放；
- Listing Analysis 可能已在第三方创建远程任务。

正式迁移要求：

```text
queued = 0
running = 0
```

无法排空时必须逐任务决定等待、续查、明确失败或重新提交，禁止批量把未知 `running` 迁到目标服务器。

### 5.2 绝对路径

队列和结果可能保存：

- `root_dir`；
- `result_path`；
- `export_json.path`；
- `request_json.output_dir`；
- `credential_scope`。

最安全方案是新旧服务器保持相同绝对路径：

```text
/var/lib/opscli/.config/opscli
```

路径不一致时：

1. 排空待执行任务；
2. 盘点历史路径字段；
3. 复制结果文件；
4. 使用经评审的一次性脚本在 SQLite 事务中改写；
5. 对每个受影响 job 验证状态和导出；
6. 保留迁移前备份和哈希。

不得直接对 SQLite 二进制文件做字符串替换。

### 5.3 `credential_scope`

`credential_scope` 是隔离 CredentialStore 的非敏感引用，但可能是绝对路径。终态任务通常已清空该字段，仍有值的任务必须逐项核对。

目标路径或 MCP Host `clientInfo.name` 变化时，应使用对应 API Key 重新完成一步登录，不把其他用户目录复制来绕过身份校验。

### 5.4 加密数据配对

必须成对迁移：

```text
seller_sprite/account_bindings.sqlite3
seller_sprite/.account_bindings.key
```

以及 `credentials_by_key/` 每个作用域中的：

```text
credentials.bin
.key
```

目标机不能先创建新密钥再只覆盖密文。密钥不匹配会导致绑定或凭证无法解密。

## 6. SellerSprite 停写和排空

统一数据采集服务目标框架应支持模块状态：

```text
seller_sprite = draining
```

停写：

```text
seller_sprite_run
seller_sprite_listing_analysis_submit
```

保留：

```text
seller_sprite_job_status
seller_sprite_jobs_status
seller_sprite_listing_analysis_status
seller_sprite_listing_analysis_result
seller_sprite_export
```

旧通用 MCP 当前没有模块 drain 能力，上线前必须通过已评审的权限或服务端开关实现，不得只依赖用户通知。

管理员在旧服务器执行：

```bash
opscli seller-sprite queue status
opscli seller-sprite queue list --state queued --limit 500
opscli seller-sprite queue list --state running --limit 500
opscli seller-sprite account-binding list
```

记录未完成 Listing Analysis job ID。队列为空不代表第三方分析全部生成完成。

## 7. SellerSprite 最终备份

### 7.1 停止旧消费者

确认 `queued/running` 为 0 后停止旧 SellerSprite 消费能力，并确认 Chrome/Xvfb 子进程退出。停止后不再允许旧端写入 SellerSprite 状态。

### 7.2 SQLite 一致性备份

```bash
mkdir -p /var/backups/opscli/collector-cutover/seller_sprite

sqlite3 /var/lib/opscli/.config/opscli/seller_sprite/task_queue.sqlite3 \
  ".backup '/var/backups/opscli/collector-cutover/seller_sprite/task_queue.sqlite3'"
sqlite3 /var/lib/opscli/.config/opscli/seller_sprite/account_bindings.sqlite3 \
  ".backup '/var/backups/opscli/collector-cutover/seller_sprite/account_bindings.sqlite3'"
sqlite3 /var/lib/opscli/.config/opscli/mcp_quota/quota.sqlite3 \
  ".backup '/var/backups/opscli/collector-cutover/seller_sprite/quota.sqlite3'"

sqlite3 /var/backups/opscli/collector-cutover/seller_sprite/task_queue.sqlite3 "PRAGMA integrity_check;"
sqlite3 /var/backups/opscli/collector-cutover/seller_sprite/account_bindings.sqlite3 "PRAGMA integrity_check;"
sqlite3 /var/backups/opscli/collector-cutover/seller_sprite/quota.sqlite3 "PRAGMA integrity_check;"
```

每个检查必须返回 `ok`。使用 `.backup` 后不复制源 `-wal`、`-shm` 文件。

注意：`mcp_quota/quota.sqlite3` 可能同时包含其他业务额度。首期若整体复制，SellerSprite 回滚时不能再用旧 quota 覆盖其他 Bundle 的最新额度。长期应支持按服务或模块拆分 quota 存储，或提供事务级数据迁移工具。

### 7.3 文件数据

```bash
install -m 0600 \
  /var/lib/opscli/.config/opscli/seller_sprite/.account_bindings.key \
  /var/backups/opscli/collector-cutover/seller_sprite/.account_bindings.key

cp -a /var/lib/opscli/.config/opscli/credentials_by_key \
  /var/backups/opscli/collector-cutover/seller_sprite/
cp -a /var/lib/opscli/.config/opscli/seller_sprite/browser_profiles \
  /var/backups/opscli/collector-cutover/seller_sprite/
cp -a /var/lib/opscli/.config/opscli/seller_sprite/api_runs \
  /var/backups/opscli/collector-cutover/seller_sprite/
```

生成哈希：

```bash
find /var/backups/opscli/collector-cutover/seller_sprite -type f -print0 \
  | sort -z \
  | xargs -0 sha256sum \
  > /var/backups/opscli/collector-cutover/seller_sprite.sha256
```

备份目录的父级按 Bundle 分隔，禁止把不同模块的同名数据库或 `.key` 扁平复制到一起。

## 8. 目标恢复

1. 确认 `opscli-collector-mcp` 未启动。
2. 创建目标目录并设置服务用户和 `0700`。
3. 校验传输后的哈希。
4. 恢复 SellerSprite 结果、Profile 和 CredentialStore。
5. 同时恢复绑定库与原 `.account_bindings.key`。
6. 恢复队列和 quota。
7. 修正文件属主和最小权限。
8. 再次运行三个 SQLite `PRAGMA integrity_check`。
9. 检查绝对路径和队列状态。
10. 启动只包含 SellerSprite Bundle 的数据采集 Profile。

## 9. 恢复验证

- 队列总数和各状态与旧端盘点一致；
- 绑定数量、账号 ID 和脱敏用户名一致；
- 受控测试绑定能够实际解密；
- 当日 SellerSprite quota 未重置；
- 历史成功 job 可读取结果；
- 文件存在且哈希一致；
- 未完成 Listing Analysis 可用原 job ID 续查；
- Profile 权限和浏览器版本兼容；
- 隔离凭证不可用时按原 API Key 重新登录；
- 其他 Bundle 目录和数据未被修改。

## 10. 不迁移内容

- 浏览器进程、PID、运行锁和临时 Xvfb；
- 使用 `.backup` 后的 SQLite `-wal`、`-shm`；
- 内存 scheduler、账号池和协程；
- 明文账号密码、临时 Cookie 导出、完整 API Key；
- 无用下载、崩溃转储和敏感调试截图；
- 其他 Bundle 未列入本次迁移范围的数据。

## 11. 后续 Bundle 的数据要求

新 Bundle 接入前必须：

1. 在 `collector/<bundle_id>/` 使用独立目录；
2. 声明哪些数据可重建、哪些必须备份；
3. 声明密钥与密文配对关系；
4. 提供一致性备份命令；
5. 提供无生产 Secret 的恢复测试；
6. 说明运行中任务是否可重放；
7. 说明外部副作用和幂等键；
8. 设计模块级回滚，不覆盖共享数据；
9. 对共享 CredentialStore、quota 等公共状态说明迁移影响。

切流和模块级回滚见[上线验证与回滚清单](06-上线验证与回滚清单.md)。
