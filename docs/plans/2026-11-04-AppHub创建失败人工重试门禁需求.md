# AppHub 创建失败人工重试门禁需求

## 背景

`POST /api/v1/apps` 可能先登记应用，再因后续资源准备失败返回 502；同一账号和 slug 再次 POST 可能获得新的 `app_id`。当前 `opscli` 没有 HTTP 自动重试循环，但 Codex 会根据错误提示或旧版 `ops-app-build-spec` 的“幂等重试”说明再次执行 `app create` 或迁移命令，短时间内产生重复应用。本地 `.opscli/creation.json` 只校验同目录请求一致，不阻止再次发送。

## 目标与范围

- 普通新建和源码复制迁移共用一个创建保护：一次创建结果不明后，Codex 无法靠重复命令、`migrate resume` 或换目标目录再次发送创建 POST。
- 用户在新的指令中明确要求重试时，可以立即在原目标目录显式放行一次，不受自动冷却时间限制。
- 不修改 AppHub API、应用列表、Git 初始化、部署等待或其他只读操作；本期不声称服务端提供幂等保证。

## 行为合同

1. 发送创建 POST 前，使用 AppHub 环境、登录主体和 slug 的摘要，在本机配置目录排他登记待核对创建；原目录继续保留 `.opscli/creation.json`。不保存令牌，也不发送 `Idempotency-Key`、`origin_type` 或 `migration_id`。
2. 收到 502、其他错误、超时、连接中断或无效创建响应时保留保护记录。默认再次执行 `app create`、`migrate resume`，或换目录执行 `migrate start`，在 POST 前返回明确错误；既有未完成的本地创建记录也按结果不明处理。
3. 成功保存 `app_id` 和本地绑定后解除跨目录保护。再次对已绑定的原目录执行 `create` 沿用已有应用，不创建新应用。已经完成但绑定丢失的本地记录仍要求按明确 ID 恢复。
4. 人工重试使用 `opscli app create <name> --path <原目录> --retry-create`；迁移使用 `opscli app migrate resume --target <原目录> --retry-create`。该参数只针对原目录已有未完成创建意图生效，不允许通过新目录绕过保护，也不允许把它作为首次创建的默认参数。
5. CLI 不能识别自然语言指令来源。`ops-app-build-spec` 必须要求 Codex 仅在用户新的明确重试指令后携带 `--retry-create`，且仅尝试一次；其他失败报告错误码、`request_id`、原目标目录和核对方法。创建失败时覆盖服务端或旧客户端可能给出的“幂等重试”建议，不据此自动重发。
6. 人工重试前应核对 AppHub 是否已有对应 `app_id`。如果已登记，优先按明确 ID 恢复原应用；人工放行再次 POST 可能创建另一应用，CLI 不把它描述为安全幂等操作。

## 验收

- 模拟首次 POST 已登记但返回 502：保留原错误码和 `request_id`，同目录、迁移恢复和换目录的默认重复调用均不再发送 POST。
- 用户明确重试并携带参数后，在原目录可以立即再发送一次；再次失败继续保持阻断，成功后解除跨目录保护。
- 已有未完成 `creation.json` 默认受保护；不同账号、环境或请求内容不能沿用原创建意图。
- 创建成功后仍允许用户在另一个目录明确新建同名应用，不将同名本身当作永久冲突。
- 测试只使用临时目录和模拟 HTTP，不创建真实 AppHub 应用。

## 边界

这是本机 CLI 加 Skill 的防误操作机制，无法证明调用来自用户本人，也不能防止其他机器、旧客户端或直接 HTTP 请求重复登记。要获得服务端级去重，AppHub 仍需实现真正的幂等键或等价约束。
