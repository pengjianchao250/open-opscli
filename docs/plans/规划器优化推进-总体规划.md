# 规划器优化推进 · 总体规划

> 本文是两份实施计划的总纲：锁定背景结论、决策默认值、依赖顺序与验收口径。执行任一子计划前必读。

**目标**：消灭 2026-08 QA 验收暴露的三类结构性问题（元数据供给脆弱 / 版本漂移 / Python 环境死穴），并完成规划器内核化收官，使 `opscli query flow` 成为主线入口。

## 背景数据结论（2026-08-19 会话，QA 库 dm_user_feedbacks 8 月 bug 292 条实证）

| 根因 | 占比 | 对应解法 |
| --- | --- | --- |
| duplicate_dataset_field 元数据事故（8-11/12 两天 69 条） | ~37% | S1 服务端导出防线 + C1 客户端自愈。**根因修订（C1 执行中实证）**：客户端同构行合并逻辑 2026-07-16 已上线（早于事故），故事故真实形态是**同名冲突字段行**（语义签名不一致），非整行完全重复；主防线是 S1（源头去重+CONFLICT 告警），C1 自愈分支为纵深兜底（公开链上基本不可达） |
| 旧版客户端 0.0.124 混跑（92 条） | ~50% | S2 版本门槛（中间件已就绪，仅差配置） |
| 环境缺 Python（预发布/托管沙箱） | 持续新增 | 计划二：内核化收官 + 主线切换 |
| 未授权筛选注入（brand_name/country_name 被注入 filters） | ~8 条 | C2 注入前权限交集校验 |
| 组件枚举 7s 窗口超时 | 17 条 | C3 枚举缓存 + 超时降级 |

结论：规划器方向不变、形态升级——**不回退 master**（报错多是护栏在工作：8 月结果错误类反馈仅 18 条 vs bug 292 条）。

## 决策默认值（执行时不再询问）

| 决策点 | 默认值 | 理由 |
| --- | --- | --- |
| 版本门槛 min_version | **0.0.153**，仅 QA 环境启用 | 0.0.124 是重灾区（50% bug）；0.0.155 太激进会误伤；生产启用另行决策 |
| 服务端 dup 处理策略 | **兜底去重（保留首条）+ Log::warning 记明细**，不拒绝导出 | 拒绝导出会把数据事故升级为全员不可用；去重+告警让事故可见且不断流 |
| 客户端 dup 自愈策略 | **完全重复行→静默去重+披露；同名不同定义→维持 raise** | 完全重复是事故形态（8-11 实况）可安全自愈；同名异义去重会静默选错口径 |
| 枚举缓存 | TTL 24h，落 `CONFIG_DIR/enum_cache/`；7s 超时降级读缓存并披露 stale | 枚举值（平台/国家等）变化频率低，24h 足够 |
| 主线切换过渡 | SKILL.md 主入口切 `opscli query flow`，旧 `python3 scripts/query_flow.py` 降级备选保留一个版本周期 | 有 Python 的环境保底可回退 |

## 内核化现状盘点（勘察实据，2026-08-19）

- 内核 `opscli/query/services/planner/` 已有 12 模块 + resources（intent_rules/schema）+ 67 个测试
- `opscli query flow` 命令已存在（`opscli/query/commands/cli.py:231`），规划段完整
- 执行段仅剩三个已声明延后项（`planner/entry.py:26-35` 明文披露）：
  1. orderBy 服务端缺陷的本地兜底/加量重查（源实现在 skill `run_query.py`：`_is_monotonic`/`_sort_value`/放大重查）
  2. result_dir 完整结果落盘 + stdout 限幅
  3. evidence_contract 内嵌
- 主线切换此前被用户决策暂停，等待上述三项补齐（change-log 2026 记录）

## 验收口径

- 计划一每任务独立测试通过 + 既有基线零回归（tests/query 235 passed；tests/skills 8 既有失败不新增）
- 计划二收官验收 = 金样对照：同一批真实请求，内核 flow 与 skill flow 的合同关键字段（选表/模板/披露）一致；主线切换后 E2E 冒烟（真实取数一次成功）
- 最终效果指标（上线后观察）：dm_user_feedbacks 中 dup_field 类、缺 Python 类、未授权注入类 bug 归零；0.0.124 客户端请求被 426 拒绝

## 明确不在本期范围

- 生产环境版本门槛启用（QA 验证一个周期后另行决策）
- 意图路由与规划器的混合架构（等意图闭环数据积累后由数据裁决）
- 服务端 orderBy 缺陷的根修（客户端兜底先行，服务端修复另行立项）
