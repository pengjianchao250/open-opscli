# 卖家精灵排队一期实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为卖家精灵 MCP 第一阶段增加基于 SQLite 的单账号排队能力，统一返回 `job_id`、状态和排队序号。

**Architecture:** 保留现有 `SellerSpriteApiManager.run()` 作为单任务执行器，在其外层增加 SQLite 任务仓储和单账号调度器。MCP 入口统一入队，任务状态以 SQLite 为主，`status.json/result.json` 继续作为任务目录调试与结果落盘产物。

**Tech Stack:** Python 3.10、sqlite3、asyncio、pytest、FastMCP

---

## 文件职责

- 新增 `opscli/seller_sprite/services/task_queue_store.py`
  - SQLite 队列仓储，负责建表、入队、取任务、更新状态、计算排队序号、重置残留运行中任务。
- 新增 `opscli/seller_sprite/services/task_scheduler.py`
  - 单账号调度器，负责拉取队列、串行执行任务、更新状态。
- 修改 `opscli/seller_sprite/services/__init__.py`
  - 导出新增的排队服务入口。
- 修改 `opscli/seller_sprite/services/api_manager.py`
  - 保留 `run()`，弱化旧的 `start()/job_status()` 文件状态主路径，转为兼容辅助能力。
- 修改 `opscli/seller_sprite/config.py`
  - 增加卖家精灵任务队列 SQLite 路径配置。
- 修改 `opscli/mcp/tools/seller_sprite.py`
  - `seller_sprite_run` 改为统一入队；`seller_sprite_job_status` 改为查询队列主状态。
- 新增 `tests/seller_sprite/test_task_queue_store.py`
  - 覆盖 SQLite 队列仓储的核心行为。
- 新增 `tests/seller_sprite/test_task_scheduler.py`
  - 覆盖单账号调度、状态流转和启动恢复。
- 修改 `tests/mcp/test_seller_sprite_tools.py`
  - 覆盖 MCP 入队返回和状态查询口径。
- 修改 `docs/change-log-pending.md`
  - 记录本次代码改动、验证结果和回滚方式。

## 本期边界

- 仅支持第一阶段单账号串行排队。
- 不实现多账号 worker 池。
- 不实现弹性扩缩。
- 不实现取消、优先级、重试中心和心跳监控。
- 不引入 `sqlmodel`。
