# 卖家精灵选产品全量分页实施计划

日期：2026-09-28。状态：首期本地开发完成，合成数据与现有链路回归完成；真实响应采样、真实20页连续采集和部署尚未完成。

主设计：[卖家精灵选产品全量分页设计](../design/卖家精灵选产品全量分页设计.md)。证据：[网页实测](../analysis/卖家精灵选产品分页网页实测.md)、[代码核查](../analysis/卖家精灵全量分页代码核查.md)。

## 1. 已确定的实施边界

- 默认继续单页 100 条。
- 新增 `collection_scope=all`，首期只支持选产品、browser-route、每页 100、XLSX。
- 全量范围是网页允许的前 2000 条，最多 20 个有效数据页。总量更大必须披露来源限制。
- 逐页落盘、跨执行代际检查点、受控重试、逐行格式化、write-only XLSX。
- 复用现有队列、账号占用、心跳、上传和 XLSX 流式沉淀，不新建调度平台。
- 全量 JSON、其他场景、自动拆分筛选、任意页大小、通用终态失败续跑 API 不进入首期。
- 本方案不依赖工作区中未提交的 SQLite 迁移文档；以当前已提交队列实现为基线。

## 3. 必测清单

| 类别 | 输入或故障 | 验收结果 |
| --- | --- | --- |
| 默认兼容 | 未传 collection_scope | 仍仅一次主列表查询，默认100；现有 JSON/XLSX 合同不变 |
| 自然末页 | total=121，100+21 | 2页，121唯一行，完整范围；不请求第3页 |
| 满页结束 | total=200 | 2页结束，不用额外空页探测 |
| 来源边界 | total=4830，size100 | 最多20数据页，2000行，source_limited；不发第21页 |
| 空结果 | 成功业务响应 total0/items空 | 仅第一页，合法空文件，matched_range |
| 失真响应 | total>0但空页、短页、服务端缩小size | 有限重试或合同错误；不误报完整 |
| 重复/漂移 | 整页重复、ASIN跨页重复、total变化 | 有界停止或unverified，不补抓超限页，不入完整缓存 |
| 恢复 | 第k页写前/写后/提交检查点后崩溃 | 从正确页恢复，成功页不丢失，未提交页不算完成 |
| 执行隔离 | generation失效或账号不同 | 旧写回失败；不同账号结果不混合 |
| 导出失败 | 全部页已采齐，save失败 | 从页文件重新导出，不重新消耗来源查询 |
| 时间/资源 | 总预算耗尽、磁盘不足、文件损坏 | 失败状态与部分清单可查，不无限恢复重跑 |
| 缓存 | page/all、不同访问策略、partial结果 | 不误命中，限制文案不丢，all XLSX 不加载全部记录 |
| 格式一致 | 币种、数字、空值、父子体、超链接/样式 | 与现有同场景正确输出一致 |

资源验收在隔离进程中使用真实字段宽度的脱敏或合成数据，分别跑 100、1000、2000 行；同时记录 Python 峰值 RSS、浏览器进程树 RSS、耗时、文件体积、临时磁盘占用。

首期设定一个待压测验证的工程门槛：相同进程基线下，2000 行路径相对 100 行路径的 **Python 峰值 RSS 增量不超过 64 MiB**。这不是已经达到的实测结果，也不是包含 Chromium 的总内存承诺。浏览器单独测量，并以部署机器可用内存、同时活跃账号数及至少 30% 余量确定并发上限。若不满足，定位批量加载或字符串复制，不能只调大服务器内存后跳过验证。

资源测量应覆盖导出、结果序列化、上传 mock、XLSX 沉淀和缓存命中；仅测 Workbook 构建不足以通过验收。分页响应文件大小上限与磁盘预留值在 P0 获得样本后确定，并作为配置/测试常量记录，不能按正常样本大小直接声称最坏情况安全。

## 4. 发布与回滚

上线初期只为明确请求 all 的任务启用新路径，page 不切换到新流程。新增配置或合同开关默认保守；若停用 all，必须显式拒绝新 all 请求，不能静默降为单页成功。

回滚时保留已提交页和导出文件，停止接收新 all；旧版本不得将带 all 字段的排队任务当成普通 page 任务执行。先排空/暂停对应新任务，再回滚调用与服务能力。队列检查点迁移采用向后兼容新增结构，不删除旧表或旧任务。
