# `opscli app dev` 多项目端口自动分配需求

## 1. 背景

开发人员可能同时启动多个 AppHub 看板。现有 `opscli app dev` 固定使用后端 `8035` 和前端 `5173`，任一端口被占用都会终止启动。人工指定新端口虽然可以绕过冲突，但模板 Vite 代理仍固定指向 `127.0.0.1:8035`，可能把当前前端请求发送到另一项目。

本需求是 `2026-09-16-opscli-app-dev本地开发预览需求.md` 的增补版本，并覆盖其中“默认端口必须空闲”“Vite 代理固定指向 8035”和“默认端口冲突直接失败”的旧条款；其余环境准备、双进程编排和线上边界继续有效。

## 2. 目标

1. 未显式指定端口时，从后端 `8035`、前端 `5173` 开始确定性查找空闲端口。
2. 不终止、不重启、不修改已经占用端口的其他项目。
3. 显式指定的端口保持严格语义，被占用时直接报错。
4. 将实际后端端口传给 Vite，使 `/api` 始终代理到当前项目。
5. 保持 AppHub 生产端口、构建、iframe 路径和同源 API 合同不变。

## 3. 分层职责

### 3.1 `opscli app` 命令族

- `opscli app dev <project-root>` 省略端口时自动选择。
- `--backend-port`、`--frontend-port` 一旦提供即视为用户明确指定，不自动替换。
- 自动选择分别从 `8035`、`5173` 起扫描最多 100 个候选端口，并排除前后端重复。
- 启动 Vite 子进程时临时注入 `APP_DEV_BACKEND_PORT`。
- 启动成功后输出实际前后端 URL；扫描耗尽时返回稳定的 `APP-DEV-PORT` 错误。

### 3.2 统一模板

- `frontend/vite.config.js` 从 Node 进程环境读取 `APP_DEV_BACKEND_PORT`，缺失时回退到 `8035`。
- 该变量只配置 Vite 开发服务器代理，不写入 `.env`，不使用 `VITE_*`，不进入浏览器运行时代码。
- `base: './'`、Dockerfile、Nixpacks、`app.yaml`、生产端口 `8000` 保持不变。

### 3.3 `ops-app-build-spec`

- 本地启动统一调用 `opscli app dev <project-root>`。
- Agent 不手动结束其他项目进程，不在默认场景自行猜测端口。
- Agent 向用户报告命令实际输出的 URL。

### 3.4 `ops-app-data-builder`

数据构建 Skill 不负责进程和端口编排，不重复维护本规则。

## 4. 非目标

- 不修改 AppHub 线上路由、公开前缀、容器入口或健康检查。
- 不把动态端口写入项目 `.env` 或提交到 Git。
- 不为显式端口提供静默降级。
- 不自动清理占用端口的进程。

## 5. 验收标准

1. 默认端口空闲时仍使用前端 `5173`、后端 `8035`。
2. 两个默认端口被占用时自动使用下一组可用端口。
3. 仅一侧冲突时只调整该侧端口。
4. 显式端口被占用时启动失败并指出端口。
5. 自动选择的前后端端口不重复，扫描耗尽时返回明确范围。
6. Vite 子进程收到实际后端端口，前端 `/api` 不会访问其他项目。
7. 前端生产构建成功，构建产物不依赖 `APP_DEV_BACKEND_PORT`。
8. Dockerfile、Nixpacks 和 AppHub 生产端口继续使用 `8000`。
