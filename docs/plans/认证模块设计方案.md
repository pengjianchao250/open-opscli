## 一、背景与目标

### 现有认证体系

三个业务系统（运营系统 ops、刊登系统 polaris、数据分析系统 dept*/xm* 等）通过 UCenter 共享登录

> **一期范围**：仅对接 ops 和 polaris，数据分析系统（dept*/xm*）预留二期通过 ops_sync 动态注册。，核心表为 `shared_login_sessions`：

| 字段 | 说明 |
|------|------|
| `session_id` | UUID 会话标识（唯一索引） |
| `email` | 用户邮箱 |
| `expires_at` | 过期时间 |
| `is_valid` | 是否有效 |

### 目标

将认证逻辑打包为独立 pip 包 `opscli`，供 Skills/CLI 工具使用，核心功能：

1. 登录授权认证并存储（Device Flow）
2. 获取对应系统的 JWT token 并存储
3. 检测指定系统的 JWT token 是否有效
4. 使用 session_id 刷新指定系统的 JWT token
5. 通过 CLI 命令获取 JWT token

## 二、整体架构

```
┌─────────────────────────────────────────────────────────┐
│                   pip 包：opscli                │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  CLI 层（typer）                                         │
│  ┌──────────┬──────────┬──────────┬──────────┐          │
│  │auth login│auth token│auth check│auth logout│          │
│  └──────────┴──────────┴──────────┴──────────┘          │
│                                                          │
│  核心逻辑层                                              │
│  ┌─────────────┐  ┌─────────────┐  ┌──────────────┐    │
│  │ DeviceFlow  │  │ TokenManager│  │SystemRegistry│    │
│  │ (ops轮询)   │  │ (存取/刷新) │  │(系统配置管理) │    │
│  └─────────────┘  └─────────────┘  └──────────────┘    │
│                                                          │
│  存储层                                                  │
│  ~/.config/opscli/                              │
│  ├── credentials.json  （session_id + 各系统JWT，加密）  │
│  ├── systems.json      （系统域名注册表，明文）           │
│  └── .key              （加密密钥，权限 600）             │
│                                                          │
└─────────────────────────────────────────────────────────┘
         │                    │
         ▼                    ▼
   ops 后端新增           各业务系统
   /api/cli/*            /api/auth/cli-token
```

### 核心类职责

| 类 | 职责 |
|----|------|
| `DeviceFlow` | 与 ops 交互，完成设备码申请→用户确认→session_id 下发 |
| `TokenManager` | 管理各系统 JWT 的存储、有效性检测、用 session_id 刷新 |
| `SystemRegistry` | 维护系统域名注册表，支持 ops 同步 + 本地配置覆盖 |

## 三、CLI 命令设计

```bash
# ── 授权管理 ──────────────────────────────────────────
opscli login
# 发起 Device Flow，打印授权 URL + 验证码，等待用户浏览器确认
# 成功后存储 session_id，并自动同步系统实例列表

opscli logout
# 清除本地所有凭证（session_id + 全部 JWT）

opscli status
# 显示当前登录用户、session_id 剩余时间、已注册系统列表

# ── Token 操作 ─────────────────────────────────────────
opscli token get --system ops
opscli token get --system polaris
opscli token get --system 营销部
# 获取指定系统的有效 JWT（自动刷新过期 token）
# 输出纯文本 JWT，方便 shell 脚本使用：
#   TOKEN=$(opscli token get --system ops)

opscli token check --system ops
# 检测指定系统 JWT 是否有效，返回状态码 0/1 + 剩余时间

opscli token refresh --system ops
# 强制用 session_id 刷新指定系统的 JWT

opscli token refresh --all
# 刷新所有已注册系统的 JWT

# ── 系统注册 ───────────────────────────────────────────
opscli system list
# 列出所有已注册系统

opscli system sync
# 从 ops 重新拉取多实例系统列表（仅更新 source=ops_sync 条目）

opscli system add --alias HR部 --url https://hr.example.com
# 手动添加一个系统实例（source=local）

opscli system remove --alias HR部
# 移除一个手动注册的实例

# ── 诊断 ───────────────────────────────────────────────
opscli doctor
# 检查：session 是否有效、各系统连通性、本地存储权限

opscli version
```

## 四、本地存储结构

### 目录

```
~/.config/opscli/
├── .key                    # 本机随机生成的加密密钥，权限 600
├── credentials.json        # AES-256-GCM 加密存储
└── systems.json            # 系统注册表，明文
```

### credentials.json（解密后）

```json
{
  "session_id": "uuid-xxxx-xxxx",
  "session_expires_at": "2026-05-17T10:00:00Z",
  "email": "user@example.com",
  "tokens": {
    "ops": {
      "jwt": "eyJhbGci...",
      "expires_at": "2026-04-17T18:00:00Z",
      "saved_at": 1713340800
    },
    "polaris": {
      "jwt": "eyJhbGci...",
      "expires_at": "2026-04-17T18:00:00Z",
      "saved_at": 1713340800
    },
    "dept_marketing": {
      "jwt": "eyJhbGci...",
      "expires_at": "2026-04-17T18:00:00Z",
      "saved_at": 1713340800
    }
  }
}
```

### systems.json

```json
{
  "systems": [
    {
      "alias": "ops",
      "system_key": "ops",
      "url": "https://ops.example.com",
      "token_endpoint": "/api/auth/cli-token",
      "source": "builtin"
    },
    {
      "alias": "polaris",
      "system_key": "polaris",
      "url": "https://polaris.example.com",
      "token_endpoint": "/api/auth/cli-token",
      "source": "builtin"
    },
    {
      "alias": "营销部",
      "system_key": "dept_marketing",
      "url": "https://dept-marketing.example.com",
      "token_endpoint": "/api/auth/cli-token",
      "source": "ops_sync"
    },
    {
      "alias": "项目组A",
      "system_key": "xm_projecta",
      "url": "https://xm-projecta.example.com",
      "token_endpoint": "/api/auth/cli-token",
      "source": "local"
    }
  ]
}
```

**source 字段说明：**

| 值 | 含义 | sync 行为 |
|----|------|-----------|
| `builtin` | 内置预设（ops/polaris） | 不覆盖 |
| `ops_sync` | 从 ops 同步 | 每次 sync 更新 |
| `local` | 用户手动添加 | 不覆盖 |

## 五、ops 后端新增接口

### Device Flow 授权接口

```
# 1. CLI 申请设备码
POST /api/cli/device/code
Response:
{
  "device_code": "uuid-xxxx",
  "user_code": "ABCD-1234",
  "verification_url": "https://ops.example.com/cli-auth",
  "expires_in": 300,
  "interval": 3
}

# 2. CLI 轮询授权结果
GET /api/cli/device/poll?device_code=uuid-xxxx
Response（等待中）: { "status": "pending" }
Response（成功）:   { "status": "authorized", "session_id": "uuid-yyyy" }
Response（超时）:   { "status": "expired" }
Response（拒绝）:   { "status": "denied" }

# 3. 用户在浏览器确认授权（需登录态）
POST /api/cli/device/confirm
Body: { "user_code": "ABCD-1234" }
Response: { "success": true }
# 将 device_code 与当前登录用户的 session_id 绑定
```

### 系统实例列表接口

```
GET /api/cli/systems
Headers: X-Session-Id: uuid-yyyy
Response:
{
  "systems": [
    {
      "alias": "营销部",
      "system_key": "dept_marketing",
      "url": "https://dept-marketing.example.com",
      "token_endpoint": "/api/auth/cli-token"
    }
  ]
}
```

### 各业务系统统一换取 JWT 接口

```
# ops / polaris / dept* / xm* 各自实现
POST /api/auth/cli-token
Body: { "session_id": "uuid-yyyy" }

Response（成功）:
{
  "jwt": "eyJhbGci...",
  "expires_in": 7200
}

Response（session 无效）:
{
  "error": "session_invalid",
  "message": "session 已过期，请重新运行opscli login"
}
```

### 接口汇总

| 接口 | 所在系统 | 说明 |
|------|---------|------|
| `POST /api/cli/device/code` | ops | CLI 发起授权 |
| `GET /api/cli/device/poll` | ops | CLI 轮询结果 |
| `POST /api/cli/device/confirm` | ops 前端页面 | 用户浏览器确认 |
| `GET /api/cli/systems` | ops | 登录后同步系统列表 |
| `POST /api/auth/cli-token` | 各系统 | 用 session_id 换取 JWT |

## 六、pip 包结构

### 目录结构

```
opscli/
├── pyproject.toml
├── README.md
└── opscli/
    ├── __init__.py             # 导出 AuthClient
    ├── cli.py                  # typer CLI 入口，注册所有命令
    ├── core/
    │   ├── device_flow.py      # Device Flow 轮询逻辑
    │   ├── token_manager.py    # JWT 存取、有效性检测、刷新
    │   └── system_registry.py  # 系统注册表管理
    ├── storage/
    │   ├── credential_store.py # credentials.json 加密读写
    │   └── crypto.py           # AES-256-GCM 加密/解密
    └── exceptions.py           # 统一异常定义
```

### pyproject.toml

```toml
[project]
name = "opscli"
version = "0.1.0"
requires-python = ">=3.10"
dependencies = [
    "typer>=0.12",
    "httpx>=0.27",
    "cryptography>=42",
    "rich>=13",
    "keyring>=25",
]

[project.scripts]
opscli = "opscli.cli:app"

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"
```

### SDK 调用接口（供 Skill 使用）

```python
from opscli import AuthClient

client = AuthClient()

# 获取指定系统的有效 JWT（自动刷新）
token = client.get_token("ops")
token = client.get_token("营销部")

# 检测是否已登录
client.is_authenticated()

# 检测指定系统 token 是否有效
client.check_token("polaris")  # 返回 {"valid": True, "expires_in": 3600}
```

### 发布与安装

```bash
# 内部 PyPI 发布（推荐）
pip installopscli --index-url https://pypi.your-corp.com

# 或 pipx 隔离安装（纯 CLI 使用）
pipx installopscli

# Skill 中作为依赖引入（requirements.txt）
opscli>=0.1.0
```

## 七、设计决策汇总

| 维度 | 决策 | 原因 |
|------|------|------|
| 授权方式 | Device Flow，ops 新增 4 个接口 | 用户体验最佳，复用现有 session |
| Token 获取 | 按需调用各系统 `/api/auth/cli-token` | 各系统独立部署，接口解耦 |
| 系统注册 | 统一平铺列表，builtin/ops_sync/local 三种来源 | 支持任意命名的多实例系统 |
| 本地存储 | `~/.config/opscli/`，AES-256-GCM 加密 | 安全规范，跨平台一致 |
| CLI 命令前缀 | `opscli` | 明确归属，避免冲突 |
| CLI 命令数量 | 14 个，覆盖授权/Token/系统/诊断 4 大模块 | YAGNI，按需扩展 |
| SDK 接口 | `AuthClient` 类，供 Skill 直接调用 | 解耦 CLI 与编程调用 |
| 分发方式 | 内部 PyPI 或 pipx | 方便内部统一管控版本 |
