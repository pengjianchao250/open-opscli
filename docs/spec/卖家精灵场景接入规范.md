# 卖家精灵场景接入规范

本文规定卖家精灵新场景从页面调研、接口取证、代码接入、导出对齐到离线验收的统一流程。现有场景只有在需求明确时才允许偏离本文默认契约，并必须在场景证据和测试中记录例外原因。

## 1. 接入原则

1. **场景语义隔离**：页面用途、主接口或结果含义不同，应注册独立 `scenario_id`，不得借用名称相近的旧场景。
2. **真实请求优先**：参数名称、类型、默认值和枚举必须来自页面真实请求或页面元数据接口，不得根据旧场景猜测。
3. **最小数据范围**：查询类场景默认只获取第一页 100 条，不自动请求或合并后续页。
4. **双路径一致**：API-direct 与 browser-route 必须发送同一业务请求，并返回相同的行范围、文件格式和 `row_count` 语义。
5. **业务数据优先**：本地工作簿参照官方业务主表，不复制 `Notes`、客服信息、二维码、推广内容等非业务页。
6. **离线可回归**：接口、导出和认证相关测试不得访问真实网络、系统 Keychain 或个人浏览器登录态。
7. **凭证不落盘**：Cookie、Token、密码、账号、认证 Header 和带签名下载地址不得写入代码、文档、日志或场景证据。

## 2. 页面调研与接口取证

### 2.1 建立场景边界

接入前先记录：

- 页面名称、页面 URL 和业务目的；
- 用户输入、筛选条件、排序条件和结果字段；
- 主查询接口、枚举接口、导出接口及任务状态接口；
- 与现有场景的差异，确认是否必须新增独立场景；
- 查询额度、导出次数、游客限制和登录态限制。

如果页面查询与官方导出的字段范围不同，应分别记录两套契约，不得把导出参数误当成主查询参数。

### 2.2 收集完整查询参数

使用可监控浏览器在页面逐项填写测试值，并捕获点击“查询”后产生的真实请求。推荐给连续输入框使用互不重复的值，例如 `1、2、3……`，以建立页面中文标签与接口字段的一一对应关系。

每个控件至少核对：

| 项目 | 必须确认的内容 |
|------|----------------|
| 文本框 | 字段名、空值行为、字符串或数组格式 |
| 数值范围 | `min/max` 字段、整数或小数、单位、上下界规则 |
| 百分比 | 页面提交值与响应值是否同一口径，例如 `12`、`0.12` 或 `12%` |
| 单选/开关 | 枚举值、布尔值或数字值、默认状态 |
| 多选 | 请求是数组、逗号字符串还是重复参数 |
| 排序 | 排序字段白名单、升降序字段和值 |
| 分页 | 页码和每页数量字段、服务端实际返回数量 |
| 周期 | 周/月类型、具体表名、默认最近周期算法 |

完成后应形成“页面标签 → 请求字段 → 示例值 → 类型/单位”的参数表。未在真实请求中验证的字段必须标记为“待验证”，不能作为正式能力发布。

### 2.3 收集枚举和元数据接口

站点、周期、类目、排序等选项可能来自独立接口。调研时必须检查页面加载及控件展开产生的网络请求，并记录：

- 接口方法和路径；
- 站点或市场参数；
- 响应中 code、名称、层级和可用状态字段；
- 是否随站点、周期或账号权限变化；
- `any`、`all` 等特殊值的真实语义；
- 本地是否需要缓存，以及缓存失效条件。

调用方传给主查询的应是页面实际使用的 code。未实现名称到 code 的可靠映射时，禁止声称支持中文名称自动转换。

### 2.4 核对响应结构

至少确认：

- 业务行路径，例如 `data.items` 或 `data.pagerDto.list`；
- 总数、当前页、每页数量和游客限制字段；
- 空结果、未登录、额度不足和业务错误的响应结构；
- 页面展示字段与原始响应字段的转换方式；
- 百分比、货币、日期、排名变化和嵌套 ASIN 列表的原始口径。

页面展示值不能代替接口原始值作为样例。字段转换必须以真实响应和官方导出共同验证，尤其不得把比例小数直接按百分数文本处理。

## 3. 场景契约与代码接入

### 3.1 场景注册

每个独立场景应在注册表中声明：

- 唯一 `scenario_id` 和中文标题；
- 主接口路径和 HTTP 方法；
- 必填参数或至少一个必填参数组；
- 独立 payload builder；
- 仅在确有需要时声明高频词、导出或状态接口。

不得为了复用代码而改变旧场景的参数、分页、导出或结果语义。公共辅助函数只能复用无业务歧义的格式化逻辑。

### 3.2 Payload 构造

Payload builder 应做到：

1. 只接受文档明确支持的公共参数和页面字段别名；
2. 将站点、周期、类目等转换为官网真实取值；
3. 对范围、枚举、排序、日期和必填条件进行本地校验；
4. 明确列表的序列化方式；
5. 保持页面单位，不擅自除以或乘以 100；
6. 对默认值写中文注释，说明其页面依据或业务原因；
7. 不携带 Cookie、Token 等认证字段，认证由客户端或浏览器登录态处理。

### 3.3 默认分页契约

普通查询类场景默认执行以下契约：

- 固定第一页；
- 固定每页 100 条；
- 主查询只请求一次；
- 不根据总数自动续页；
- 不合并后续页；
- `row_count` 等于第一页业务数组的实际行数；
- 服务端少于 100 条时，以实际返回为准。

不同接口可使用 `page/size`、`pageNum/pageSize` 等真实字段，但对外语义必须一致。若页面或接口最大值低于 100，必须在场景 manifest、Skill 参数手册和测试中记录例外。只有用户需求明确要求全量数据时，才可设计分页，并需单独评估额度、限流、重试和合并规则。

### 3.4 API-direct 与 browser-route

两条执行路径必须共享同一个已校验 payload，并满足：

- HTTP 方法、接口、请求体和 Referer 语义一致；
- 都只获取约定页数；
- 都执行同样的登录失效和业务错误判断；
- 都使用同一行提取逻辑和本地导出逻辑；
- 都返回一致的 `row_count`、文件名和结果模型。

browser-route 可以负责恢复页面登录态或完成官网要求的可见交互，但不得静默扩大数据范围或调用 API-direct 未调用的官网导出接口。

## 4. 导出策略

### 4.1 先选择导出模式

| 模式 | 适用条件 | 处理方式 |
|------|----------|----------|
| 查询 JSON 本地生成 XLSX | 官网导出有次数限制；查询响应已包含业务字段；只需业务主表 | 捕获查询 JSON，按官方业务主表在本地生成 XLSX |
| 官方 XLSX 原样保存 | 接口直接返回完整文件；文件结构难以可靠重建；需求明确要求官方原件 | 校验响应确为 XLSX 后按官方文件名保存，不解析、不截断、不重建 |

例如，`aba-research` 使用查询 JSON 本地生成业务主表；`aba-reverse` 属于官方 XLSX 原样保存例外。每个场景必须在 `manifest.json` 中明确 `source`、是否本地生成、是否调用官网导出及是否允许转换。

### 4.2 本地 XLSX 对齐范围

本地生成时，应只对齐官方**业务主表**：

- 工作表名称及动态行数；
- 业务表头和列顺序；
- 字段来源、fallback 和嵌套字段展开规则；
- 数字、百分比、货币和日期格式；
- 表头样式、列宽、行高、冻结窗格和筛选；
- ASIN、图片、商品页等业务超链接；
- 空值和 `N/A` 的官方表现。

默认不生成：

- `Notes` 工作表；
- 客服联系方式和使用说明；
- 二维码、公众号图片和推广图片；
- 与业务数据无关的版权、广告或引流内容；
- 为复制装饰内容而新增的图片处理依赖。

官方文件含上述内容时，可在 `workbook-profile.json` 客观记录，但本地交付仍只保留业务主表。若业务明确要求额外工作表，必须逐项说明用途并新增测试。

### 4.3 官方原件保存要求

原样保存模式必须：

- 校验状态码、Content-Type、ZIP/XLSX 文件头和最小文件长度；
- 优先使用响应中的安全文件名，并清理路径字符；
- 不使用 openpyxl 打开后重新保存；
- 不改变工作表、格式、图片、公式或行数；
- 测试中使用本地二进制 fixture，不访问官网。

## 5. 场景证据

每个正式场景应建立：

```text
opscli/seller_sprite/reference/scenarios/{scenario_id}/
├── manifest.json
├── sample-request.json
├── sample-response.json
├── official-headers.json
└── workbook-profile.json
```

按场景实际情况保留文件；没有响应 JSON 或本地工作簿时可省略不适用文件。

### 5.1 `manifest.json`

至少记录：

- 场景 ID、标题和页面路由；
- 主接口、方法、响应类型和业务行路径；
- 必填条件、分页范围和自动分页开关；
- 枚举或元数据接口；
- 导出来源及转换策略；
- 官方参考文件名、主表、表头数量和 SHA-256；
- 样例文件和取证日期。

### 5.2 脱敏规则

样例只能保留复现字段映射所需的最少数据：

- 删除 Cookie、Authorization、Token、Session、密码和账号信息；
- 删除完整请求 Header，只保留必要的 Content-Type 等非敏感信息；
- 下载 URL 应删除签名、临时参数和内部域名信息；
- ASIN、关键词等公开业务标识可保留代表性值，内部人员或账号字段必须替换；
- 响应只保留代表性行，不能因样例过大提交整份生产数据；
- 保存前确认 JSON 可离线解析，并搜索常见凭证关键字。

## 6. 离线测试矩阵

### 6.1 Payload 测试

覆盖：

- 必填参数和别名；
- 站点/市场映射；
- 默认周期及周/月具体周期；
- 枚举、多选和列表序列化；
- 排序白名单；
- 数值范围、百分比单位和 min/max 校验；
- 固定第一页 100 条；
- 非法站点、周期、枚举和数值。

### 6.2 Manager 测试

覆盖 API-direct：

- 主接口、方法和 payload 准确；
- 只发起一次查询；
- 不请求后续页；
- 不误调官网导出；
- `row_count` 等于实际业务行数；
- 输出文件名和导出模式准确。

### 6.3 Browser-route 测试

覆盖：

- 使用与 API-direct 相同的 payload；
- 必要页面交互、登录恢复和请求捕获；
- 只保留约定第一页；
- 登录失效和游客限制不会被误判为成功；
- 页面关闭等清理异常不会覆盖真实业务结果。

### 6.4 XLSX 测试

本地生成模式至少断言：

- 仅包含约定业务工作表；
- 不包含 `Notes` 和二维码；
- 工作表名、表头、列顺序和数据行数；
- 数值格式、列宽、行高、冻结窗格和筛选；
- 字段转换、空值、链接和嵌套数据；
- 百分比使用真实响应口径转换。

官方原件模式应断言下载字节未被转换，并校验 XLSX 文件头和输出文件名。

### 6.5 MCP 与文档测试

确认 MCP 场景列表、参数手册和 Skill 执行规则均包含新场景，并准确描述：

- 必填参数；
- 默认周期；
- 第一页 100 条；
- 导出来源；
- 是否生成本地 XLSX；
- 是否排除 `Notes` 和二维码；
- 与名称相近场景的边界。

## 7. 文档和版本同步

完成场景接入后必须同步：

1. `opscli/skills/templates/ops-seller-sprite/SKILL.md`；
2. `opscli/skills/templates/ops-seller-sprite/SKILL_MCP.md`；
3. `opscli/skills/templates/ops-seller-sprite/SCENARIO_PARAMS_ZH.md`；
4. `opscli/skills/templates/ops-seller-sprite/data/VERSION.json`；
5. `docs/change-log-pending.md`；
6. 场景 reference 证据和必要的调研文档。

Skill 版本按实际变更递增。文档中的接口、字段、分页和导出描述必须与代码及测试一致，不得保留已删除行为。
