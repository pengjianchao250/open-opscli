# ASIN取数前端数据结构

本文档说明 `ops-asin-data-collector` 给前端消费的返回结构。后端/脚本执行后，前端优先读取：

```text
output/asin-data/<run_id>/frontend-data.json
```

如果需要人工确认本次运行概览，可读取同目录 HTML；该文件也是默认上传到阿里云的文件：

```text
output/asin-data/<run_id>/frontend-data.html
```

本地还会保留 Markdown 交接文件：

```text
output/asin-data/<run_id>/frontend-data.md
```

## 顶层结构

```json
{
  "运行信息": {
    "运行ID": "asin-data-20260608-120000-abcdef",
    "开始时间": "2026-06-08T12:00:00",
    "结束时间": "2026-06-08T12:03:00",
    "输出目录": "output/asin-data/asin-data-20260608-120000-abcdef",
    "是否DryRun": false,
    "ASIN数量": 1,
    "失败ASIN数量": 0
  },
  "数据": []
}
```

`数据` 是 ASIN 维度数组。每个 ASIN 固定分成四段：

1. `基础数据`
2. `卖家精灵关键词数据`
3. `卖家精灵AI全景分析数据`
4. `Alexa优化建议数据`

## 字段说明

`基础数据` 使用中文字段，包含输入信息、Amazon 抓取摘要、BI 销售数据、爬虫 Listing 数据和错误列表。销售与 Listing 明细也会转换成中文字段，例如 `产品名称`、`销量`、`价格`、`评分`、`评论数`。

`卖家精灵关键词数据` 包含 `关键词输入`、`关键词反查` 和 `关键词挖掘` 三类信息。`关键词输入.关键词列表` 是表格输入或反查派生后的机器可读关键词清单，取数服务可以直接按该字段继续取数；`关键词挖掘.种子关键词` 是本次实际送给 SellerSprite keyword-miner 的关键词。

`卖家精灵AI全景分析数据.content` 直接返回卖家精灵 AI 全景分析接口结果里的完整 `content`。脚本只会把 JSON 字符串解析成 JSON 对象，不做摘要、不删字段、不扁平化。

`Alexa优化建议数据` 来自 `opscli amazon-rufus get-backend` 当前运行生成的报告。`数据` 是按题号拆分后的问答明细，`报告路径` 指向本次 Alexa Markdown 报告。若传入 `--skip-rufus`，该段会返回 `状态=跳过`。

## 状态值

前端展示优先使用中文 `状态`：

| 状态 | 含义 |
| --- | --- |
| `成功` | 数据源执行成功 |
| `跳过` | 数据源被参数跳过或没有必要执行 |
| `失败` | 数据源执行失败 |
| `部分成功` | 子任务中有成功也有失败 |
| `计划中` | dry-run 模式，只生成命令计划 |
| `预留` | 兼容旧版本占位状态，新版本默认不再返回 |

如需调试，可读取同级 `原始状态` 字段，对应脚本内部的 `success`、`skipped`、`failed`、`partial`、`planned`。

## 兼容说明

原有 `asin-data.jsonl` 保留不变，并在每行新增 `frontend_data`。新前端建议直接读取 `frontend-data.json`，旧调用方仍可继续读取 `asin-data.jsonl`、`manifest.json` 和 `commands.jsonl`。
