# 跨平台发布前检查

本文档用于 `opscli` 发布到 PyPI / TestPyPI 前的统一预检，目标是尽量在发布前发现以下问题：

- 某个平台无法安装依赖
- 某个平台单测失败
- 打包产物构建失败
- wheel 安装成功但控制台命令不可用
- CLI 入口、顶级命令或 SDK re-export 失效

## 1. 当前检查范围

当前仓库仍是**单包发布**，因此预检以现有单包能力为准，不包含未来拆包/插件化方案。

这套检查覆盖：

1. 安装开发依赖
2. 运行单元测试
3. 构建 `sdist` 和 `wheel`
4. 将构建出的 wheel 安装到全新虚拟环境
5. 验证 `opscli` 控制台入口和基础命令帮助
6. 验证顶层 `AuthClient` re-export

不覆盖：

- 真实后端联调
- 真实浏览器授权登录
- Amazon 抓取的真实 Playwright 网络行为
- TestPyPI / PyPI 实际上传

## 2. 本地执行

### 2.1 一键执行全量预检

```bash
python scripts/release_preflight.py --stage all
```

### 2.2 分阶段执行

只安装测试依赖：

```bash
python scripts/release_preflight.py --stage install
```

只跑单测：

```bash
python scripts/release_preflight.py --stage test
```

只构建发行产物：

```bash
python scripts/release_preflight.py --stage build
```

只验证已构建 wheel 的安装和 CLI smoke：

```bash
python scripts/release_preflight.py --stage smoke
```

传递额外 pytest 参数：

```bash
python scripts/release_preflight.py --stage test --pytest-args -q tests/auth
```

## 3. CI 检查矩阵

仓库已新增工作流：

- [cross-platform-preflight.yml](/Users/mask/python3/opscli/.github/workflows/cross-platform-preflight.yml)

默认矩阵：

| 维度 | 值 |
| --- | --- |
| OS | `ubuntu-latest` / `macos-latest` / `windows-latest` |
| Python | `3.10` / `3.12` / `3.13` |

工作流会在以下场景执行：

- `push` 到 `main`
- 针对 `main` 的 `pull_request`
- 手动 `workflow_dispatch`

## 4. 发布前建议动作

建议在正式发布前按顺序完成：

1. 本地执行 `python scripts/release_preflight.py --stage all`
2. 确认 GitHub Actions 的跨平台矩阵全部通过
3. 检查 `README` 中安装说明是否仍与当前发布方式一致
4. 确认版本号和 `tests/test_version_consistency.py` 对齐
5. 再执行 TestPyPI 发布和安装回归

## 5. 结果判定

满足以下条件，可认为“跨平台发布前检查通过”：

- 三个平台矩阵全部通过
- 所有测试通过
- `python -m build` 成功产出 `dist/*.whl` 和 `dist/*.tar.gz`
- 干净虚拟环境中 `opscli --version`、`opscli --help`、各一级子命令帮助可正常运行
- `from opscli import AuthClient` 与 `from opscli.auth import AuthClient` 均可成功导入

## 6. 已知限制

- 当前检查更偏“安装/打包/基础 CLI 可用性”，还不是完整的端到端发布验证。
- `amazon` 模块的 Playwright 真实运行依赖浏览器环境和外部页面稳定性，建议单独保留人工验证步骤。
- Windows 兼容性目前主要靠这套矩阵做回归守护；如需对外明确承诺“完全支持 Windows”，建议后续再补一轮真实使用路径验证。
