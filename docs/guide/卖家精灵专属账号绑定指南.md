# 卖家精灵专属账号绑定指南

本文面向 SellerSprite 服务部署管理员，说明如何在服务端本机为 OPS 用户绑定专属卖家精灵账号。

## 1. 适用范围

- 每个 OPS 用户邮箱只能绑定一个专属账号。
- 同一个命名账号可以绑定多个 OPS 用户。
- 已绑定用户提交 SellerSprite 普通任务或 Listing Analysis 时，自动使用专属账号且不消耗每日额度。
- 未绑定用户继续使用公共账号池和原每日额度策略。
- 专属账号登录失效时任务直接失败，禁止回退公共账号池。
- 绑定管理只提供本地 CLI，不提供 MCP 管理工具。

命令必须在 MCP 服务实际使用的主机和配置目录中执行。多实例部署时，应确保实例使用同一持久化配置卷，或在实际承接请求的实例上管理绑定。

## 2. 安全存储

默认文件位于 `CONFIG_DIR/seller_sprite/`：

| 文件 | 用途 |
|---|---|
| `account_bindings.sqlite3` | 保存命名账号、用户绑定和 AES-GCM 密文 |
| `.account_bindings.key` | 保存 32 字节 AES-256-GCM 密钥 |

密码通过交互式隐藏输入读取，不进入命令参数、SQLite 明文、任务队列、日志或命令输出。

运维要求：

1. 不要在命令参数、脚本、工单或聊天记录中填写密码。
2. 数据库与密钥文件必须同时备份；密钥丢失后无法解密已有账号。
3. 密钥文件必须限制为服务账号可读写，不要提交到 Git。
4. 不要单独复制数据库到不可信环境。

## 3. 绑定或更新账号

```bash
opscli seller-sprite account-binding bind \
  --user-email user@aukeys.com \
  --account-name account-a \
  --username seller@example.com
```

命令随后显示隐藏密码输入提示：

```text
卖家精灵密码:
```

成功输出只包含邮箱、账号 ID、账号名称、脱敏用户名、稳定账号键和绑定时间，不包含密码。

### 复用同一账号

为其他用户使用相同的 `--account-name` 再执行一次绑定：

```bash
opscli seller-sprite account-binding bind \
  --user-email another@aukeys.com \
  --account-name account-a \
  --username seller@example.com
```

注意：同名账号代表同一份可复用凭证。重新绑定同名账号会更新用户名和密码，所有复用该账号的用户后续任务都会使用新凭证。同一个卖家精灵用户名不能创建为多个不同命名账号。

## 4. 查看绑定

```bash
opscli seller-sprite account-binding list
```

列表输出示例：

```json
[
  {
    "user_email": "user@aukeys.com",
    "account_id": "...",
    "account_name": "account-a",
    "username": "s***r@example.com",
    "account_key": "...",
    "bound_at": "2026-07-20T10:00:00+08:00"
  }
]
```

该命令不读取或解密密码。

## 5. 解绑

```bash
opscli seller-sprite account-binding unbind \
  --user-email user@aukeys.com
```

输出字段：

- `deleted`：是否删除了用户绑定。
- `failed_queued_tasks`：因解绑而失败的尚未领取任务数量。

解绑语义：

- 该用户尚未领取的专属 `queued` 任务以 `SELLER_SPRITE_DEDICATED_ACCOUNT_UNAVAILABLE` 失败。
- 已经 `running` 的任务继续使用领取时加载到内存的账号完成。
- 命名账号本身不会删除，其他复用该账号的用户不受影响，后续也可重新绑定。

## 6. 额度与执行行为

已绑定用户调用 `seller_sprite_quota_status` 时返回无限额快照：

```json
{
  "service": "seller_sprite",
  "unlimited": true,
  "limit": null,
  "used": 0,
  "remaining": null,
  "failures": 0,
  "reset_at": null
}
```

专属账号执行约束：

- 同一账号即使绑定多个用户，也严格串行执行任务。
- 不同专属账号可以并行，专属账号任务最多同时运行 3 个。
- 普通任务和 Listing Analysis 都固定使用提交时确认的专属账号引用。
- 绑定被删除、改绑、凭证无法解密或账号登录失败时，任务明确失败，不会进入公共账号池。

## 7. 常见问题

### 返回“专属账号绑定服务不可用”

检查数据库目录是否可写、SQLite 文件是否损坏，以及数据库与密钥文件是否配套。系统采用失败关闭策略，不会在绑定库异常时把用户降级到公共账号池。

### 返回“专属账号绑定已变更”或“专属账号已不可用”

任务提交后对应用户发生了解绑、改绑，或命名账号的名称、用户名发生变化。确认当前绑定后重新提交；不要尝试让任务回退公共账号。

### 返回专属账号认证失败

在服务端重新执行 `account-binding bind`，使用原 `account-name` 更新凭证。认证失败的当前任务不会自动切换公共备用账号，需要在凭证修复后重新提交。

### 解绑后仍有任务运行

这是预期行为。解绑只失败尚未领取的任务，已经运行的任务按领取时账号完成。命令输出中的 `failed_queued_tasks` 仅统计被终止的排队任务。
