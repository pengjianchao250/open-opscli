# 交给当前环境的 skill-creator

`ops-creator-skill` 负责业务访谈、流程地图、数据预检和边界判断；正式创建或更新 Skill 必须交给当前环境可用的 `skill-creator` 或同类技能创建能力完成。

## 调用前硬门槛

调用 skill-creator 前必须已有：

- 用户确认的 Q1-Q6。
- 阶段 1 技术补充。
- 创建价值判断。
- 触发与不触发边界。
- 输入、输出、完成信号。
- 流程步骤、判断规则、例外和升级条件。
- 涉及内部数据时的预检结论。
- 旧 Skill 改造时的基线、保留行为、影响点扫描、受影响项确认和兼容策略。
- 至少 2-3 个测试 prompt 和断言。
- 需要团队复用时的安装/打包/发布计划。

缺任一项，不要调用 skill-creator 写正式文件；先回访谈或标 `[待确认]`。

## 交接 brief

交给 skill-creator 的 brief 必须包含：

```markdown
## Skill 名称
## 展示名称
## 触发描述
## 不应触发
## 目标用户
## 真实触发话术
## 必要输入
## 工作流
## 判断规则
## 例外与升级
## 内部数据方案与预检结论
## 脚本固化建议
## 输出规范
## 测试 prompt 与断言
## 发布/安装/打包要求
## 待确认问题
```

## Codex 环境要求

在 Codex 中创建或更新 Skill 时：

1. 使用 `skill-creator` 的规范处理目录、frontmatter、`agents/openai.yaml`、`references/`、`scripts/` 和基础校验。
2. 新建 Skill 优先放到当前 Codex Skill 根，例如 `<CODEX_HOME>/skills` 或当前会话已加载的 Skill 根。
3. 更新已安装 Skill 时，直接修改已加载 Skill 根下的目标目录，并运行 `quick_validate.py`。
4. 当前会话的技能列表可能不会热刷新描述，但新会话或下一次加载会读取安装目录里的新版文件。最终必须报告实际安装路径。

## 创建后回检

skill-creator 完成后，回到本 Skill 做业务回检：

- 是否误把 `[AI 假设，待用户确认]` 写成事实。
- 是否有不应触发边界。
- 是否把一次性任务包装成 Skill。
- 是否把“生成本地文件”误当完成。
- 涉及数据时，预检是否通过；失败是否阻止正式取数流程。
- 旧 Skill 改造是否先扫描影响点，并只确认本次受影响的范围、名称、触发、输出、数据、脚本、安装兼容等事项。
- 是否有测试 prompt、断言和结果。
- 是否有安装路径、校验结果和可安装包或无需打包理由。

未通过时，先补访谈、补数据或补测试，再让 skill-creator 更新。

## 完成交付

只有以下全部完成，才能说 Skill 已交付：

- 文件已在当前 Skill 根或用户指定安装目录。
- `SKILL.md` 校验通过。
- `agents/openai.yaml` 与主文件一致。
- 需要团队复用时，已生成可安装压缩包和提交说明。
- 已列出测试结果和仍需优化项。
