# 内部数据取数预检

只要目标 Skill 会使用公司内部数据，创建或更新前必须先做取数预检。预检是硬门槛，不是建议项。

适用场景包括：部门、渠道、ASIN、广告、销售额、订单、利润、库存、排名、评论、Listing、预算、趋势、周期对比、报表、异常清单。

## 不得跳过

- 不得凭印象猜数据集、字段、过滤条件或口径。
- 不得在字段不存在、权限失败、工具超时、结果为空且原因不明时继续创建正式 Skill。
- 不得把失败查询写成“已验证取数规则”。
- 不得把一次 smoke query 的偶然结果写成永久业务阈值。

## 预检步骤

1. `识别数据意图`：业务对象、时间范围、平台/国家/部门/渠道/ASIN/类目、指标、决策用途、输出粒度。
2. `模拟真实提问`：根据未来使用者写 2-3 条 prompt，覆盖常规、缺参、边界/空结果风险。
3. `catalog 匹配`：优先用 `ops-dataset-query` catalog 找候选数据集；catalog 失败时说明失败原因并用本地缓存/搜索兜底。
4. `metadata 校验`：确认维度、指标、过滤字段、排序字段存在，比例类指标优先用基础字段本地派生或使用数据集明确口径。
5. `dry-run/query_build`：构造查询计划，验证维度、指标、过滤、日期、对比、limit 能通过。
6. `smoke query`：需要正式业务判断时做小样本查询，通常 `limit 3-10`。如果结果为空，先定位原因。
7. `结论分级`：给出 `通过 / 阻塞 / 降级可用 / 待用户确认`。

## 结论规则

- `通过`：字段存在、过滤有效、dry-run 通过；必要 smoke query 通过或空结果有明确业务解释。可写入正式 Skill。
- `降级可用`：内部数据暂不可用，但用户确认可以用 CSV/Excel/人工导出作为输入。正式 Skill 只能写降级路径，不写自动取数规则。
- `待用户确认`：缺平台、部门、周期、口径、字段用途或权限说明。先追问，不创建正式文件。
- `阻塞`：字段不存在、权限失败、工具超时、查询无法构造、空结果原因不明。停止创建或只交付待确认 brief。

## 预检记录模板

```markdown
## 取数预检
- 模拟问题：
- 数据意图：
- 候选数据集：
- 字段校验：通过 / 失败，证据：
- dry-run/query_build：通过 / 失败，证据：
- smoke query：通过 / 空结果 / 未执行，原因：
- 结论：通过 / 阻塞 / 降级可用 / 待用户确认
- 可写入正式 Skill 的规则：
- 不能写死的口径：
- 降级路径：
```

## 写入目标 Skill

预检通过后，写入目标 Skill 时区分：

- `创建前预检`：放到 `references/data-plan.md` 或 `references/data-recipes.md`。
- `日常取数`：主 `SKILL.md` 只写何时取数、必要参数、已验证数据路径、失败处理。

日常执行不得每次重复完整预检。只有字段变化、权限失败、空结果、新场景、用户要求重新检查口径时，才重新展开 catalog/metadata/dry-run/smoke query。

## 失败处理

预检失败时输出：

```markdown
暂不创建正式 Skill。
原因：
- ...

可以继续的方式：
- 补充缺失口径：
- 改用 CSV/Excel：
- 人工确认字段：
- 先创建 personal_draft，不写自动取数规则：
```
