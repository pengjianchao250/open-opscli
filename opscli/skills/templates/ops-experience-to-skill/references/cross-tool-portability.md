# 跨 AI 工具兼容与替代方案

生成的运营 Skill 不能只依赖当前 AI 工具。运营同事可能使用 Codex、ChatGPT、Claude、Cursor、Claude Code、Dify、Coze、飞书智能伙伴或其他内部 AI 工具。因此每个 Skill 都要把“当前工具专属实现”和“通用替代实现”分开写。

## 1. 先识别专属能力

检查流程里是否使用了这些当前工具专属或不一定可迁移的能力：

- 当前工具的 Skill/技能调用。
- MCP 工具，例如 `ops-dataset-query` MCP。
- app connector 或平台连接器。
- 子 agent / 并行 agent。
- 内置浏览器、文件链接、工作区路径。
- 仅当前工具可用的图像、文档、表格、演示文稿工具。

这些能力可以用于创建阶段和高质量参照，但不能作为唯一执行路径。

## 2. 为每个专属能力写替代路径

| 当前工具能力 | 通用替代方案 |
| --- | --- |
| ops MCP 查询 | opscli 命令、Python 调用 CLI、人工导出 CSV/XLSX |
| 子 agent 评测 | 同一 prompt 多轮运行、人工审阅、promptfoo、脚本断言 |
| Skill/技能调用 | 普通 Markdown 操作手册 + prompt 模板 |
| 平台文件链接 | 相对路径、压缩包、固定输出目录 |
| 内置浏览器预览 | 静态 HTML 文件 |
| 内置 Excel/文档工具 | Python `openpyxl`、`python-docx`、CSV/Markdown |

## 3. 写作期三纯净

为了让 Skill 能迁移到更多 AI 工具，写 `SKILL.md` 时先保持正文干净：

1. `正文纯文本`：不要把某个平台专属触发符当成指令写进去，例如特定平台的斜杠命令、快捷工具名或成员提及语法。必须展示时，用“例如”说明。
2. `能力描述`：写“调用命令行执行脚本”“读取用户上传的 CSV”，不要写死某个平台的工具名。不同 AI 工具会把能力映射到自己的 Shell、Terminal、Bash 或文件工具。
3. `路径不写死`：用相对路径、`<workspace>`、`<output_dir>` 这类占位，不硬编码当前 AI 工具的安装目录或本机绝对路径。

平台专属增强可以放到独立段落，或者用 HTML 注释隔离：

```markdown
<!-- platform: codex -->
当前工具可使用 ops-dataset-query MCP 做字段校验和小样本查询。
<!-- /platform -->

<!-- platform: default -->
如果没有 ops-dataset-query，请让用户从内部系统导出 CSV/XLSX，再运行 `scripts/normalize_input.py`。
<!-- /platform -->
```

不支持注释隔离的平台通常会忽略这些段落；支持的平台可以按需渲染或提取。

## 4. 双轨验证

如果创建阶段使用了当前工具专属服务，推荐这样验证：

1. 用当前工具专属能力生成 `reference_output`。
2. 用通用替代方案生成 `portable_output`。
3. 对比关键字段、指标、章节、异常数量、输出格式。
4. 差异写入 `references/portability-notes.md`。
5. 如果替代方案达不到同等质量，写清限制和人工补偿步骤。

## 5. 跨平台冒烟清单

发布或交给其他团队前，至少检查：

- `跨平台冒烟`：在当前工具和一个目标替代工具中，用同一条真实 prompt 跑通核心流程。
- `降级路径`：每段平台专属能力都有“没有这个能力时怎么办”。
- `description 中性`：除非 Skill 只服务某个平台，否则触发描述不要绑定特定 AI 工具名。
- `脚本可运行`：Python 脚本不依赖当前 AI 工具的私有库或绝对路径。
- `输出一致`：关键字段、指标、风险等级、待确认问题和文件格式一致。

## 6. 写进 Skill 的格式

在生成的 Skill 中加入：

```markdown
## 运行环境

- 当前工具模式：使用 [具体能力]。
- 通用 AI 模式：使用 `scripts/[name].py` + 用户导出的 CSV/XLSX。
- 不可用能力的降级：如果无法访问内部数据，则要求用户上传导出文件，并标记数据口径。

## 替代方案校验

- 当前工具参照输出：
- 通用替代输出：
- 必须一致的字段/指标：
- 允许差异：
- 人工确认点：
```

## 7. 不要做的事

- 不要把当前工具专属的 MCP/连接器写成所有 AI 都能用。
- 不要假设其他 AI 工具能访问本地路径或公司内部系统。
- 不要把内部数据查询结果硬编码到 Skill。
- 不要为了迁移性牺牲准确性；无法替代时明确写限制。
