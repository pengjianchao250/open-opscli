# Rufus 报告 Markdown 格式化规范

适用文件：`B0B1MLVMY5-20260506-175322.md`  
适用范围：Amazon Rufus 答案报告的 Markdown 清洗、表格化和可读性优化。

## 1. 总体目标

1. 完整保留源文件原始输出内容，包括重复段落、异常文本、截断残片、原始判断和原始措辞。
2. 只做 Markdown 语法层面的格式化：标题层级、列表、表格、代码块、引用块、空行与缩进。
3. 禁止摘要、改写、删减、去重、合并同义内容、纠正原文事实或补充外部信息。
4. 裸文本表格、逐行字段、孤立项目符号可以整理为标准 Markdown，但所有原始字段必须完整保留。
5. 输出文件必须仍为 `.md`，并与源文件放在同一目录。

## 2. 文件命名规范

| 文件类型 | 命名格式 | 示例 |
|---|---|---|
| 源文件 | `<ASIN>-<YYYYMMDD-HHMMSS>.md` | `B0B1MLVMY5-20260506-175322.md` |
| 格式化规范 | `<源文件名>-格式化规范.md` | `B0B1MLVMY5-20260506-175322-格式化规范.md` |
| 优化版报告 | `<源文件名>-格式优化版.md` | `B0B1MLVMY5-20260506-175322-格式优化版.md` |

## 3. 文档结构规范

优化版报告必须沿用源文件原始结构，不新增报告说明、目录、结论摘要等源文件不存在的内容。允许做的结构调整仅限于把原有裸标题升级为 Markdown 标题。

```markdown
## 第 1 题：<问题原文>

### 相关产品
### 答案
### 推荐 ASIN
### 总结
```

结构要求：

| 层级 | 用途 | 规则 |
|---|---|---|
| `#` | 报告标题 | 仅当源文件已有一级标题时保留；不得新增 |
| `##` | 每道题 | 保留源文件“第 N 题：问题原文” |
| `###` | 题内模块 | 保留源文件已有的“相关产品、答案、推荐 ASIN、总结”等模块 |
| `####` | 细分主题 | 仅用于源文件已有的裸标题，例如“核心卖点”“总体评估”等 |

## 4. 内容保留规范

| 场景 | 处理规则 |
|---|---|
| “答案”和“总结”完全一致 | 两段都必须保留，只允许分别格式化 |
| “总结”比“答案”更有编号或更清晰 | 不得用总结覆盖答案；两者按源文件顺序保留 |
| 同一道题重复出现相同表格 | 每一处表格都必须保留，不得删除重复表格 |
| 同一观点多次重复 | 保留每一次出现，不合并、不压缩 |
| 原文有明显错误、乱码或异常 | 保留原样，可通过格式化让其更可读，但不得纠错或解释 |

## 5. 表格格式规范

### 5.1 标准 Markdown 表格

所有表格必须包含表头、分隔行和数据行：

```markdown
| 维度 | Aiheal | 竞品平均 | 判断 |
|---|---|---|---|
| 价格 | $54.99 | $62-80 | 低价优势 |
```

### 5.2 裸文本表格转换

原文件中常见的裸文本表格模式如下：

```text
评估维度
Aiheal
竞品平均
评分
价格
$54.99
$62-80
✅ 最低
```

必须转换为：

```markdown
| 评估维度 | Aiheal | 竞品平均 | 评分 |
|---|---|---|---|
| 价格 | $54.99 | $62-80 | ✅ 最低 |
```

转换规则：

| 原始形态 | 转换方式 |
|---|---|
| 连续多行字段，且前几行为表头 | 按固定列数分组转为 Markdown 表格 |
| 一行内容跨多行，例如“❌ / 致命问题” | 合并为同一单元格：`❌ 致命问题` |
| 单元格内有多个短句 | 使用 `<br>` 分隔，避免破坏表格 |
| 列数超过 5 列 | 优先保留为表格；如果过宽，拆为“主表 + 补充说明” |
| 表格内容缺失或截断 | 不补造数据，保留原始残缺内容；如需说明，只能使用源文件已有文字 |

### 5.3 推荐表格模型

#### 对比表

| 推荐列 | 说明 |
|---|---|
| `维度` | 比较对象，例如价格、可靠性、认证 |
| `Aiheal` | 目标 ASIN 表现 |
| `竞品/市场主流` | 对标对象表现 |
| `判断` | 明确优势、劣势或风险 |

#### 用户适配表

| 推荐列 | 说明 |
|---|---|
| `用户类型` | 适合或不适合的人群 |
| `适配度` | 推荐、不推荐、有条件推荐 |
| `原因` | 用一句话说明 |

#### 优先级表

| 推荐列 | 说明 |
|---|---|
| `优先级` | P1、P2、P3、P4 |
| `项目` | 待优化事项 |
| `影响` | 高、中、低，或星级 |
| `成本` | 高、中、低 |

## 6. 列表与段落规范

| 原始问题 | 处理规则 |
|---|---|
| 孤立一行 `•` | 删除孤立符号，将下一行改为 `- <内容>` |
| `✅ xxx — yyy` | 改为列表或表格：`- ✅ **xxx**：yyy` |
| `❌ xxx — yyy` | 改为列表或风险表格 |
| 裸标题没有 Markdown 标记 | 根据层级改为 `###` 或 `####` |
| 长段落堆叠 | 拆为“结论 + 支撑点 + 风险” |

## 7. 异常内容标注规范

如果原始报告存在异常，必须保留原始异常文字，不得新增解释性结论：

| 异常类型 | 标注方式 |
|---|---|
| 答案采集失败 | 保留源文件中的 `Sorry, something went wrong. Retry` 原文 |
| 内容截断 | 保留残缺表头和残缺正文，不新增“疑似截断”等判断 |
| 表格无法恢复 | 保留原始残片，可放入代码块提升可读性 |
| 数据口径冲突 | 保留冲突描述，不新增“需二次核验”等非原文判断 |

## 8. 状态与风险表达规范

状态符号可以保留，但必须与文字绑定，不能单独成行。

| 推荐写法 | 不推荐写法 |
|---|---|
| `✅ 支持：±1°F 精准温控` | `✅` 单独一行 |
| `❌ 不支持：无预设按钮` | `❌` 单独一行 |
| `⚠️ 风险：可靠性反馈较弱` | `⚠️` 单独一行 |

## 9. 引用与链接规范

1. Amazon 链接统一放在“相关产品”表格中。
2. 推荐 ASIN 独立列出，不混入正文段落。
3. 不输出原始 JSON、headers、payload 或调试信息。

相关产品推荐格式：

```markdown
| ASIN | 链接 |
|---|---|
| B0B1MLVMY5 | https://www.amazon.com/dp/B0B1MLVMY5 |
```

## 10. 质量检查清单

输出前必须检查：

| 检查项 | 通过标准 |
|---|---|
| 标题层级 | 不新增一级标题；题目继续使用源文件的 `##` |
| 表格语法 | 每张表都有 `|---|` 分隔行 |
| 孤立符号 | 不存在单独一行的 `•`、`✅`、`❌`、`⚠️` |
| 重复内容 | 源文件重复出现的“答案”和“总结”必须完整保留 |
| 异常内容 | 第 3 题残缺表头、第 6 题失败文本必须保留原文 |
| 信息保真 | 不新增、不删除、不改写原文件中的数据和结论 |

## 11. 明确禁止事项

| 禁止事项 | 原因 |
|---|---|
| 删除重复的“总结” | 违反完整保留原则 |
| 把长答案改写成“结论摘要” | 属于内容修改 |
| 用自己的话重组判断逻辑 | 属于内容改写 |
| 新增目录、报告说明、异常说明 | 属于新增内容 |
| 补全第 3 题残缺表格 | 属于补造源文件不存在的内容 |
| 把第 6 题失败结果改写成分析 | 属于新增内容 |
