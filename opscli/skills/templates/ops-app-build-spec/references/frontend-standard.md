# 前端开发规范

本文件只约束前端实现，API 合同以后端为准；按本次改动范围读取相关约束。

## 合同边界

- API 路径、方法、参数、响应信封、错误码、鉴权头和字段语义由后端定义，前端不得维护第二套口径。
- 修改请求、错误处理或共享类型前，读取 `backend-redlines.md`，核对目标项目 `backend/CLAUDE.md`、`docs/apphub-contract.md` 及受影响的路由、Pydantic Schema 和生成的 OpenAPI。
- API 变化必须先由后端更新路由、Schema、相关测试和 OpenAPI，再同步前端请求、类型与测试；禁止手工修改 OpenAPI。
- 文档与运行代码不一致时先修正后端合同，不新增前端兼容分支掩盖漂移。
- 纯文案、样式或布局调整不涉及接口时，无需额外加载后端全文。

## 技术与结构

- 沿用模板的 Vue 3 + JavaScript、Vite、Element Plus、Axios、Pinia 和 Vue Router，以及项目现有包管理器与锁文件。
- 不强制迁移 TypeScript、Vue Query，不为遵守规范引入新库或重搭脚手架。
- 统一模板使用 Vue runtime-only 构建；组件视图必须使用 SFC 顶层 `<template>`、独立 `.vue` 组件或 render function，禁止组件对象中的字符串 `template`、`Vue.compile` 和从 `vue` 导入运行时 `compile`。
- `src/views` 负责页面布局与交互编排；`src/components` 放可复用或职责独立的 UI；`src/api` 统一封装请求与响应处理。
- 目录按实际需要创建，不预建空目录或为简单页面强拆文件。
- 复用已有组件、客户端和样式变量；仅对重复出现且含义稳定的业务概念抽象。
- 修改公共函数前搜索所有调用方并核对影响；不搭万能表格配置框架，不设文件行数硬上限。

## 状态与数据

- 保留已有业务 store 的职责；跨组件共享的业务状态可由 Pinia 管理，不强制搬回页面。
- 弹窗开关、输入草稿等临时 UI 状态留在组件内，不为局部状态新增全局 store。
- 同一业务数据保持单一来源；派生展示用计算值，不在页面、组件和 store 重复维护副本。
- 请求失败必须保留失败状态，不用空列表或成功提示掩盖错误。
- 分页结果不得冒充全量数据；统计、筛选和导出须说明或遵守实际数据范围。

## 页面行为

- 使用 Element Plus 和项目已有图标库；功能图标不得用 emoji 代替。
- 异步页面明确区分加载、失败、空数据和成功状态，并提供必要的重试入口。
- 提交操作使用 pending/disabled 防重复机制，完成后恢复状态，失败时保留可修正的输入。
- 表单必须校验用户输入并展示可理解的业务错误，不显示原始堆栈或敏感字段。
- 必要注释解释业务原因、边界和取舍，不复述代码动作。

## 样式与布局

- 组件样式优先使用 `scoped`；全局样式只放主题变量、基础样式和确需共享的规则。
- 按实际使用设备检查内容可读、操作可达；避免整页横向溢出和内容遮挡，不为桌面工具另做一套移动端页面。
- 宽表格可在局部容器内横向滚动，不以压缩关键字段或隐藏操作适配窄屏。

## 请求实现

- 浏览器通过统一 Axios 客户端使用相对 URL，沿用模板 `./api/v1` 写法、hash router 和 Vite `base: './'`，适配动态访问前缀。
- 不改成从域名根解析的 `/api/...`，不硬编码 AppHub 域名、内部服务地址或平台前缀；具体端点及字段仍从目标项目后端合同读取。
- 使用项目统一客户端处理后端响应；是否存在 HTTP 200 内的业务失败，只按目标项目合同判断。
- 错误归一化时保留服务端稳定 `code` 和必要的 `data`，不依赖 `msg` 文案判断。
- 当错误信封同时包含泛化 `msg` 与更具体的安全错误原因时，统一客户端必须优先展示 `data.inner_error.message` 等后端明确允许回传的详细原因；不得把 `LIMIT_TOO_LARGE`、字段缺失等可行动错误压缩成“请求验证失败”或“请求失败”。
- 应用代码不得读取、复制或持久化平台密钥、JWT、Cookie，不新增 token store 或自行拼鉴权头；身份交给网关与既有客户端。涉及真实数据时同时读取 `data-access-standard.md`。

## 验证

- 修改请求或共享类型时核查受影响的后端路由、Schema 和 OpenAPI；修改 store、表单或关键交互时运行相关行为测试，必要时补充。
- 测试覆盖行为与状态变化；低风险文案、样式调整不新增只断言文案或 CSS 类名的机械测试。
- 交付前运行相关测试与生产构建，命令以目标项目 `package.json` 为准；未配置 lint/typecheck 时不虚构命令。
- 交付前运行本 Skill 的 `scripts/validate_frontend_contracts.py <project-root>`；该门禁用于捕获生产构建不会阻止的 Vue runtime-only 模板编译问题。
- 构建属于已授权开发的正常验证，不另设许可门槛；仍遵守宿主工具的授权边界，不绕过审批。
- 界面改动在具备浏览器条件时检查主要操作、布局、业务模块正文和控制台 Vue warning；未实测浏览器，不宣称布局、响应式或真实联调已通过。
- 如实报告已执行结果、未执行项和阻塞，构建通过不等于已部署或真实数据验收通过。
