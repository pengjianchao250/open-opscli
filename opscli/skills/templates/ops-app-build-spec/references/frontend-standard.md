# 前端开发规范

本文件只约束前端实现。API 合同以后端为主：修改请求、错误处理或共享类型前，必须同时读取 `backend-redlines.md`，并核对目标项目的 `backend/CLAUDE.md`、`docs/apphub-contract.md`、生成的 OpenAPI、实际路由和 Pydantic Schema。

## 合同边界

- API 路径、方法、参数、响应信封、错误码、鉴权头和字段语义由后端定义，前端不得维护第二套口径。
- 请求地址使用相对 URL；具体 API 前缀、响应形状、成功语义和业务失败表达只从目标项目后端合同读取，本文件不重复定义。
- API 变化必须先由后端更新路由、Schema、相关测试和 OpenAPI，再同步前端请求、类型与测试；禁止手工修改 OpenAPI。
- 文档与运行代码不一致时先修正后端合同，不新增前端兼容分支掩盖漂移。

## 技术与结构

- 沿用项目从模板继承的 Vue 3、Vite、Element Plus、Axios、Pinia 和 Vue Router，不重新搭脚手架或随意替换技术栈。
- 页面使用现有 views 体系，可复用 UI 放组件目录，请求集中在 `src/api`；只有跨页面共享状态才进入 Pinia。
- 优先复用项目现有组件、请求客户端、类型和样式变量，不创建第二套基础设施。

## 页面行为

- 使用 Element Plus 和项目已有图标库；功能图标不得用 emoji 代替。
- 异步页面必须处理 loading、空数据、失败和成功状态；提交操作必须有 pending/disabled 防重复机制。
- 表单必须校验用户输入并展示可理解的业务错误，不显示原始堆栈或敏感字段。
- 桌面与移动端不得出现内容遮挡、横向溢出或关键操作不可达。

## 请求实现

- 浏览器只使用相对 URL，并通过项目统一 Axios 客户端请求；不得硬编码 AppHub 域名、内部服务地址或平台前缀。
- 使用项目统一客户端处理后端响应；是否存在 HTTP 200 内的业务失败，只按目标项目合同判断。
- 错误归一化时保留服务端稳定 `code` 和必要的 `data`，不依赖 `msg` 文案判断。
- 前端不得保存密钥、JWT、Cookie 或直连内部取数服务。涉及真实数据时同时读取 `data-access-standard.md`。

## 验证

- 修改请求或共享类型时同时校验后端 OpenAPI；修改 store、表单或关键交互时补充相关测试，覆盖行为和状态变化，不只断言文案或 CSS 类名。
- 按目标项目命令执行相关测试；用户允许构建时再执行生产构建，并如实报告未执行项。
