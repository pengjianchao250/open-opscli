# 项目迁移规范

迁移前先判断现有项目是否已满足模板合同。符合合同的项目原地开发，不因 remote、目录命名或模板版本不同而重复迁移。

## 通用流程

1. 记录源项目 Git 状态、入口、页面、路由、接口、数据来源、配置和测试。
2. 保留源项目，在独立目录克隆当前统一模板。
3. 以目标模板的项目结构和开发规范为准，只迁移业务代码与必要配置。
4. 不复制依赖目录、构建产物、本地数据库、密钥、旧部署脚本或旧平台配置。
5. 对照迁移前清单核对页面、路由、表单、权限、接口和错误状态。
6. 项目缺少开发规范时，从 `assets/backend/` 补齐规范文件；只同步规范，不复制应用脚手架。

## 强制边界

- 不在源项目内重新初始化或批量覆盖。
- 不用“能够构建”代替业务行为一致。
- 不修改已验证的用户数据或共享环境来完成迁移。
- 取数能力按当前 `data-access-standard.md` 重新核对，不能照搬旧接口和凭证方式。
- 构建、数据库和发布文件使用目标模板版本，不从源项目覆盖。
- 同步 `AGENTS.md`、`CLAUDE.md` 或开发指南前展示差异，保留项目特有约定。

需要更换前端框架、后端运行时、数据库类型，或无法确认行为等价时停止。输出需要迁移的能力、风险、目标文件和验证方式，由用户或 IT 决定后续方案。

旧实现只在目标项目的对应业务行为验证通过并取得明确确认后删除。
