# 如何找竞品

## 适用请求

- “从这个 ASIN 找竞品”
- “这个关键词下有哪些核心竞品”
- “找外观相似、流量相似或关联竞品”

## 先建立正确口径

竞品是一种需要证据验证的关系，不是一张商品列表。

`competitor-lookup` 使用 `asins` 时只是按指定 ASIN 筛选商品，结果可能包含目标商品的父子体或变体。它不能单独回答“谁是这个 ASIN 的竞品”。运营反馈确认，以共同关键词、流量词和 StyleSnap 视觉搜索建立候选，更贴近实际工作。

## 输入

- 必填：站点，以及 ASIN、核心关键词或产品主图中的至少一种。
- 建议：产品用途、规格、目标人群、价格带和明确排除条件。

只有 ASIN 时，先读取商品页面和流量词；不要追问用户本可以从数据中获得的关键词。只有候选仍存在明显歧义时，再请用户确认。

## 工作流

### 1. 建立商品基线

有目标 ASIN 时，先使用 `ops-amazon-product-data` 读取标题、类目、用途、规格、价格、评分、品牌、父子体和变体信息。完成标准：能够描述目标商品解决什么问题、卖给谁，以及哪些属性决定可比性。

### 2. 从 ASIN 提取搜索意图

使用卖家精灵反查目标 ASIN 的流量词：

```bash
opscli seller-sprite run keyword-reverse \
  --site US \
  --period 30d \
  --params '{"asin":"B0XXXXXXXX"}' \
  --export-format json
```

从结果中选择与产品用途和规格高度相关的核心词。优先保留主要流量词、精准流量词和能清楚表达购买意图的词；品牌词、宽泛词和明显错配词单独标记。

### 3. 按关键词建立搜索竞品候选

对用户给出的核心词或上一步筛出的核心词查询商品：

```bash
opscli seller-sprite run competitor-lookup \
  --site US \
  --period 30d \
  --params '{"keyword":"desk lamp"}' \
  --export-format json
```

必要时用 Amazon 搜索结果数据补充真实搜索页面样本。记录“哪个关键词发现了哪个商品”，不要把多个词下反复出现的同一父体重复计数。

### 4. 补充关联商品

有目标 ASIN 时查询关联流量：

```bash
opscli seller-sprite run association-traffic \
  --site US \
  --period 30d \
  --params '{"asins":["B0XXXXXXXX"]}' \
  --export-format json
```

关联结果需要区分直接替代、互补品、配件、广告关联和无关推荐，不能全部归入直接竞品。

### 5. 补充视觉相似商品

用户给了 ASIN 或主图，并且视觉形态会影响购买决策时，调用 `ops-amazon-stylesnap`：

1. 读取商品第一张可靠主图。
2. 上传到 Amazon StyleSnap。
3. 获取可见的视觉相似商品。
4. 遇到登录、CAPTCHA、地区验证或反机器人页面时等待用户接管。

StyleSnap 是低频、人工监督的发现方式。视觉相似只能说明外观或图片表达接近，仍需验证用途、规格和价格。

### 6. 验证和分层

至少检查以下证据：

| 维度 | 判断问题 |
| --- | --- |
| 搜索意图 | 是否争夺同一批高相关关键词？ |
| 用途与人群 | 是否解决相同任务并面向相近用户？ |
| 规格与兼容性 | 核心尺寸、结构、适配对象是否可比？ |
| 价格带 | 是否处于用户可能互相替换的价格范围？ |
| 流量关系 | 是否有共同流量词或关联曝光关系？ |
| 视觉关系 | 外观、款式、颜色或主图表达是否接近？ |

完成后分类为：

- 核心直接竞品
- 搜索或流量竞品
- 关联商品
- 视觉相似商品
- 标杆商品
- 替代品或互补品
- 排除项

## 输出模板

| ASIN/父体 | 类型 | 发现来源 | 共同关键词 | 可比证据 | 主要差异 | 建议用途 | 结论状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |

`结论状态` 使用“候选”“已验证”或“排除”。核心竞品结论至少需要搜索意图和产品可比性两类证据。

## 限制

- 第三方流量、销量和搜索量多为估算或采样。
- StyleSnap、关联流量和搜索共同出现分别代表不同关系，不能互相替代。
- 父体和变体关系不完整时，明确披露可能存在重复计数。
