---

## 1. 测试用例

### 用例 1：正常案例 — 单 ASIN 诊断

```json
{
  "id": "case-1",
  "prompt": "帮我诊断一下 B08N5KWB9H 最近 30 天的健康度",
  "expected_behavior": "执行认证检查 → 查询主数据集和星级数据集 → 合并数据 → 计算评分 → 输出诊断报告",
  "assertions": [
    "输出必须包含综合健康评分（0-100）",
    "输出必须包含 6 个分项指标及其状态（健康/预警/严重）",
    "输出必须标注数据时间范围",
    "如有预警或严重指标，必须包含行动建议",
    "不能编造数据或指标值"
  ]
}
```

### 用例 2：边界案例 — 星级缺失

```json
{
  "id": "case-2",
  "prompt": "分析 B09NEWASIN1 的健康度，这个是刚上的新品",
  "expected_behavior": "识别可能缺少星级数据 → 查询后星级为空 → 自动排除星级并重分配权重 → 标注星级不可用",
  "assertions": [
    "输出必须标注星级数据不可用",
    "评分计算不包含星级（权重重分配到其他 5 个指标）",
    "使用新品宽松阈值（ACOS <= 35%、转化率 >= 6%）",
    "输出要说明使用了新品阈值"
  ]
}
```

### 用例 3：批量 + 自定义权重

```json
{
  "id": "case-3",
  "prompt": "帮我对比这几个 ASIN 的健康度：B08X1, B09Y2, B07Z3，用利润优先模式，时间范围上个月",
  "expected_behavior": "批量查询 → 使用利润优先权重计算 → 按评分排序输出",
  "assertions": [
    "输出包含 3 个 ASIN 的评分",
    "使用利润优先权重（毛利率 0.40、ACOS 0.25）",
    "按健康评分降序排列",
    "批量结果包含汇总统计（平均分、成功/失败数）"
  ]

```

### 用例 4：异常 — 查询返回空

```json
{

  "prompt": "诊断 B99NOTEXIST 在 2025-01-01 到 2025-01-31 的健康度",
  "expected_behavior": "查询返回空 → 确认 ASIN 和日期范围 → 告知用户无数据 → 不编造诊断结果",

  ]

```

## 2. 基准对比

### baseline

- **新建 Skill**：baseline 是不使用 Skill，直接让 AI 处理同一个 prompt
- **更新 Skill**：baseline 是旧版 Skill（v0.1.x）

### 对比维度

| 维度 | 检查点 |
|------|--------|
| 追问质量 | 是否更少追问无关问题 |
| 数据准确性 | 是否正确使用 opscli 查询而非编造 |
| 判断完整性 | 是否执行所有 6 指标评估 |
| 例外处理 | 是否正确处理星级缺失、新品、空结果 |
| 输出规范 | 是否按固定格式输出，含评分、指标、建议 |
| 上下文负担 | 日常执行加载的 token 数是否合理 |

### 评分记录格式

```json
{
  "case_id": "case-1",
  "run": "with_skill",
  "assertions": [
    {"text": "输出包含综合健康评分", "passed": true, "evidence": "评分 72/100"},
    {"text": "输出包含 6 个分项指标", "passed": true, "evidence": "毛利率/转化率/ACOS/退款率/周转/星级"}
  ],
  "summary": "通过 5/5"
}
```

## 3. 回归门槛

发布或更新前至少满足：

- 新版不能比旧版少执行关键检查（6 指标评估、认证门禁）
- 空结果时不能给正式结论
- 评分公式和阈值不变时，同一输入的评分结果必须一致
- CLI 和 MCP 模式的核心逻辑一致
