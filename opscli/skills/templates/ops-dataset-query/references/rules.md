# 歧义与口径规则

本文件不是启动必读项。只在 `SKILL.md` 的歧义预检命中某一类具体歧义时，读取对应小节。

## 候选来源硬边界

运行时候选必须先来自授权卡片或已选数据集元数据：CLI-only 使用本次 planner/guidance 返回，MCP-only 使用本次 `query_metadata` 返回。不得用未授权数据、先前账号结果或静态知识扩展候选集。

自然语言数据集和字段选择只使用授权候选的中文名称和中文说明。用户明确给出的精确完整英文技术标识，可以对当前授权候选做精确匹配；不得从中文口语推导英文 `dataset_name` 或 `field_name`，也不得对这些英文 key 做自然语言近似检索。

完整中文数据集名出现在更长问句中时，它是用户显式选表证据。嵌套名称保留最长命中；问句独立命中多个数据集、同名冲突或平台能力冲突时先澄清。广告类型已指定但粒度未指定时，只有请求类型与中文默认报表覆盖完全一致且命中真实中文指标时才自动选择。

## 何时必须澄清

命中以下任一情形才进入澄清：

- 两张以上授权数据集卡片都合理，且粒度或口径不同。
- 已选数据集中多个中文字段都能表达用户术语。
- 人名或组织名可对应销售、开发、小组、大组或部门等多个角色。
- 指标可对应原币/CNY、明细/汇总、数量/金额或多个公式口径。
- 时间表述不能唯一还原为主周期和对比周期，例如“最近一个月”。
- 用户要求的明确筛选值不在当前账号组件枚举中，或对应组件 alias 未返回。

候选为空不表示可以扩大数据范围；应报告当前授权元数据无可用候选，或在所有权/数据状态不明时要求刷新。

## 澄清方式

1. 用中文名称、中文说明、业务粒度和口径差异列出授权候选。
2. 一次只询问会改变数据集、字段、时间、币种或筛选的关键问题。
3. 等待用户选择；不在问题中暗示默认答案。
4. 将确认结果传回 planner/guidance 或已选数据集 `query_metadata`，再构造查询。

## 时间口径

- **唯一计算来源**：相对时间必须使用规划器调用 Python `datetime` 后返回的 `reference_date`、`reference_year`、`start` 和 `end`；不得由模型心算或猜测当前年份。用户未写年份时，以 Asia/Shanghai 当前日期的年份为相对计算基准；窗口自然跨年时按 Python 日历跨年，不强行截断在当前年。
- **近 N 天**：包含今天的 N 个自然日，即 `[今天-(N-1), 今天]`。例：今天为 7 月 13 日，"近 7 天" = 7 月 7 日至 7 月 13 日；从 `今天-N` 起算是历史高频错误，多算了一天。
- **中英文混写**：`近30tian`、`近30day`、`近30days` 与 `近30天` 同义，必须识别为用户明确时间，不得回退成默认近30天。
- **周边界**：本周 = 本周一至今天；上周 = 上周一至上周日（完整 7 天）；"最近一周"与"上周"不同，表述不清时澄清。
- **月边界**：本月 = 本月 1 日至本月最后一天（整月口径；月末未到时数据仅覆盖到最新已更新日期，在结果中如实披露，不因此改窗口或要求确认）；上月 = 上月 1 日至上月最后一天（注意大小月天数）；跨年时 1 月的"上月" = 去年 12 月。
- **缺省时间**：用户完全未给时间范围时，默认按"近 30 天（含今天）"处理，并且必须在执行确认摘要和结果说明中显式声明该默认口径。
- **执行前展示绝对日期**：任何相对时间表述最终都要换算为绝对起止日期并披露。规划器已唯一解析的“本月/上月/近 N 天”等直接执行，不再次确认；只有原文未给时间、`is_default=true` 时才确认默认近 30 天。
- **上下文范围继承**：同一会话的追问或复杂任务子步骤未重新指定时间、筛选时，继承上一轮已确认的范围；调用规划器时必须带原请求或已锁定的绝对起止日期，不能只传丢失全局约束的步骤摘要。

## 紧凑口径规则

- **币种换算是请求参数，不是字段**：用户表达明确币种意图（"用美元/按 USD/加元口径"，仅支持 USD/GBP/CAD/EUR/JPY/CNY）时由规划器写入 `globalCurrency`（手工路线 CLI `--global-currency`、MCP `global_currency=`）；元数据里没有 `currency` 字段属正常，不得据此判定不支持按币种查询，也不得用选 `_cny`/原币字段代替；多币种 = 逐币种各查一次，禁止外部汇率或本地换算；回复中的币种以返回的 `meta.currency`（`result_disclosures.currency`）为准，为空只能说"未声明"。
- **白名单外币种走澄清，不走执行**：请求里出现 USD/GBP/CAD/EUR/JPY/CNY 之外的币种（如港币 HKD）时，规划器返回 `status=clarify_required` + 澄清码 `unsupported_currency`，并在 `model_view.unsupported_currencies` 列出识别到的代码。必须告知用户仅支持上述六种币种，让其改选支持的币种或确认按默认币种查询；确认后把口径写回原请求重跑。**禁止**直接执行后把结果当作该币种，也禁止用任何外部汇率折算。
- 原币字段与 `_cny` 字段并存、且用户要求原币/站点币种或精准对账口径时，才属字段口径歧义：澄清选哪一组字段，不静默选择；跨币种金额不得相加。
- 环比/同比必须同时明确主周期与对比周期；整自然月窗口的环比固定为上一个自然月（整月对整月），大小月天数差异属正常口径，不需补齐也不需确认；其他窗口月份天数不等时不自行补齐。
- **快照类指标**（如库存量，合同中 `is_snapshot=true`，对应元数据 `snapshot_metric=1`）只反映某一天的切面，禁止跨日/跨期累加；需要趋势时按日展示快照序列，不求和。走规划器主线时窗口收敛由内核完成：未按时间粒度维度分组的多日窗口自动收敛为最新完整快照日（见 `execution_ref.snapshot_policy`），按日期维度分组时不收敛，环比/同比各取周期末日快照；与流量指标混查且未按日分组时返回 `clarify_required` + `snapshot_metric_window_conflict`，须让用户按日期维度分组或拆成两次查询。
- 库存类字段有多个中文口径时，要求用户选择可售、在途、平台仓、海外仓或其他已返回候选。
- **输出列名禁止意译**：展示结果与结论中的字段称呼必须使用元数据 `verbose_name` 原文（规划合同中该中文名为 `label_zh`），不得改写、简化或意译。
- **组织与组件筛选口径**：小组（team）与部门（dept）是相互独立的维度，不得互相推导；店铺、渠道、平台是不同维度不得混用。组件枚举成员先做 NFKC、首尾空白和大小写归一，部门编号中的多位阿拉伯数字与中文数字统一归一（如"22部"与"二十二部"），并保留"项目"前缀作为组织身份的一部分。"十二部"、"项目十一部"、"22部"、"项目二十二部"等完整部门词必须整体识别，禁止截取其中的"一部"或"二部"作为销售小组，也不得用这些子串命中"一部-B组"等销售小组枚举的主段。归一后存在唯一完整等值成员时只选择该枚举原值并直接执行，不得再次询问用户是否采用，也禁止加入仅因名称包含而命中的其他成员："9部"只选"九部"，不选"项目九部"；"范泰克"只选"范泰克"，不选"范泰克体系外"。部门、国家、渠道、品牌等所有组件字段必须保留值所在语段的正负极性：排除单值用 `!=`、排除多值用 `not_in`，禁止把否定筛选写成 `=`/`in`；正负冲突时必须澄清。没有唯一完整等值成员时展示枚举候选并澄清，不得自动使用子串扩大范围。
- **点名指标完整性**：多指标请求必须逐项核对 `model_view.metrics` 和 `query_template.metrics`；稳定别名也算显式点名，例如“收入及毛利”必须对应并保留“销售额、毛利”两项。只命中部分指标时转 `metric_not_in_dataset` 澄清，不得拿残缺指标集合执行。
- 缩写只能结合已选数据集的中文说明判断；如仍有多义，展示候选并澄清。

## 禁止发明默认筛选

除非用户明确指定，不得凭推断为查询添加任何默认筛选条件。

【例外】来自服务端元数据 filter_configs 的默认条件不属于"发明"：它是数据集口径
的一部分，必须应用且必须在回答中披露（default_filters_zh 原文转述）。
除此之外仍然禁止凭推断添加任何筛选。
