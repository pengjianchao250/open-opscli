# OPS 数据集应用取数指南

本指南只处理标准 AppHub 应用的数据产品取数决策。数据集、字段、聚合、公式、筛选枚举和查询执行继续由 `$ops-dataset-query`、`$ops-query-wizard` 与当前在线元数据负责。

静态资料、历史目录和字段附件只能帮助发现候选来源，不能作为线上可用性、当前权限或字段合同的事实源。

## 1. 先判断任务类型

| 模式 | 判定 | 动作 |
| --- | --- | --- |
| `one-off-query` | 临时核数、分析或导出，不修改站点 | 退出本 Skill，使用对应查询 Skill |
| `guided-query` | 业务范围、指标、维度、时间或筛选仍有歧义 | 使用 `$ops-query-wizard` 澄清 |
| `viewer-live` | AppHub 页面按当前访问者权限实时读取 OPS | 复用标准模板 `ViewerQueryGateway` |
| `viewer-private-persisted` | 当前用户需要保存历史、收藏、筛选或加工结果 | 使用可信 `owner_user_id` 隔离持久化 |
| `approved-system-sync` | 统一页面、API 或数据库需要固定同步过程数据 | 仅在项目已提供批准的系统适配器时继续 |
| `reference-only` | 只读取字段字典、附件或历史目录 | 仅形成候选，不生成正式查询或运行时代码 |

“搭建 AppHub 运营看板”属于站点数据层场景；“创建、修改或分析当前 Dashboard 页面”属于 Dashboard 专用 Skill，不由本 Skill 接管。

## 2. 固定同步硬门槛

标准模板当前确认的 OPS 正式路径是访问者身份下的 `ViewerQueryGateway`。不得为了实现固定同步：

- 保存或复用访问者的 `X-Ops-Token`。
- 用某个用户的 viewer 权限生成站点共享快照。
- 自行创建系统账号、后台登录、定时任务或不存在的 SDK Client。
- 把本地开发 Session、CLI 登录态或 Mock 当作线上系统身份。

只有同时满足以下条件，`approved-system-sync` 才能进入实现：

1. 项目中实际存在经过批准的 OPS 应用运行时适配器。
2. 适配器的身份、授权范围、调用合同和部署方式有项目证据。
3. 数据范围不是从访问者请求体或不可信 Header 自报。
4. 同步批次、分页、幂等、自然键、快照和失败恢复合同完整。
5. `app.yaml.opscli.datasets` 已声明经过在线验证的数据集白名单。

任一条件不满足时，在 `data-spec.md` 标记 `blocked`，列出缺少的适配器或授权条件，不生成伪实现。

## 3. 数据产品拆解

按业务用途、消费者、刷新要求和自然粒度拆分有限、互不重复的数据产品，不按卡片或字段数量拆分。每个数据产品至少回答：

- 页面要帮助谁做什么决策。
- 数据是访问者实时读取、用户私有保存，还是批准的系统同步。
- 需要哪些业务对象、时间窗口、指标、维度和筛选。
- 数据自然粒度和自然键是什么。
- 快照、趋势、累计、比率和币种如何解释。
- 允许多旧的数据，如何展示更新时间、分页和截断。
- 站点 API、加工、存储和测试分别承担什么职责。

可以使用 `sales_overview`、`inventory_risk`、`advertising_diagnosis` 等业务名称，但不能根据名称直接猜数据集技术标识。

## 4. 候选来源与在线验证

候选来源可以来自业务需求、项目现有合同、历史资料或数据集应用清单，但必须标记为 `candidate`。候选阶段只记录业务域、可能的中文数据集名称、预期粒度、时间语义和需要验证的字段类型，不写入未经在线验证的技术别名、字段名、公式或筛选枚举。

需求清晰时使用 `$ops-dataset-query`，传递业务问题、用途、消费者、时间范围、维度、指标、筛选、排序、预期粒度、刷新要求和最大数据量。候选中文数据集只能作为候选理由，不能伪装成用户已指定的数据集。

需求模糊时使用 `$ops-query-wizard`，只澄清会改变数据合同、权限或存储方案的问题。澄清后回到本 Skill 固化数据产品。

验证后为每个来源标记：

- `candidate`：只有参考依据，尚未在线验证。
- `verified`：当前身份在线元数据和少量真实查询均确认。
- `blocked`：无权限、未返回、字段不完整、服务异常或运行时适配器缺失。

记录验证时间、验证方式、数据集真实名称、字段、粒度、时间、筛选、分页和空值行为。真实结果和导出文件不得提交源码。

## 5. 查询组件边界

查询组件只用于取得当前账号可用的部门、渠道、国家、销售小组、销售、开发、ASIN、SKU 或广告类型等枚举，不能作为销售额、库存、广告效率、利润等业务结果，也不能替代正式业务数据集。

用户输入不在在线枚举中时必须展示候选并澄清，不能做子串扩张。

## 6. 时间、快照和指标

- 相对日期在合同中转换为明确起止日期，并记录时区。
- 用户未提供时间时必须确认，不静默生成长期合同。
- 快照指标默认取最新快照日；趋势按日展示，不跨日累计库存、排名或状态。
- 比率使用汇总分子除以汇总分母，除非在线字段定义明确要求其他算法。
- 原币与人民币分开处理，币种未明确时先确认。
- `0`、`null`、空字符串和零行分别处理；零行不等于业务值为零。
- Top N 声明排序字段、方向、条数、分页和是否截断。

## 7. 分页与固定过程数据

页面实时查询应设置明确 limit、超时和稳定排序。经过批准的系统同步还必须定义：

- 确定性分页和断点续传游标。
- 批次 ID、开始时间、完成时间和终态。
- 原始字段保留、规范映射和 schema 版本。
- 自然键、去重、幂等写入和增量边界。
- 快照日期、源数据更新时间和本站获取时间。
- 部分失败、重试、回滚或保留最后有效版本的策略。

不能只保存页面最终汇总数字，也不能让页面请求临时承担全量同步任务。

## 8. 跨数据集与跨来源组合

组合前必须对齐商品身份、时间、粒度、币种、单位、用户权限和存储范围。组合和二次加工在 FastAPI service 完成。共同变化、相关性和时间先后不能直接写成确定因果。

## 9. data-spec.md 记录要求

每个数据产品至少记录：

1. `product_key`、页面用途和消费者。
2. `acquisition_mode` 及选择原因。
3. 来源候选、验证状态、验证时间和证据。
4. 数据集、字段、粒度、自然键、时间、筛选和指标口径。
5. 身份边界、QueryGateway 或批准适配器路径。
6. `app.yaml.opscli.datasets` 白名单变更。
7. 分页、截断、新鲜度、超时、重试和空值处理。
8. 站点 API、加工、存储、迁移、测试和阻塞项。

## 10. 验收清单

- [ ] 单次查询没有被扩展成站点数据工程任务。
- [ ] Dashboard 页面任务没有误路由到本 Skill。
- [ ] 候选来源和已验证合同有明确状态区分。
- [ ] 数据集、字段和筛选来自当前在线元数据。
- [ ] 查询组件只用于枚举和关联。
- [ ] 粒度、自然键、时间、快照和币种已明确。
- [ ] 比率没有求和，快照没有跨日累计。
- [ ] OPS viewer 数据没有进入未隔离共享存储。
- [ ] 固定同步具有批准适配器，或者被明确标记为 `blocked`。
- [ ] 分页、截断、数据量和新鲜度已披露。
- [ ] 真实查询结果、导出和凭证未进入源码。
