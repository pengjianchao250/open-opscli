# ops-dataset-query 规划器开发分析

## 修复结论

最终 P0=0、P1=0。本轮改动继续按通用语法所有权实现，没有为具体部门、品牌或渠道名称增加业务特判。

## 核心规则

1. 字段身份优先：显式前置标签优先于值内部或后续出现的后置标签；后置列表选择最靠右字段标签，同一位置选择最长标签。
2. 列表整体归属：`字段 A、B` 与 `A、B 字段` 都先锁定完整列表，再和当前账号授权枚举求交集。
3. 排除极性整组继承：`、/，/,/和/与/或` 不得切断排除作用域；整组排除生成 `not_in`，不能形成一正一负两个条件。
4. 复合值独占内部子串：完整销售小组、渠道命中后，其部门、大组、国家和品牌片段不得被其他组件消费。
5. 安全失败：部分授权只查询交集并披露；零授权、同值正负冲突均撤下模板并澄清，不扩大为全范围。
6. 英文枚举只认短语：支持 `show/list/display available`、`what values are available for <字段>`、`what <字段> values are available`；`available sales/inventory/performance` 等业务表达继续阻断组件表。
7. 组件 Top N 无需虚构排序指标，只写 `limit`。

## 缺陷闭环

- ASCII 逗号排除列表：由第二项被误判为包含，改为列表级极性继承。
- 后置字段列表：补齐 `的/除外/之外/以外` 边界及字段前置、后置的优先级。
- 长短标签重叠：`销售小组` 与 `小组` 同结束位置时取最长标签；`事业部部门` 取最靠右的“部门”。
- 单值后置冲突：`只看HOMFA但HOMFA品牌除外` 先锁定品牌，再返回 `component_filter_polarity_conflict`，不再泄漏为渠道筛选。
- 英文枚举倒装：`what <字段> values are available` 已覆盖 9/9 组件表，业务负例仍安全澄清。
