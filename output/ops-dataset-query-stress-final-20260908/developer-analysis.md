# ops-dataset-query 规划器开发分析

## 修复结论

当前 P0/P1 为 0。核心改动集中在字段身份遮蔽、组件文本所有权、多值与极性、时间语言和趋势排序五类通用边界，不以单个业务例句写特判。

## 通用规则

1. 先识别并遮蔽结构身份：数据集全名、完整字段标签、技术字段、ISO 日期和语法关键词不再进入组件值反查。
2. 长值拥有内部子串：完整渠道、销售小组等复合值一旦归属某字段，内部国家、品牌、部门和大组不得被其他字段再次消费。
3. 多值先整体归属再求授权交集：`、/逗号/和/与/或` 共用列表逻辑；交集非空时只下发授权值并披露未授权项，零交集时阻断，禁止退化为全范围查询。
4. 筛选与分组分离：字段标签在 `= / 不等于 / 排除 / 除外 / 只看` 等筛选结构中不得同时加入维度。
5. 极性在模板前确定：单值排除用 `!=`，多值排除用 `not_in`；同值正负冲突必须澄清。
6. 完整字段优先于短别名：长标签内部的“收入、销量、销售额”等不重复生成指标，短别名在其他语段独立出现时仍能解析。
7. 时间与排序按语义类型判定：英文月份、前 N 天/周/月、季度和年度均落为 Python 日历窗口；趋势默认日期升序，指标名自带“排名”不覆盖趋势顺序。
8. 未绑定技术字段不生成残缺模板：自然语言直接出现 `price`、`order_qty` 等技术名时返回 `clarify_required + recommended_fields_confirmation` 并提示使用 `--field`；技术名与展示名相同（如 ASIN）的字段不受影响。
