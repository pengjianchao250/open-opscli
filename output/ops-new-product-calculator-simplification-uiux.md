# 新品计算器逻辑精简交互设计

## 1. 交互范围

本次 UI 是终端 CSV 填写体验与 Rich 表格输出，不修改网页视觉系统。

冻结项：

- 图标库：不使用图标，不新增 emoji 占位。
- 字体系统：沿用用户终端字体。
- Design Token：沿用 Rich 现有 cyan 表头；全程费用和平均费用使用 red 强调；区间使用普通次行文本。
- 组件生态：仅使用项目现有 `rich.table.Table`。
- 页面骨架：任务摘要 → 费用方案表。

## 2. 草稿填写体验

新版 `填写表格.csv` 完全不显示“成本费用”分组及其字段，业务用户只填写产品信息、备货设置和其他仍需输入的内容。同目录的 `填写表格-旧版.csv` 保留原字段，仅作历史备份，说明行明确标记“已弃用”，不引导用户继续填写。

指定二区默认写入 `zone_1_2`，CSV 直接显示“美东+美西”。用户仍可在 CSV 中主动改成其他有效下拉值。

### 2.1 包装参数补全

`使用说明.md` 把参考信息拆成两组：

- 单件 SKU 包装：默认选项是“按实物填写（推荐）”，另列 Amazon.sg 官方 SD 卡、图书、电子玩具示例。
- FBA 入库外箱：默认选项是“按实际装箱填写（推荐）”，另列美国 FBA 入库箱合规上限。

参考项只帮助用户理解量级，不自动写入 CSV。“当前值”只展示接口或用户已确认的数据；“示例”与“当前值”必须保持视觉和语义分离。

Skill 每轮最多询问 3–5 个仍缺失或无效的必填字段，顺序为单件包装、入库外箱、剩余字段。用户选中参考模板后需要明确确认；未确认时继续停留在补全阶段。

## 3. 结果展示

标题使用“费用方案”，不再使用“试算结果”或“方案切换”，避免暗示 CLI 可交互切换。

费用方案表由 `calculator detail` 一次性输出。Skill 原样采用该输出，不手工重建 Markdown 表格；默认不追加成本、利润、毛利、Web 页面或原始 JSON 提示。

表格遵循用户截图的信息顺序：

```text
分区推荐 | [首单数量] | 分区线路 | 每PCS头程费用 | 每PCS目的仓费用 | 每PCS尾程费用 | 每PCS全程费用 | 每PCS全程平均费用
```

- 不显示单选圆点。
- 所有方案同时展示。
- 同一方案有多条线路时，各线路在对应费用单元格中逐行对齐。
- 主费用在第一行，范围在第二行，例如 `2.3181\n(2.2882~2.3583)`。
- 全程费用与全程平均费用突出显示。
- 首单数量按 `allPlans[0].first_order_qty` 控制整列显隐，匹配参考前端行为。

## 4. 提示文案

表格前保留：

```text
注：费用计算结果不含头程清关税金。
```

删除“更多方案”“切换方案会更新结果”等网页交互文案。

## 5. 完成检查

- CSV 中不存在任何利润成本字段。
- 旧版 CSV 包含完整字段和弃用说明，且不会影响新版填写流程。
- 未返回的包装、重量、箱规字段保持空白，不从示例自动填充。
- 单件包装参考、入库外箱上限和单箱数量询问边界清晰。
- 指定二区默认显示“美东+美西”。
- 表格不存在单选或切换提示。
- 所有 `allPlans` 方案和 `schemes` 线路均未丢失。
- 费用值、区间、单位与参考前端一致。
- 窄终端不会用省略号截断表头或费用区间。
