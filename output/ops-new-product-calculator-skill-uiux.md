# 新品计算器 Skill 交互设计

## 1. 设计范围

本次没有图形界面实现。UIUX 指 Agent 与业务用户之间的对话入口、信息层级、确认门和结果呈现；不涉及图标库、字体、Design Token 或组件库变更。

## 2. 交互原则

- 先识别用户当前状态，再询问缺失信息。
- 使用站点、平台、海关类目、草稿、任务编号等业务语言。
- 每次只呈现当前决策需要的信息。
- 技术命令用于说明即将执行的动作，不替代业务解释。
- 长字段填写迁移到 `填写表格.csv`，不在对话中逐字段追问。

## 3. 三类入口

### 3.1 新建试算

首次回复：

```text
我先确认三个基础选择：
- 试算站点：默认美国
- 试算平台：默认亚马逊 + 沃尔玛
- 海关类目：请给一个商品关键词，例如“数据线”
```

只展示 3–5 个类目候选。生成草稿后，把用户注意力放在 `填写表格.csv` 的“请填写”列。

### 3.2 继续草稿

首次回复：

```text
我会先查看现有草稿并校验填写情况，不会直接提交真实任务。
```

先 `show`，再 `validate`。校验错误只解释最关键的 3–5 项，并告诉用户在 CSV 的哪类字段中修正。

### 3.3 查询或复用任务

首次回复：

```text
我会用任务编号查询试算结果；如果信息不足，再从任务列表定位。
```

如果用户要求复制，说明会创建新的草稿目录，不会覆盖原任务或已有草稿。

## 4. 提交确认门

`validate` 通过后使用固定确认结构：

```text
草稿已通过校验。
submit 会创建真实试算任务。确认要提交吗？
```

用户未明确确认时，不执行 `submit`。

## 5. 结果信息层级

查询成功后按固定顺序回复：

1. 状态、推荐方案、Web 详情页。
2. 完整试算结果表格。
3. 简短业务解释。

表格必须保留 CLI 实际返回的所有方案列，并尽量保留：

- 售价、毛利、毛利率。
- 非税采购价、头程费用、仓库费用、尾程费用。
- 站内广告、站外促销、平台佣金、退款费、固定成本。
- 备注。

不把结果压缩为仅包含“方案、毛利、毛利率”的摘要表。

## 6. 异常交互

| 场景 | 用户可见回复 |
|---|---|
| 未登录 | 说明需要完成 OPS 登录，再继续新品试算 |
| 缺少 Polaris 权限 | 说明当前账号缺少 BI/Polaris 权限，不反复要求登录 |
| 校验失败 | 返回反馈编号，解释关键字段问题并指导修改 CSV |
| 查询超时 | 说明任务可能仍在计算，先查列表状态后再重试 |
| 用户不想编辑本地文件 | 提供 Web 新品计算器入口 |

任何回复都不展示完整 JWT、Cookie、`sudo` 或内部后端地址。

## 7. Web 路由

| 用户目标 | 入口 |
|---|---|
| 创建新品试算 | `https://bi.xenkee.com/#/newProductCalculator` |
| 查看试算列表 | `https://bi.xenkee.com/#/calculatorResultList` |
| 查看结果详情 | `https://bi.xenkee.com/#/calculatorDatail?task_code=<TASK_CODE>&sudo=<SUDO>` |

详情页中的 `TASK_CODE` 与 `SUDO` 使用实际任务返回值替换；对话中不额外复述完整敏感值。

## 8. 完成检查

- 是否直接进入了用户当前所在的任务阶段。
- 是否只询问完成当前步骤所需的信息。
- 是否在提交前获得明确确认。
- 是否保留完整结果表和推荐标识。
- 是否隐藏敏感信息。
- 非认证类命令失败时是否已返回 `feedback_uuid`。
- 是否根据用户目标提供了正确的线上入口。
